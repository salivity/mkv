How MKV Stores HDR Content Light Level Metadata

The Matroska (MKV) container stores High Dynamic Range (HDR) content light level information directly within its standardized header structure using Extensible Binary Meta Language (EBML). By embedding static HDR metadata parameters—specifically Maximum Content Light Level (MaxCLL) and Maximum Frame-Average Light Level (MaxFALL)—in the video track header, MKV allows media players and display devices to parse luminance requirements and apply accurate tone mapping without having to decode the underlying video bitstream first.

In the Matroska specification, visual metadata is organized hierarchically inside the TrackEntry element. Content light level data is located within the Video settings under the Colour element.

The structure follows this exact hierarchy:

  • Segment: The root container.
  • Tracks: The container for all track definitions.
  • TrackEntry: The definition for a specific stream (e.g., video).
  • Video: Video-specific parameters (resolution, frame rate).
  • Colour: Advanced colorimetry and HDR metadata.

Within the Colour element, two specific unsigned integer tags store the content light level values measured in candelas per square meter (nits):

  1. MaxCLL (EBML ID 0x55BA): Represents the Maximum Content Light Level. It defines the brightness of the single brightest pixel found anywhere in the entire video stream.
  2. MaxFALL (EBML ID 0x55BB): Represents the Maximum Frame-Average Light Level. It defines the highest average brightness across all pixels in any single frame of the video.

Alongside MaxCLL and MaxFALL, the Colour block often contains a nested MasteringMetadata element. This sub-element stores the mastering display's chromaticity coordinates (red, green, blue, and white point) and the display's minimum and maximum luminance capabilities (LuminanceMin and LuminanceMax).

While HDR codecs such as HEVC/H.265 and AV1 can embed this metadata internally via Supplemental Enhancement Information (SEI) NAL units or sequence headers, MKV duplicates this data at the container level. This container-level storage enables demuxers, hardware splitters, and playback software to instantly negotiate HDMI display metadata and configure rendering pipelines before initializing the video decoder.
