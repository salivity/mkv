Can MKV Contain xHE-AAC Audio Tracks?

This article examines whether the Matroska (MKV) multimedia container can encapsulate audio tracks encoded in xHE-AAC (Extended High Efficiency Advanced Audio Coding). It covers container compatibility, technical implementation details, software muxing capabilities, and the playback requirements necessary to decode these streams.

Yes, an MKV container can encapsulate xHE-AAC audio tracks. Matroska is an extensible, open-standard multimedia container designed to be codec-agnostic, allowing it to package virtually any modern audio, video, or subtitle format, including the latest additions to the MPEG audio family.

Technically, xHE-AAC is standardized as Unified Speech and Audio Coding (USAC) under MPEG-D (ISO/IEC 23003-3) and represented as Audio Object Type 42 (AOT 42) in MPEG-4 Audio. When encapsulated within an MKV container, xHE-AAC is stored using the standard Matroska AAC Codec ID (A_AAC). The container holds the stream's initialization data within the CodecPrivate element, which contains the standard MPEG-4 AudioSpecificConfig signaling the USAC payload.

To encapsulate xHE-AAC into an MKV file, modern multimedia tools like FFmpeg or MKVToolNix can be used. If the source xHE-AAC stream is provided in an ADTS, LOAS/LATM, or raw MP4/M4A elementary stream format, these utilities can parse the bitstream headers and remux the audio directly into an MKV file without re-encoding.

While the MKV container successfully holds and demuxes xHE-AAC data, actual audio playback requires an underlying decoder that supports the format. The media player or operating system must utilize a compatible decoding library—such as Fraunhofer's FDK AAC library—to decode the stream into PCM audio. Modern operating systems (including current versions of Android, iOS, Windows 11, and macOS) have native decoders, making playback straightforward in updated media players such as VLC or mpv.
