How MKV Differentiates Hearing Impaired Subtitles

Matroska (MKV) container files distinguish between hearing-impaired subtitles and standard subtitles primarily through standardized metadata flags embedded directly in the track headers. By using specific track elements such as the FlagHearingImpaired identifier, along with standardized language tags and descriptive track titles, the MKV format allows modern media players to automatically recognize, label, and select the appropriate subtitle track based on user accessibility preferences.

The Matroska Track Header System

The MKV format is built on Extensible Binary Meta Language (EBML), which organizes data into distinct tracks: video, audio, and subtitles. Each subtitle track contains a TrackEntry header containing essential metadata about that specific stream, such as codec type, language, and display behavior.

The FlagHearingImpaired Element

The definitive way an MKV file identifies hearing-impaired subtitles—commonly referred to as Subtitles for the Deaf and Hard of Hearing (SDH)—is through the FlagHearingImpaired element.

  • Standard Subtitles: The FlagHearingImpaired value is set to 0 (false) or omitted, signaling that the track contains only spoken dialogue translations or transcriptions.
  • Hearing-Impaired Subtitles: The FlagHearingImpaired value is set to 1 (true), signaling that the track includes non-speech audio cues, such as background noises, musical descriptions, tone indicators, and speaker identifications.

Track Naming and Legacy Tagging

In addition to the binary header flag, MKV files often use the Name or TrackName element for labeling and backward compatibility. Muxing tools (such as MKVToolNix) frequently label these tracks as "English SDH", "English [CC]", or "English (Hearing Impaired)".

Older media players that do not parse the newer FlagHearingImpaired EBML element rely on these text strings to inform the user that the track is designed for the hearing impaired.

How Media Players Process the Metadata

When a compatible media player (such as VLC, mpv, or Kodi) opens an MKV file, it reads the track header definitions:

  1. Detection: The player checks the TrackType (set to subtitle) and checks for the presence of the FlagHearingImpaired flag.
  2. User Preferences: If the player's accessibility settings are configured to prioritize hearing-impaired tracks, it will automatically select the track with the flag set to 1.
  3. Interface Labeling: The player displays an SDH icon, a "CC" badge, or an explicit "(Hearing Impaired)" label next to the track in the subtitle selection menu, helping users make an informed choice between regular dialogue subtitles and comprehensive descriptive subtitles.
