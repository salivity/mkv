How MKV Stores Dynamic Range Compression

The Matroska (MKV) multimedia container format handles track-level dynamic range compression (DRC) through a combination of embedded codec-level metadata, the standardized Matroska tagging system, and ReplayGain elements. Because MKV is an extensible binary format based on EBML (Extensible Binary Meta Language), it does not enforce a single dynamic range alteration on raw audio data. Instead, it preserves original stream-level DRC profiles or provides track-specific metadata targets that demuxers and decoders read at runtime to adjust dynamic range dynamically.

Codec Bitstream Encapsulation

The primary method MKV uses to retain DRC values is bitstream pass-through within individual audio tracks. Formats such as Dolby Digital (AC-3), Dolby Digital Plus (E-AC-3), DTS, and Opus contain native dynamic range metadata and dialog normalization (dialnorm) coefficients directly within their audio frames.

When multiplexing these streams into an MKV container:

  • The audio packets are stored inside Block or SimpleBlock elements under the Matroska Cluster structure.
  • Codec-specific initialization data, which may define baseline dynamic range behavior, is stored in the CodecPrivate element inside the corresponding TrackEntry.
  • Decoders extract this embedded metadata directly from the payload without requiring container-level parsing to interpret frame-by-frame compression curves.

Matroska EBML Tagging System

For container-level track metadata that isn't native to the raw audio bitstream, MKV employs its hierarchical EBML Tags element. This system links specific dynamic range parameters directly to an individual track via its unique identifier (TrackUID).

Within the Tags structure:

  1. A Tag element is created containing a Targets master element.
  2. The TargetTypeValue is set to represent a track-level target, and TrackUID is assigned the unique ID of the target audio track.
  3. Nested SimpleTag elements define dynamic range properties using standard key-value string pairs (e.g., custom DRC profiles, normalization parameters, or target sound-pressure levels).

ReplayGain and Track Gain Elements

While distinct from continuous multi-band dynamic range compression, static track-level gain adjustments are supported natively in MKV via standard ReplayGain tags. Matroska maps track-level gain through tags such as:

  • REPLAYGAIN_TRACK_GAIN: Stores the relative decibel adjustment required to bring the track to a target reference level.
  • REPLAYGAIN_TRACK_PEAK: Specifies the maximum sample value of the track to prevent clipping when DRC or gain boosts are applied.

Playback and Demuxer Processing

During playback, the media splitter (demuxer) reads the TrackEntry and any associated Tags linked to the TrackUID. If codec-level DRC is present, the demuxer passes the raw bitstream to the audio decoder, which reads the embedded DRC profiles (such as "Film Standard", "Music Light", or "Speech") and applies gain reductions or boosts according to the user's playback environment. If container-level tags are present, the media player's audio filter applies the defined dynamic scaling during the post-decode digital signal processing (DSP) stage.
