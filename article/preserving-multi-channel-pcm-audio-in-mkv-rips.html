Preserving Multi-Channel PCM Audio in MKV Rips

Ripping multi-channel Pulse-Code Modulation (PCM or LPCM) audio from physical media into the Matroska (MKV) container requires tools to extract, convert, and package uncompressed sound streams without lossy degradation. Media ripping applications achieve this preservation by reading the raw audio bitstream from the source disc, maintaining precise channel layout metadata, standardizing sample formats, and packaging the data directly into MKV audio tracks using stream passthrough.

Demuxing the Raw Audio Stream

Physical media formats like Blu-ray discs store uncompressed multi-channel audio tracks as LPCM streams alongside video and subtitle packets within MPEG-2 Transport Stream (M2TS) files. When a ripping tool processes this data, it first demuxes the container. Rather than decoding and re-encoding the audio through a lossy codec (such as AAC or AC3), the software extracts the uncompressed pulse-code samples directly from the multiplexed stream. This process is functionally a direct stream copy, ensuring that no audio samples are discarded, compressed, or dynamically altered.

Byte Order and Endianness Handling

Blu-ray specifications typically store LPCM audio in big-endian byte order (often referred to as BD-LPCM). Most modern multimedia containers, operating systems, and media players expect uncompressed PCM audio to use little-endian byte ordering, following the standard Microsoft WAVE format.

To preserve compatibility without compromising fidelity, ripping tools perform an endian conversion during the remuxing phase. The tool reads the 16-bit or 24-bit samples and reverses the byte order for each individual sample. Because this transformation only rearranges how the binary data is read rather than altering sample values, the audio remains mathematically identical to the source recording.

Matroska Codec Identification and Header Metadata

The Matroska container natively supports raw PCM streams through dedicated codec identifiers, primarily A_PCM/INT/LIT (uncompressed integer PCM in little-endian format). When the ripping tool muxes the extracted PCM data into an MKV file, it constructs a Matroska track header containing essential technical parameters:

  • Sampling Frequency: Preserves source rates such as 48 kHz, 96 kHz, or 192 kHz.
  • Bit Depth: Explicitly defines whether samples are 16-bit, 24-bit, or 32-bit.
  • Channel Count: Identifies the total number of audio streams (e.g., 6 channels for 5.1 surround or 8 channels for 7.1 surround).

By writing these parameters into the MKV track definition, the container ensures that downstream media splitters and audio renderers allocate the correct buffer sizes and decoding pipelines during playback.

Channel Mapping and Spatial Positioning

Multi-channel PCM relies on explicit channel ordering to ensure that individual audio tracks route to their intended speakers (such as Front Left, Center, Front Right, Low-Frequency Effects, and Surround channels). Blu-ray LPCM tracks use specific channel assignment tables defined by SMPTE standards.

During the muxing phase, ripping software maps the input channel configuration into standard channel assignment masks compatible with the Matroska specification and modern audio APIs (like WAVEFORMATEXTENSIBLE). The software interleaves the multi-channel samples in the designated playback order—such as Left, Right, Center, LFE, Left Surround, Right Surround—ensuring that surround sound staging and multi-channel separation remain intact across any playback hardware.
