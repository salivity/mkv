Arabic and Hebrew RTL Subtitles in MKV Files

The Matroska (MKV) container format fully supports embedded subtitle tracks containing right-to-left (RTL) scripts such as Arabic and Hebrew. By leveraging standard Unicode encoding, MKV can store multiple text-based and image-based subtitle formats that accommodate complex scripts, bidirectional text, and custom styling. While the MKV container itself flawlessly preserves RTL subtitle data, the proper visual display relies heavily on the capabilities of the media playback software being used.

How MKV Stores RTL Subtitles

MKV is a flexible, open-standard multimedia container capable of multiplexing audio, video, and various subtitle formats into a single file. For text-based subtitles like SubRip (.srt), Advanced SubStation Alpha (.ass), and WebVTT (.vtt), MKV uses UTF-8 character encoding. Because UTF-8 includes the full Unicode character set for Arabic and Hebrew, the raw characters, diacritics, and layout codes are stored without data loss.

In addition to text formats, MKV supports image-based (bitmap) subtitle formats such as PGS (Blu-ray subtitles) and VOBSUB (DVD subtitles). These formats store subtitles as pre-rendered images rather than text, meaning Arabic and Hebrew subtitles will always display exactly as authored, completely bypassing any text-rendering limitations.

Storage vs. Rendering

There is an important distinction between storing RTL subtitles in an MKV file and rendering them correctly on screen:

  • Storage (The MKV Container): The MKV file reliably holds the subtitle stream, language tags (such as ara for Arabic or heb for Hebrew), and character data.
  • Rendering (The Media Player): The media player's subtitle engine is responsible for interpreting the stored text. Proper display of Arabic and Hebrew requires bidirectional (BiDi) text processing to handle mixed RTL and LTR (left-to-right) text, as well as complex text shaping to connect Arabic letters correctly.

Best Practices for RTL Subtitles in MKV

To ensure optimal compatibility and display quality for Arabic and Hebrew subtitles in MKV files:

  1. Always Use UTF-8 Encoding: When embedding text-based subtitles (SRT or ASS), ensure the source text file is saved with UTF-8 encoding to prevent garbled text (mojibake).
  2. Set the Correct Language Flag: Use tools like MKVToolNix to assign the correct ISO language code (ara for Arabic, heb for Hebrew) to the subtitle track so compatible players can apply the appropriate font rules.
  3. Use Modern Media Players: Players utilizing modern subtitle rendering engines (such as libass or modern VSFilter)—including MPV, VLC Media Player, and MPC-HC—will correctly shape Arabic cursive characters and handle Hebrew bidirectional ordering.
