Auto Framerate Switching in Modern Media Centers

Auto-framerate switching is a critical media center feature that synchronizes a display's refresh rate with the native frame rate of a video file to eliminate motion judder. Modern media players—such as Kodi, Plex, and Infuse—achieve this by extracting container- and bitstream-level metadata from MKV (Matroska) files, querying the connected display's supported refresh rates via operating system APIs, and triggering a display mode switch before video playback begins.

1. Metadata Extraction from the MKV Container

When an MKV file is loaded, the media center's demuxer (often built on libraries like FFmpeg or libmatroska) parses the file's track headers. The player specifically inspects the TrackEntry element within the Segment Info:

  • DefaultDuration: Matroska stores the time duration per frame in nanoseconds within the DefaultDuration element of the video track. For example, a 23.976 fps video has a DefaultDuration of approximately 41708333 nanoseconds, while a true 24.000 fps video has 41666666 nanoseconds.
  • Bitstream Fallback: If DefaultDuration is missing or imprecise, the parser reads the underlying video codec's bitstream headers—such as the Video Usability Information (VUI) parameters in H.264, HEVC, or AV1 streams—to determine the precise timing (num_units_in_tick and time_scale).

2. Querying Display Capabilities (EDID)

Once the frame rate is identified, the media center queries the operating system's display subsystem to find compatible display modes reported by the monitor or TV via Extended Display Identification Data (EDID).

  • Android / Android TV: The player queries the Display.getSupportedModes() API (available in Android 6.0+) or uses the SurfaceView.setFrameRate() API (introduced in Android 11).
  • Apple tvOS: The app uses AVPlayer and the AVDisplayCriteria API to request automatic switching for frame rate and dynamic range.
  • Windows: Players utilize DirectX, Direct3D, or vendor-specific GPU APIs (NVIDIA, AMD, Intel) to enumerate supported refresh rates.
  • Linux: Media centers query display servers using DRM/KMS (Direct Rendering Manager / Kernel Mode Setting) or X11/Wayland extensions to read available modes.

3. Target Refresh Rate Matching

The media center matches the parsed video frame rate to the closest optimal display refresh rate:

  • Exact Matching: 23.976 fps content is paired with a 23.976 Hz (or 23.98 Hz) mode, whereas 24.000 fps content is mapped to an exact 24.000 Hz mode.
  • Integer Multiple Matching (Cadence): If an exact match is unavailable, the player targets an integer multiple to prevent telecine judder. For example, 24 fps content can be mapped to 120 Hz (a 5:5 pulldown) or 25 fps content can be mapped to 50 Hz.
  • Fractional Precision Handling: High-end players ensure that fractional rates (23.976 fps, 29.97 fps, 59.94 fps) are strictly differentiated from integer rates (24.000 fps, 30.000 fps, 60.000 fps) to prevent a repeated or dropped frame every 41 seconds.

4. Executing the Display Mode Switch

After selecting the target refresh rate, the player calls the OS-level display change command.

Under legacy HDMI standards (HDMI 2.0 and older), this triggers a full HDMI clock resynchronization, leading to a temporary black screen ("HDMI bonk") lasting 1 to 3 seconds. To prevent the audio or video from starting prematurely, the media center pauses playback buffers until the OS confirms the display mode change is complete.

On setups supporting HDMI 2.1 Quick Media Switching (QMS) and Variable Refresh Rate (VRR), the display adjusts its refresh rate instantly without signal interruption or a blank screen.

5. Clock Synchronization During Playback

After the switch occurs, the media engine synchronizes the audio clock and display refresh clock. Because quartz crystals on hardware clocks can experience slight drift, the media center relies on an internal master clock (usually audio) and applies micro-adjustments or audio-resampling algorithms to maintain continuous frame-to-refresh synchronization throughout the duration of the stream.
