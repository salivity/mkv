How MKV Stores Stereo 3D Video Layout Flags

This article explains how the Matroska (MKV) container stores stereoscopic 3D metadata for frame-compatible video formats. MKV achieves this by embedding a dedicated stereoscopic signaling element within its track headers, allowing media players and 3D displays to identify whether a single video stream contains packed stereo views—such as Side-by-Side or Top-and-Bottom—and automatically adjust the display aspect ratio and rendering mode.

The StereoMode EBML Element

Matroska uses Extensible Binary Meta Language (EBML) to define its hierarchical data structure. Stereoscopic 3D metadata is stored at the container level within the track configuration. Specifically, it resides inside the Video element of a TrackEntry:

  • EBML Path: Segment \(\rightarrow\) Tracks \(\rightarrow\) TrackEntry \(\rightarrow\) Video \(\rightarrow\) StereoMode
  • Element ID: 0x53B8
  • Data Type: Unsigned Integer (uinteger)

The presence of the StereoMode element signals to the decoder that the video stream is multiplexed using a specific stereoscopic frame-packing layout. If the element is omitted, decoders default to 0 (mono / 2D).

Frame-Compatible Layout Values

Matroska assigns integer values to the StereoMode tag to define the spatial arrangement and eye dominance (which view appears first). The most common standard values include:

  • 0: Mono (default 2D)
  • 1: Side-by-Side (Left Eye is on the left)
  • 2: Top-and-Bottom (Right Eye is on the top)
  • 3: Top-and-Bottom (Left Eye is on the top)
  • 4: Checkerboard (Right Eye is first)
  • 5: Checkerboard (Left Eye is first)
  • 6: Row Interleaved (Right Eye is first)
  • 7: Row Interleaved (Left Eye is first)
  • 8: Column Interleaved (Right Eye is first)
  • 9: Column Interleaved (Left Eye is first)
  • 10: Anaglyph (Cyan / Red)
  • 11: Side-by-Side (Right Eye is on the left)
  • 12: Anaglyph (Green / Magenta)
  • 13: Both eyes laced in one block (Left Eye first)
  • 14: Both eyes laced in one block (Right Eye first)

Values 1, 3, and 11 are the most widely used in digital distribution for Half Side-by-Side (HSBS) and Half Top-and-Bottom (HTAB/HOU) encodings.

Display Dimensions and Aspect Ratio Handling

Frame-compatible stereoscopic formats often compress two views into standard frame dimensions (for example, two \(960\times1080\) images squeezed into a single \(1920\times1080\) frame). To ensure the individual eyes are displayed with the proper proportions after separation, MKV uses supplementary video header elements:

  • PixelWidth (0xB0) and PixelHeight (0xBA): Define the actual encoded resolution of the packed frame (e.g., \(1920\times1080\)).
  • DisplayWidth (0x54B0) and DisplayHeight (0x54BA): Define the target rendering dimensions for the combined canvas or per-eye aspect ratio, preventing anamorphic distortion when split into two full-aspect views.
  • DisplayUnit (0x54B2): Defines the unit used for display dimensions (pixels, centimeters, inches, or display aspect ratio).

Player and Decoder Behavior

When an MKV parser reads the StereoMode tag:

  1. Detection: The player detects the frame-packing format and eye ordering before decoding frame payloads.
  2. Separation: The renderer splits the decoded frame along the defined boundary (vertically for Side-by-Side, horizontally for Top-and-Bottom).
  3. Display Output: The software either formats the two views for output hardware (such as HDMI 3D frame-packing, polarized interlacing, VR headset viewports, or shutter glasses) or collapses the video into a standard 2D stream by cropping to the primary eye.
