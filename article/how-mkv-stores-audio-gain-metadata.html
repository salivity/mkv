How MKV Stores Audio Gain Metadata

Matroska (MKV) files manage volume normalization across diverse audio streams by utilizing a combination of EBML metadata tags, container-level track properties, and embedded bitstream data. Instead of modifying the original audio samples, the container stores standardized gain values—such as ReplayGain and EBU R128 metrics—allowing media players to dynamically adjust playback volume across different tracks, languages, or commentary streams without quality loss.

Matroska Tagging System

The primary method for storing loudness metadata in an MKV file is through its hierarchical Tags element. Matroska uses Extensible Binary Meta Language (EBML) to map metadata to specific components of the container.

To apply gain to an individual audio track:

  • A Tag element is created with a Targets sub-element.
  • The TargetTypeValue is set to 30 (the standard target level for an individual track).
  • The TagTrackUID links the tag directly to the unique identifier of the target audio track.
  • Inside SimpleTag entries, gain values are stored as key-value string pairs.

Commonly implemented tags include:

  • REPLAYGAIN_TRACK_GAIN: Stored in decibels (e.g., -6.50 dB), defining the adjustment needed to reach target loudness.
  • REPLAYGAIN_TRACK_PEAK: A floating-point number representing the highest sample value to prevent clipping.
  • R128_TRACK_GAIN: An EBU R128 standard gain offset, measured in LUFS/LU increments.

Track Header Elements

MKV specifications define audio properties within the TrackAudio element under the main TrackEntry. While less common for dynamic volume normalization than the Tagging system, the container supports static volume and output scaling parameters. Splitters can read these elements to determine baseline channel layouts, sampling rates, and default output adjustments before passing data to the audio decoder.

Embedded Bitstream Metadata Passthrough

In addition to container-level tags, MKV serves as a transparent transport for codecs that include their own internal volume normalization data:

  • Dolby Digital (AC-3 / E-AC-3): Contains Dialogue Normalization (dialnorm) metadata within the elementary stream headers.
  • AAC: Can contain Dynamic Range Control (DRC) and Loudness metadata inside the bitstream's Audio Specific Config.
  • Opus: Contains an internal Output Gain header field embedded directly in the stream headers to normalize default playback.

When an MKV muxer packs these elementary streams into clusters, it preserves this internal bitstream data entirely.

Playback and Decoupled Processing

When a player parses an MKV file, the demuxer reads both the container-level tags (like ReplayGain) and the codec-level headers. The playback software applies these values as digital pre-amplification parameters during decoding. Because the gain data exists purely as metadata, it ensures consistent loudness across different streams—such as switching from a loud 5.1 surround mix to a quiet stereo commentary track—without permanently altering the encoded audio.
