Convert MKV PGS Subtitles to Editable Text

Converting Presentation Graphic Stream (PGS) subtitles embedded within MKV files into editable text formats like SRT or VTT involves extracting image streams and processing them through Optical Character Recognition (OCR). Because PGS subtitles are stored as high-definition bitmap images rather than plain text, extraction tools must isolate the graphic frames, match character shapes to text data, resolve timing synchronization, and export the result into standard subtitle formats.

1. Demuxing the Subtitle Stream

The conversion process begins by separating the subtitle track from the MKV container, a process known as demuxing. Utilities such as mkvextract (part of the MKVToolNix suite) or FFmpeg read the MKV container's header to identify the PGS stream (codec ID: S_HDMV/PGS). The software extracts this track as a raw .sup file, which contains a series of timed image frames alongside metadata detailing display coordinates, palette information, and precise start and end timecodes.

2. Frame Parsing and Image Preprocessing

Once extracted, the subtitle tool (such as Subtitle Edit or BDSup2Sub) parses the .sup file into individual graphical events. Each subtitle event consists of a compressed bitmap and associated timing information.

Before text recognition can occur, the software preprocesses the bitmap images to improve accuracy:

  • Color Palette Binarization: The tool analyzes the color palette and alpha transparency channels, converting multi-color or antialiased text into high-contrast black-and-white (binary) images.
  • Noise Reduction: Transparent borders and background artifacts are removed to isolate only the character glyphs.
  • Layout Analysis: The software detects line breaks, italicized sections, and character spacing to preserve formatting.

3. Optical Character Recognition (OCR)

Because computers cannot natively read text stored inside a bitmap, an OCR engine is employed to translate visual shapes into Unicode characters. Tools typically use one of two methods:

  • Pattern Matching (Binary Comparison): The software compares individual character images against a database of known fonts and character matrices. When an unknown glyph appears, the user is prompted to type the character manually, gradually building a custom character matrix.
  • Neural Network OCR Engines (e.g., Tesseract): Modern tools often integrate Tesseract OCR. Tesseract analyzes the preprocessed image using machine learning models trained on vast typography datasets, automatically identifying letters, numbers, punctuation, and formatting styles such as italics or bold text without requiring manual training.

4. Error Correction and Post-Processing

OCR output is rarely flawless due to antialiasing, uncommon fonts, or overlapping artifacts. Subtitle conversion tools pass the raw recognized text through post-processing algorithms to correct common OCR errors, including:

  • Visual Ambiguities: Resolving confusions between uppercase "I", lowercase "l", and the number "1", or between "O" and "0".
  • Dictionary Checking: Using language-specific spellcheck dictionaries to validate recognized words.
  • Italics and Tagging: Inserting formatting tags (e.g., <i> and </i>) based on the detected slant of the glyphs.

5. Formatting and Timecode Generation

In the final step, the tool matches the corrected text lines back to the original timestamps extracted from the PGS metadata. The application then compiles the text and timecodes into a standard plain-text subtitle format, most commonly SubRip (.srt), WebVTT (.vtt), or Advanced SubStation Alpha (.ass), producing a lightweight, fully editable, and searchable subtitle file.
