How MKV Preserves Dolby Vision Profile 8 Metadata

This article explains the technical mechanism behind how the Matroska (MKV) multimedia container encapsulates and preserves dynamic metadata for Dolby Vision Profile 8 streams. Dolby Vision Profile 8 combines a standard High Dynamic Range (HDR10) base layer with dynamic metadata, allowing compatible displays to adjust brightness and color frame-by-frame while maintaining backward compatibility. The MKV format achieves this preservation primarily by encapsulating the raw HEVC bitstream along with embedded Supplemental Enhancement Information (SEI) Network Abstraction Layer (NAL) units directly within its structural tracks, accompanied by specific container-level signaling.

The Structure of Dolby Vision Profile 8

Dolby Vision Profile 8 (most commonly Profile 8.1) is a single-track, dual-layer compatibility profile. It consists of:

  1. A Base Layer (BL): A standard 10-bit HEVC (H.265) video stream encoded with the SMPTE ST 2084 (PQ) transfer function and BT.2020 color space, identical to standard HDR10.
  2. Reference Processing Unit (RPU) Metadata: Dynamic metadata containing scene-by-scene and frame-by-frame color mapping, trim data, and mastering display specifications.

Unlike dual-track profiles (such as Profile 7 used on UHD Blu-rays, which often utilize a separate Enhancement Layer), Profile 8 embeds the RPU directly into the video stream alongside the HDR10 base layer.

In-Band Carriage via NAL Units

The MKV container preserves Dolby Vision dynamic metadata primarily because of how the HEVC elementary stream is structured. The dynamic RPU metadata is carried "in-band" as specific HEVC Network Abstraction Layer (NAL) units.

  • Prefix SEI Messages: The RPU is packaged within ITU-T T.35 user data unregistered Supplemental Enhancement Information (SEI) messages (NAL unit type 39 in HEVC).
  • Interleaved Placement: These metadata NAL units immediately precede the video slice data for each frame to which they apply.

When multiplexing an HEVC stream into an MKV container, tools like MKVToolNix retain the elementary stream structure unaltered. The container stores the access units—including both the base video slices and the prefix SEI messages—inside standard Matroska SimpleBlock or BlockGroup elements under the V_MPEGH/ISO/HEVC codec ID. Because Matroska encapsulates the complete access unit, the RPU NAL units are never stripped or modified during the muxing process.

Container-Level Dolby Vision Signaling

To ensure that media splitters and hardware decoders can identify the presence of Dolby Vision without scanning every frame's bitstream, modern Matroska specifications include standardized signaling for Dolby Vision metadata.

During muxing, the container populates a dedicated configuration record within the video track headers:

  • Dolby Vision Configuration Record (CodecPrivate or Track Elements): This stores key parameters, including the Profile (Profile 8), Level, RPU presence flag, and backward compatibility ID (e.g., Cross-Compatibility ID 1 for HDR10).
  • Color Elements: The MKV header specifies standard color descriptors (MatrixCoefficients, TransferCharacteristics, and Primaries) set to BT.2020 and PQ, allowing non-Dolby Vision capable renderers to fall back safely to HDR10.

The Demuxing and Playback Pipeline

During playback, the MKV demuxer processes the file using a streamlined workflow:

  1. Detection: The demuxer reads the track headers to confirm the presence of Dolby Vision Profile 8.
  2. Pass-Through: The demuxer unpacks the SimpleBlock structures and passes the continuous HEVC bitstream—containing both the base layer frames and the interleaved SEI RPU packets—directly to the video decoder.
  3. Extraction and Application: A Dolby Vision-compliant decoder separates the RPU NAL units from the HEVC slice data. The base layer is decoded into raw video frames, and the RPU metadata is parsed to apply the dynamic tone mapping instructions before outputting the signal via HDMI to a compatible display. If the decoder or display does not support Dolby Vision, the SEI NAL units are simply ignored, and the video falls back to standard HDR10.
