How MKV Stores BT.709 Mastering Display Primaries

This article explains how the Matroska (MKV) container formats and stores mastering display color primaries for BT.709 video content. Using standardized Extensible Binary Meta Language (EBML) elements within the track header, MKV defines both standard color profiles and exact CIE 1931 chromaticity coordinates for mastering displays, ensuring accurate color reproduction during playback.

The MKV EBML Header Structure

Matroska organizes media properties in a hierarchical EBML tree. Color metadata is stored at the track level under the TrackEntry element, specifically nested inside the Video element.

To define color characteristics, MKV uses the Colour element (EBML ID: 0x55B0). Inside this element, video parameters such as color space, matrix coefficients, transfer characteristics, and mastering display primaries are explicitly defined.

Segment
 └── Tracks
      └── TrackEntry
           └── Video
                └── Colour (0x55B0)
                     ├── Primaries (0x55B9)
                     └── MasteringMetadata (0x55D0)

Standard Primary Signaling: The Primaries Element

For standard BT.709 signaling, MKV utilizes the Primaries element (0x55B9) located directly within the Colour master element.

  • Element Name: Primaries
  • EBML ID: 0x55B9
  • Type: Unsigned Integer
  • BT.709 Value: 1 (ITU-R BT.709)

When this value is set to 1, compliant decoders automatically apply the standard ITU-R BT.709 color primaries without requiring explicit coordinate lookups.

Explicit Mastering Display Coordinates: MasteringMetadata

When content requires precise mastering display metadata (often shared in mastering workflows or HDR-to-SDR conversions), MKV uses the MasteringMetadata sub-element (0x55D0).

Under MasteringMetadata, the container stores the exact CIE 1931 chromaticity coordinates (\(x, y\)) for the Red, Green, and Blue color primaries, along with the White Point, as floating-point values:

  • PrimaryRChromaticityX (0x55D1): 0.640
  • PrimaryRChromaticityY (0x55D2): 0.330
  • PrimaryGChromaticityX (0x55D3): 0.300
  • PrimaryGChromaticityY (0x55D4): 0.600
  • PrimaryBChromaticityX (0x55D5): 0.150
  • PrimaryBChromaticityY (0x55D6): 0.060
  • WhitePointChromaticityX (0x55D7): 0.3127 (Illuminant D65)
  • WhitePointChromaticityY (0x55D8): 0.3290 (Illuminant D65)

Additionally, mastering luminance limits can be specified using:

  • LuminanceMax (0x55D9): Maximum luminance in candelas per square meter (\(\text{cd/m}^2\) or nits), typically 100.0 for standard BT.709 mastering displays.
  • LuminanceMin (0x55DA): Minimum luminance in \(\text{cd/m}^2\), often 0.0001 to 0.05.

Container vs. Bitstream Precedence

Video codecs like H.264 (AVC) and H.265 (HEVC) can store BT.709 metadata internally within their Video Usability Information (VUI) or Supplemental Enhancement Information (SEI) messages.

When an MKV container contains explicit Colour and MasteringMetadata elements, modern media players and demuxers use the container-level metadata to configure rendering pipelines and display color management prior to initializing the video decoder. If container-level values and bitstream-level values differ, Matroska specification guidelines recommend that players prioritize container metadata or treat conflicting bitstream data as an override only if specifically instructed by the playback environment.
