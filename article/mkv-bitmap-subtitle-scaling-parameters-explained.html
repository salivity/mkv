MKV Bitmap Subtitle Scaling Parameters Explained

Bitmap subtitles such as PGS (Presentation Graphic Stream) and VobSub embedded in a Matroska (MKV) container rely on specific header elements and codec metadata to scale correctly against video streams. This article explains the key parameters within an MKV container that dictate how media splitters and players scale, position, and render embedded bitmap subtitle images.

Understanding Bitmap Subtitles in Matroska

Unlike text-based formats (like SRT or ASS) that can dynamically re-flow text, bitmap subtitles consist of pre-rendered image streams designed for a specific target canvas resolution. When played on displays with different resolutions or non-square pixel aspect ratios, the rendering engine must calculate how to resize these image overlays based on parameters defined in the MKV container.

Key MKV Parameters Controlling Scaling Behavior

The scaling behavior of embedded bitmap subtitles is primarily governed by the interaction between the video track's display geometry elements and the subtitle track's private configuration data.

1. Video Track Dimensions (TrackEntry \ Video)

Media players calculate the scale of subtitle planes relative to the video frame using the following video track header elements:

  • PixelWidth and PixelHeight: Defines the raw, unscaled coded resolution of the video stream (e.g., 1920x1080 or 720x480). Bitmap subtitle coordinates often map directly to these pixel values when no aspect ratio correction is required.
  • DisplayWidth and DisplayHeight: Specifies the target presentation dimensions after applying aspect ratio adjustments. If the video is anamorphic (e.g., non-square pixels such as a DVD standard 720x480 displayed as 16:9), players use these values to stretch the video and scale bitmap overlays horizontally or vertically to match the intended presentation shape.
  • DisplayUnit: Defines the units used for DisplayWidth and DisplayHeight (0 = pixels, 1 = centimeters, 2 = inches, 3 = display aspect ratio). This parameter ensures players correctly calculate the final pixel aspect ratio (PAR) for both the video and the overlaid subtitle planes.

2. Subtitle Track Configuration (CodecPrivate)

For bitmap formats, the subtitle track's CodecPrivate element contains essential baseline geometry:

  • VobSub (S_VOBSUB): The CodecPrivate data contains the .idx configuration header, which explicitly defines the original authoring canvas resolution (e.g., size: 720x480). Renderers compare this original canvas size against the active video track's PixelWidth/PixelHeight and DisplayWidth/DisplayHeight to apply uniform or non-uniform scaling multipliers.
  • PGS (S_HDMV/PGS): PGS streams embed composition metadata—specifically the Composition Object Segment (POS/PCS)—inside the subtitle packet payload. While the MKV container does not override individual PGS packet headers, the player aligns these fixed-coordinate segments (commonly 1920x1080 or 1280x720) with the container-level video display dimensions.

How Players Process Scaling

When rendering embedded bitmap subtitles, a compliant media player processes the MKV parameters through the following steps:

  1. Canvas Resolution Detection: The player reads the subtitle's native resolution from the CodecPrivate data or the subtitle stream header.
  2. Aspect Ratio Adjustment: The player checks the video track's PixelWidth, PixelHeight, DisplayWidth, and DisplayHeight to determine if the video is anamorphic.
  3. Scale Factor Calculation: A scaling factor is applied to resize the bitmap image from its native canvas resolution to match the active presentation frame, preventing subtitles from appearing distorted, stretched, or misaligned over black bars and active video areas.
