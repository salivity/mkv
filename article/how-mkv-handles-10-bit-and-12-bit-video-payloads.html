How MKV Handles 10-Bit and 12-Bit Video Payloads

The Matroska (MKV) multimedia container represents 10-bit and 12-bit color depth video payloads through a combination of dedicated container-level metadata and transparent bitstream encapsulation. By utilizing its Extensible Binary Meta Language (EBML) architecture, MKV provides explicit header fields to declare high bit-depth color properties while simultaneously preserving the native bitstream syntax of modern video codecs like HEVC, AV1, VP9, and AVC.

Container-Level Signaling: The Matroska Colour Element

Matroska defines video color parameters at the container level inside the TrackEntry hierarchy. Under TrackEntry -> Video, MKV specifications include a dedicated master element called Colour (EBML ID: 0x55B0).

Within the Colour master element, bit depth is explicitly defined by:

  • BitsPerChannel (EBML ID: 0x55B2): An unsigned integer indicating the bit depth of the luma and chroma components. For 10-bit video, this value is set to 10; for 12-bit video, it is set to 12 (defaulting to 8 if absent).

The Colour element also houses accompanying metadata necessary for correctly interpreting high bit-depth and High Dynamic Range (HDR) pipelines:

  • MatrixCoefficients (0x55B1): Specifies color space matrix transformations (e.g., BT.2020 non-constant luminance).
  • ColourPrimaries (0x55B9): Defines the chromaticity coordinates of the source primaries (e.g., ITU-R BT.2020).
  • TransferCharacteristics (0x55BA): Identifies the opto-electronic transfer function (e.g., SMPTE ST 2084 / PQ or ARIB STD-B67 / HLG).
  • Range (0x55B7): Explicitly signals limited (broadcast) or full (PC) quantization ranges.
  • MasteringMetadata (0x55D0): Contains sub-elements for SMPTE 2086 mastering display color volume and luminance bounds.

This container-level signaling allows demuxers and media players to configure rendering pipelines, swap surface formats (e.g., P010 for 10-bit YUV 4:2:0), and establish hardware overlay planes without needing to decode the underlying video frames first.

Bitstream-Level Encapsulation

While MKV provides container-level metadata, the actual 10-bit or 12-bit pixel data resides entirely within the payload bitstream inside SimpleBlock or Block structures. MKV operates as a transparent wrapper, preserving the exact bitstream formats required by specific codecs:

  • H.264 / AVC: High bit-depth video is identified via high profiles such as High 10 Profile or High 4:2:2/4:4:4 Predictive profiles, where the Sequence Parameter Set (SPS) contains bit_depth_luma_minus8 and bit_depth_chroma_minus8 set to 2 (for 10-bit) or 4 (for 12-bit).
  • H.265 / HEVC: Stored typically using the V_MPEGH/ISO/HEVC track type. The bit depth is signaled inside the Profile Tier Level (PTL) syntax and SPS structures (bit_depth_luma_minus8 = 2 for Main 10, or up to 4 for Main 12).
  • AV1: Stored as V_AV1. Bit depth is carried inside the AV1 Sequence Header via seq_profile and the bit_depth syntax element (Profile 0 supports 8-bit and 10-bit, Profile 2 supports 12-bit).
  • VP9: Stored as V_VP9. Profile 2 (10-bit/12-bit 4:2:0) and Profile 3 (10-bit/12-bit 4:2:2/4:4:4) carry the bit-depth configuration in the frame header.

Synchronization Between Container and Codec

MKV maintains a decoupled structure where the container metadata complements the elementary bitstream:

  1. Parser Efficiency: Fast-seeking parsers read the MKV header's BitsPerChannel to prepare the display pipeline before initializing hardware decoders.
  2. Decoder Authority: During playback, hardware and software decoders primarily parse the in-band codec headers (SPS, VPS, Sequence Headers) to construct the internal decoding arrays.
  3. Collision Handling: If a discrepancy occurs between the MKV BitsPerChannel element and the internal codec bitstream, compliant decoders prioritize the in-band elementary bitstream to decode the frames, while renderers may rely on the container's Colour element for display tone mapping and color space conversion.
