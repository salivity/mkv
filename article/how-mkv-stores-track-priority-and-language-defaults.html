How MKV Stores Track Priority and Language Defaults

The Matroska (MKV) container format manages track priority and default language selection through standardized metadata elements embedded within each track's header. This article details how MKV uses specific Extensible Binary Meta Language (EBML) flags, language identifiers, and structural hierarchy to instruct media players on which audio and subtitle streams to activate automatically upon playback.

The TrackEntry Element

Inside an MKV file, all stream metadata resides within the Tracks master element, which contains individual TrackEntry elements for every video, audio, and subtitle stream. Within each TrackEntry, the container stores technical parameters (codecs, bitrates) along with behavioral metadata that governs stream selection.

Key EBML Flags for Track Priority

To establish default playback behavior, the Matroska specification defines specific binary flags inside the TrackEntry:

  1. FlagDefault (Default Track Flag): This boolean flag indicates whether a track should be considered eligible for automatic playback. If set to 1 (True), the player recognizes it as a default candidate. If set to 0 (False), the player skips the track during initial selection unless a user explicitly requests it or no default exists. MKV allows multiple tracks of different types (e.g., one audio and one subtitle) to have FlagDefault set to 1.

  2. FlagForced (Forced Track Flag): Primarily used for subtitles, this flag marks content that is essential for context regardless of the user's general subtitle preferences (e.g., translating foreign dialogue in an otherwise native-language film). Players typically prioritize forced tracks when the corresponding audio language matches the forced subtitle language.

  3. FlagHearingImpaired and FlagVisualImpaired: Modern MKV specifications include specific accessibility flags. These provide additional context for media players configured to select accessibility streams automatically.

Language Identification (Language and LanguageBCP47)

Priority selection relies heavily on matching track languages with the user's preferred playback settings:

  • Legacy Language Element: Stores a 3-letter ISO 639-2 language code (e.g., eng, fre, jpn).
  • LanguageBCP47 Element: Introduced in newer specifications, this element supports modern BCP 47 language tags (e.g., en-US, zh-Hant), allowing for granular regional and dialect targeting.

Media players evaluate these tags against their own internal language priority lists (e.g., "Always play audio in English; show subtitles in English if audio is Japanese").

Track Ordering as a Tiebreaker

When multiple tracks share the same language and identical FlagDefault values, media players resolve the conflict using the physical order of the TrackEntry elements in the file header. Lower track numbers (appearing earlier in the EBML tree) receive higher priority by standard convention.

How Media Players Interpret MKV Track Priority

When an MKV file is opened, media players generally resolve track selection using the following priority hierarchy:

  1. User Override / Fixed Preferences: The player checks user settings for preferred languages and subtitle display rules.
  2. Forced Flag Check: If audio matches the user's language, the player looks for matching subtitles with FlagForced = 1.
  3. Language Matching with FlagDefault: The player searches for a track that matches the user's preferred language and has FlagDefault = 1.
  4. First Available Default: If no language match occurs, the player selects the first track of each type where FlagDefault = 1.
  5. Physical Fallback: If no tracks are flagged as default, the player falls back to the first available track in the file order.
