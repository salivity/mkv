Can MKV Encapsulate MPEG-5 EVC Video Streams?

The Matroska (MKV) multimedia container is technically capable of encapsulating video streams encoded in the MPEG-5 Essential Video Coding (EVC) format. Due to Matroska’s extensible, open architecture based on Extensible Binary Meta Language (EBML), it is designed to support virtually any compression format, including next-generation standards like EVC. This article explains how MKV handles EVC streams, the technical requirements for encapsulation, and the current state of playback and software support.

The Extensibility of the Matroska Container

Matroska does not restrict video storage to a fixed set of legacy codecs. Instead, it identifies video streams using standardized Codec IDs. When a new compression standard emerges, Matroska can accommodate it by defining a unique identifier and mapping the codec's bitstream format into the container’s track structure.

MPEG-5 EVC (standardized under ISO/IEC 23094-1) outputs bitstreams organized into Network Abstraction Layer (NAL) units, similar to its predecessors AVC (H.264) and HEVC (H.265), as well as its contemporary VVC (H.266). Because MKV already possesses mature frameworks for handling NAL-unit-based video, wrapping an EVC stream follows the same fundamental principles.

How EVC Encapsulation Works in MKV

To encapsulate an EVC video stream inside an MKV container, muxing tools handle two primary components:

  1. Codec Identification and Initialization Data: The container header stores the stream’s sequence parameter sets (SPS) and picture parameter sets (PPS) within the CodecPrivate element. This provides decoders with the necessary initialization data prior to parsing video frames.
  2. Frame Payload Mapping: The individual NAL units containing the slice data for each frame are placed inside Matroska SimpleBlock or BlockGroup elements, with accurate timestamps (PTS and DTS) assigned for smooth playback.

EVC features two profiles: a royalty-free Baseline Profile and a more advanced Main Profile. Matroska is agnostic to these profiles and can carry either stream without requiring structural container changes.

Current Software and Tooling Ecosystem

While the container specification easily allows for EVC integration, practical usage depends on software implementation:

  • Muxing and Demuxing: Open-source multimedia frameworks such as FFmpeg continuously expand support for MPEG-5 standards. Once the designated Codec ID and bitstream filters are fully mapped in modern muxers like MKVToolNix or FFmpeg, users can remux raw EVC elementary streams (.evc) directly into .mkv files.
  • Playback and Decoding: Playback requires both a demuxer capable of reading the MKV track mapping and an EVC decoder (such as the reference decoder or optimized third-party decoders) installed on the system.

Conclusion

MKV can encapsulate MPEG-5 Essential Video Coding (EVC) streams. The combination of Matroska's flexible EBML foundation and EVC's standard NAL unit structure ensures seamless packaging, multi-track audio pairing, and subtitle integration for this next-generation video codec.
