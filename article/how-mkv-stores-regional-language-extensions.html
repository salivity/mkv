How MKV Stores Regional Language Extensions

The Matroska (MKV) multimedia container manages regional language variations and dialects by integrating IETF BCP 47 language tags directly into its track metadata structures. While legacy MKV implementations relied strictly on three-letter ISO 639-2 codes, modern specifications incorporate dedicated elements that allow software to define language, script, region, and custom variant extensions (such as Brazilian Portuguese, Latin American Spanish, or Traditional Chinese) with high precision while maintaining backward compatibility with older media players.

Legacy Language Handling: ISO 639-2

Originally, the Matroska specification utilized a single EBML (Extensible Binary Meta Language) element within each TrackEntry called Language (Element ID: 0x22B59C). This field accepted standard ISO 639-2 bibliographic or terminology three-letter codes (e.g., eng for English, spa for Spanish, fre/fra for French).

Because ISO 639-2 only identifies base languages, it lacked native support for specifying regions or dialects. Distinctions like American English (en-US) versus British English (en-GB), or European Spanish (es-ES) versus Latin American Spanish (es-419), could not be stored in a standardized metadata field and were often relegated to informal track name strings.

Modern Implementation: The LanguageBCP47 Element

To resolve this limitation, the Matroska specification introduced the LanguageBCP47 element (Element ID: 0x22B59D). This element stores standard IETF BCP 47 language tags formatted as UTF-8 strings.

BCP 47 provides a hierarchical structure composed of hyphen-separated subtags, enabling granular language definitions:

  • Language Subtag: Identifies the primary language (e.g., pt for Portuguese, zh for Chinese).
  • Script Subtag: Identifies the writing system (e.g., zh-Hant for Traditional Chinese, zh-Hans for Simplified Chinese).
  • Region Subtag: Identifies the geographic territory using ISO 3166-1 country codes or UN M.49 geographical regions (e.g., pt-BR for Brazilian Portuguese, es-419 for Latin American Spanish).
  • Variant Subtags: Identifies dialectical or historical variations (e.g., de-CH-1901 for German, traditional Swiss orthography).

When an MKV file is muxed, the full BCP 47 string is written into the LanguageBCP47 element inside the corresponding TrackEntry block for audio, video, or subtitle tracks.

Dual-Tagging and Backward Compatibility

To maintain compatibility with older software and hardware players that do not recognize the LanguageBCP47 element, modern multiplexers (such as MKVToolNix and FFmpeg) employ a dual-tagging strategy:

  1. The Legacy Element: The base language code is extracted and written into the legacy Language element as an ISO 639-2 code (e.g., por for a pt-BR track). Older players read this field and display the primary language, ignoring the region.
  2. The BCP 47 Element: The complete tag (e.g., pt-BR) is written to LanguageBCP47. Modern players that support newer Matroska specifications read this field and prioritize it over the legacy tag, accurately presenting the regional variation to the user and applying region-specific subtitle styling or audio selection preferences.
