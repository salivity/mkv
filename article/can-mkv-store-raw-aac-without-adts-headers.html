Can MKV Store Raw AAC Without ADTS Headers?

An MKV (Matroska) container can hold raw AAC audio streams without ADTS headers, and doing so is the standard, specified behavior for the format. This article explains how the Matroska container handles raw AAC audio, why ADTS headers are removed during the muxing process, how stream configuration is preserved, and the technical implications for media playback and conversion.

The Matroska Specification for AAC

In the Matroska specification, AAC audio is identified primarily by the CodecID A_AAC. Unlike standalone .aac files or transport streams (MPEG-TS) that rely on Audio Data Transport Stream (ADTS) headers for frame synchronization and stream parameters, container formats like Matroska handle framing, packet boundaries, and timing independently.

Because the container manages synchronization at the track and cluster levels, storing ADTS headers alongside every audio frame is redundant and inefficient. Consequently, Matroska stores AAC audio as raw access units.

AudioSpecificConfig in CodecPrivate

To play raw AAC audio without per-frame ADTS headers, decoders need the stream's technical parameters. Matroska solves this by storing the stream's configuration once in the track header:

  • Header Extraction: When an AAC stream with ADTS headers is muxed into MKV, the muxer parses the initial ADTS header to determine the profile (e.g., AAC-LC, HE-AAC), sample rate, and channel configuration.
  • AudioSpecificConfig (ASC): This data is converted into an MPEG-4 AudioSpecificConfig binary structure.
  • Storage: The ASC is written directly into the CodecPrivate element of the Matroska track header.

Decoders initialize themselves using this CodecPrivate block before reading the subsequent raw audio frames.

Frame Storage Within Clusters

Once the track configuration is established:

  1. Header Stripping: The 7-byte (or 9-byte, if CRC is present) ADTS headers are stripped from each audio packet.
  2. Raw Access Units: The remaining raw AAC payload (the raw data block) is packaged directly into Matroska SimpleBlock or BlockGroup elements.
  3. Overhead Reduction: Stripping these headers saves approximately 7 to 9 bytes per frame, which reduces total file overhead over long durations.

Conversion and Remuxing Behavior

When working with multimedia tools like FFmpeg or MKVToolNix, this behavior occurs automatically:

  • Muxing into MKV: When ingesting an ADTS AAC stream, the muxer applies an ADTS-to-ASC bitstream filter (such as aac_adtstoasc in FFmpeg) to extract the global header and discard the frame headers.
  • Extracting from MKV: If raw AAC is extracted from an MKV into a standalone .aac file, the demuxer must read the AudioSpecificConfig from CodecPrivate and dynamically reconstruct ADTS headers for every frame to ensure compatibility with players that expect the ADTS format.
