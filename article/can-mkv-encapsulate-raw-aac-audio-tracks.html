Can MKV Encapsulate Raw AAC Audio Tracks?

The Matroska (MKV) multimedia container format natively supports the encapsulation of raw Advanced Audio Coding (AAC) audio streams without relying on proprietary wrappers, intermediary container formats, or transport stream packaging. By handling AAC as a pure elementary stream and storing critical codec configuration data directly within the container’s track headers, MKV provides an open, highly efficient mechanism for multiplexing AAC audio alongside any supported video or subtitle tracks.

Native Elementary Stream Support

Matroska does not require AAC audio to be enclosed inside proprietary wrappers like Apple’s M4A/CAF or standard MPEG-4 Part 14 (ISOBMFF) container structures. Instead, MKV accepts raw AAC Elementary Streams (ES). When audio is multiplexed into an MKV file, raw AAC access units (individual audio frames) are written directly into standard Matroska SimpleBlock or Block data structures inside the file's clusters.

Handling Stream Metadata via CodecPrivate

Standard AAC streams require configuration data—such as audio profile, sampling frequency, and channel configuration—to be decoded properly. In proprietary formats, this data is buried in specialized container atoms or repeated in continuous frame headers.

Matroska solves this natively through the CodecPrivate element:

  • AudioSpecificConfig Extraction: During multiplexing, tools extract the AudioSpecificConfig data from the source audio.
  • Track Header Storage: This configuration binary is stored once within the CodecPrivate element of the MKV track header.
  • Stripping Redundant Headers: If the source AAC stream uses an ADTS (Audio Data Transport Stream) wrapper, the multiplexer strips away the redundant 7-to-9-byte ADTS header from every individual frame. This reduces file overhead while keeping the underlying raw audio intact.

Standardized Matroska Codec IDs

Matroska uses standardized, open Codec IDs to signal AAC audio to decoders:

  • A_AAC: The modern, unified Matroska Codec ID used for all MPEG-2 and MPEG-4 AAC profiles (including LC, HE-AAC, and LD), relying on CodecPrivate to communicate the specific profile details.
  • Legacy Identifiers: Older MKV specifications utilized explicit IDs such as A_AAC/MPEG4/LC or A_AAC/MPEG2/LC, which also operated on raw elementary streams rather than third-party container boxes.

Tooling and Interoperability

Industry-standard open-source tools like FFmpeg and MKVToolNix handle raw AAC insertion natively. When packaging raw .aac files into an .mkv destination using these utilities, the tools automatically extract the configuration data, populate the track headers, and encapsulate the raw audio frames directly into the Matroska structure without requiring any external or proprietary container wrapping.
