Role of PrevUID in Linking Sequential MKV Segments

The Matroska (MKV) container format supports segment linking, a feature that connects separate video files into a continuous presentation without physically merging them. This article explains the role of the PrevUID element in this architecture, detailing how it identifies preceding file segments, enables seamless playback transitions, and maintains chronological integrity across split media files.

What is the PrevUID Element?

In the Matroska container hierarchy, every file segment can have a globally unique identifier called the SegmentUID, which is a 128-bit (16-byte) random value located in the Info element. The PrevUID (Previous Unique Identifier) is a companion element placed within the same Info header. Its primary function is to store the exact SegmentUID of the MKV file that directly precedes the current file in a sequence.

Facilitating Seamless Sequential Playback

When a large video—such as a feature-length film or an episodic series—is split into multiple MKV files, media players require a standardized method to determine file order. PrevUID provides this reference mechanism:

  1. Chain Identification: By reading the PrevUID in the current file, an MKV-compliant media player can verify if it has access to the preceding part of the video.
  2. Reverse Seeking and Navigation: While the NextUID element tells a player which file comes next, PrevUID allows players to handle backward navigation, rewind operations, and chronological verification across split media.
  3. Timeline Continuity: Media players use the combination of SegmentUID, PrevUID, and NextUID to construct a unified timeline. This ensures that timestamps, subtitles, audio tracks, and chapter markers transition smoothly across file boundaries without audio drops or visual stutter.

Role in Ordered Chapters and Linked Segments

Matroska supports two primary forms of linking: Hard Linking and Medium Linking (often utilized with Ordered Chapters).

  • Hard Linking: In basic multi-part files, PrevUID and NextUID form a linear chain where segments are played strictly end-to-end.
  • Ordered Chapters: In more complex setups, chapters within one MKV file can reference content in an external MKV file (such as a shared opening or ending sequence across an entire season of a television show). The PrevUID ensures the playback engine preserves the correct hierarchical and temporal relationship when returning from or navigating between these external segments.

Integrity and File Verification

Because PrevUID references a 128-bit hash rather than a standard file path, the linking is not broken if the previous file is renamed. Media players scan the directory for an MKV file containing the matching SegmentUID. This makes the sequential chain robust against superficial changes to filenames, relying purely on the structural metadata embedded inside the files.
