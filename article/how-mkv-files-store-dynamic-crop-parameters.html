How MKV Files Store Dynamic Crop Parameters

The Matroska (MKV) container format allows video players to remove black borders dynamically during playback without altering or re-encoding the original video stream. This is achieved by storing non-destructive cropping metadata directly within the container's video track headers. When a compatible media player opens the file, it reads these metadata flags and adjusts the active display viewport on the fly, rendering only the intended picture area.

The Matroska Track Header Structure

MKV files are built on EBML (Extensible Binary Meta Language), a hierarchical binary format similar to XML. Video configuration settings, including resolution and aspect ratio, are located within the video track definition inside the EBML tree:

Segment ➔ Tracks ➔ TrackEntry ➔ Video

Inside the Video element, Matroska defines four specific unsigned integer tags dedicated to border removal:

  • PixelCropTop: Number of pixels to remove from the top of the video frame.
  • PixelCropBottom: Number of pixels to remove from the bottom of the video frame.
  • PixelCropLeft: Number of pixels to remove from the left side of the video frame.
  • PixelCropRight: Number of pixels to remove from the right side of the video frame.

If any of these elements are omitted from the header, the player defaults their values to 0.

How the Playback Pipeline Applies Dynamic Cropping

  1. Header Parsing: Before decoding video frames, the media player reads the TrackEntry block to determine the raw stream resolution (PixelWidth and PixelHeight) and checks for the presence of the PixelCrop elements.
  2. Decoding: The video decoder processes the compressed video stream normally, decoding full frames that may still contain the hardcoded black bars.
  3. Viewport Calculation: Before rendering the frame to the screen, the player applies the crop boundaries:
    • Cropped Width = PixelWidth − (PixelCropLeft + PixelCropRight)
    • Cropped Height = PixelHeight − (PixelCropTop + PixelCropBottom)
  4. Aspect Ratio Adjustment: The player factors in any DisplayWidth, DisplayHeight, or DisplayUnit parameters to scale the cropped area correctly, ensuring the video displays at the intended aspect ratio without distortion.
  5. Presentation: The video renderer displays only the pixel region defined by the crop parameters, eliminating the black borders without needing a video filter chain that modifies the underlying decoded frames.

Advantages of Container-Level Cropping

  • Lossless and Reversible: Because the pixel data is never permanently removed from the bitstream, the crop parameters can be modified or removed instantly using remuxing tools like mkvmerge without re-encoding the video.
  • Encoder Efficiency: Encoding video with standard macroblock dimensions (such as multiples of 16) avoids compression artifacts. Container-level cropping allows the encoder to keep optimal dimensions during encoding while allowing the end user to see a clean, borderless image.
