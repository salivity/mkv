Understanding the FileUID Element in MKV Files

The FileUID element in a Matroska (MKV) multimedia file is a globally unique identifier designed to distinguish a specific file from all others across different systems and storage environments. Located within the Segment Information header of the Matroska container specification, this 128-bit value persists regardless of filename changes or folder relocation. This article explains the technical definition of FileUID, its role in segment linking and media library management, and why it is critical for container-level identification.

What Is the FileUID Element?

In the Matroska specification, the FileUID (Element ID: 0x73A4) is an EBML (Extensible Binary Meta Language) element found inside the Info segment. It contains a 128-bit (16-byte) randomly generated binary number, functionally equivalent to a standard UUID (Universally Unique Identifier).

When a Matroska file is multiplexed or authored, the multiplexer generates this identifier to assign the container an immutable signature. Because the generation process relies on pseudo-random algorithms, the probability of two independent MKV files sharing the same FileUID is virtually zero.

Primary Functions of FileUID

1. Independent File Identification

Filenames are mutable and frequently changed by users, media management tools, or operating systems. The FileUID remains embedded within the file’s internal binary structure. Media scrapers, media servers, and cataloging software can read this value to track, catalog, and reference a specific media file without relying on file system paths or naming conventions.

2. Segment Linking and Seamless Playback

One of Matroska’s advanced features is segment linking, which allows a single media experience to be split across multiple distinct files or to share common components (such as an opening sequence for television episodes). FileUID serves as the target address for cross-file references:

  • Hard Linking: A media player reads the NextUID or PrevUID elements in one file, which contain the exact FileUID of the adjacent file, allowing seamless sequential playback.
  • Ordered Chapters: Complex chapter structures reference the FileUID of external files to load specific segments on demand.

3. Deduplication and Version Control

Content management systems and distribution pipelines use the FileUID to detect duplicate files across large storage networks. If a video stream is re-encoded, remuxed, or modified, a new FileUID is generated, allowing automated systems to distinguish between different revisions of the same source material.

4. Stream and Track Disambiguation

While TrackUID uniquely identifies individual audio, video, or subtitle tracks within a container, FileUID represents the entire container context. This distinction ensures that multimedia frameworks (such as FFmpeg or GStreamer) properly associate tracks with their parent container during complex decoding or transcode pipelines.
