How MKV Stores 360 VR Projection Metadata

Matroska (MKV) files store projection metadata for 360-degree virtual reality (VR) video by utilizing dedicated Extensible Binary Meta Language (EBML) elements located directly within the video track settings. This standardized metadata defines the geometry, rotation, and field of view, instructing compatible media players and VR headsets on how to unwrap and project flat video frames onto a three-dimensional spherical canvas.

The Matroska Track Hierarchy

MKV organizes media data hierarchically using EBML. Video streams are defined inside the Tracks master element, with each individual stream represented by a TrackEntry. To declare immersive video properties, the container embeds a specialized Projection master element directly inside the Video settings block of the relevant track:

Segment ➔ Tracks ➔ TrackEntry ➔ Video ➔ Projection

Core Projection Elements

The Projection element contains several child elements that specify how the video must be rendered in 3D space:

  • ProjectionType: An integer defining the geometric mapping layout. Standard values include:
    • 0: Rectangular (standard flat 2D video).
    • 1: Equirectangular (standard 360-degree spherical projection).
    • 2: Cubemap (video mapped across six cubic faces).
    • 3: Mesh (custom 3D geometry defined by polygon vertices).
  • ProjectionPoseYaw, ProjectionPosePitch, and ProjectionPoseRoll: Float values that define the default rotational orientation of the camera in degrees. These offsets ensure the initial viewpoint faces the intended focal point of the scene.
  • ProjectionData: A binary field reserved for private or specialized configuration data, such as custom mesh definitions or proprietary cubemap layouts.

Stereoscopic Integration

Immersive VR often combines 360-degree projection with stereoscopic 3D. MKV manages this via the StereoMode element located at the same hierarchical level as the Projection element. Common values designate configurations such as Side-by-Side, Top-Bottom (Over-Under), or interleaved frame packing.

When a media player encounters both a StereoMode tag and a Projection tag, it first separates the image stream into distinct left and right eye buffers, then applies the specified projection mapping to render a stereoscopic 3D sphere.

Player Interpretation and Playback

During playback, parsers like FFmpeg, VLC, or native VR video engines inspect the TrackEntry headers before decoding the visual frames. If the ProjectionType is present and set to equirectangular or cubemap, the rendering engine creates a 3D bounding geometry, binds the decoded video frames as a texture to that geometry, and positions the virtual camera at the center. This system enables standard H.264 or HEVC codecs to carry VR video without requiring custom, non-standard codec extensions.
