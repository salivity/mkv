MKV Global Title Metadata in Multi-Episode Files

The Matroska (MKV) container format manages global and episode-specific metadata for multi-episode files by utilizing its flexible Extensible Binary Meta Language (EBML) architecture. Through a combination of the Segment Information element, a hierarchical tagging system, and chapter-level metadata binding, MKV allows media creators to define top-level file titles alongside distinct episode titles and properties within a single physical file.

Segment Information Element

At the highest structural level, an MKV file contains a Segment element that houses all video, audio, subtitle, and metadata tracks. Within this segment lies the Info (Segment Information) block, which contains the Title element.

  • Top-Level Storage: The Title element inside Segment/Info represents the default global title for the entire container.
  • Multi-Episode Role: In multi-episode files (such as an entire season or a multi-part feature combined into one file), this global field typically holds the overarching series or collection name (e.g., "Series Name - Season 01").

The Matroska Tagging System

For structured and granular metadata, Matroska uses a dedicated Tags master element containing one or more Tag elements. Each Tag element is composed of two primary sub-elements: Targets and SimpleTag.

Targets and TargetTypeValue

The Targets element establishes the scope of the metadata using TargetTypeValue integers. This hierarchy differentiates global titles from individual episode data:

  • TargetTypeValue 70 (Collection): Represents the entire franchise or series.
  • TargetTypeValue 60 (Season): Represents a specific season or volume.
  • TargetTypeValue 50 (Episode/Movie): Represents an individual episode.

SimpleTag

Within a Tag, SimpleTag blocks define key-value pairs such as TITLE, SUMMARY, ARTIST, and DATE_RELEASED. A tag targeting level 70 or 60 provides the global show context, while tags targeted at level 50 define individual episode names and descriptions.

Binding Metadata via Chapter Structures

When multiple episodes exist on a continuous timeline inside a single MKV file, MKV binds episode-specific titles using the Chapters element:

  1. Chapter Atoms: The timeline is divided into distinct episodes using <ChapterAtom> elements, each defined by start and end timestamps.
  2. ChapterDisplay: Each atom contains a <ChapterDisplay> element with a <ChapterString>, providing a basic title displayed during playback navigation.
  3. ChapterUID Linking: Each <ChapterAtom> is assigned a unique identifier (ChapterUID). The advanced Tags system references this ChapterUID inside its Targets element, linking rich metadata (such as episode name, director, and synopsis) directly to that specific time segment without conflicting with the global file title.

Through this modular hierarchy of Segment Titles, Chapter UIDs, and Target-scoped Tags, MKV maintains clear separation between global media titles and granular, multi-episode content.
