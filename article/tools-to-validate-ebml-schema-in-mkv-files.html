Tools to Validate EBML Schema in MKV Files

Validating the Extensible Binary Meta Language (EBML) schema of a Matroska (MKV) file is critical for developers ensuring container integrity, specification compliance, and playback compatibility. Because MKV is built on the hierarchical, binary EBML framework (defined in RFC 8794), syntax or structural errors in the schema can lead to parsing failures or corrupted media streams. This guide outlines the most effective command-line utilities, software development kits, and parsing tools developers can use to inspect and validate the EBML structure of any arbitrary MKV file.

1. MKVToolNix (mkvinfo)

mkvinfo is part of the official MKVToolNix suite and serves as the primary reference tool for analyzing Matroska files.

  • How it works: Running mkvinfo with high verbosity walks the entire EBML element tree, printing element names, sizes, IDs, and positions.

  • Validation capability: It will flag unknown elements, invalid element lengths, or malformed master elements.

  • Usage:

    mkvinfo -v -v input.mkv

    Adding -z allows developers to inspect the raw EBML tree directly in the console.

2. ebmlite (Python)

ebmlite is a lightweight, pure-Python library designed explicitly for parsing and validating EBML files using custom or standard EBML schemas defined in XML.

  • How it works: It parses binary files against schema definition files (such as the official Matroska EBML schema).
  • Validation capability: It allows programmatic validation. If an element's data type, mandatory occurrence, or parent-child hierarchy violates the schema, ebmlite raises specific parsing exceptions.
  • Key advantage: Ideal for automated test suites, CI/CD validation pipelines, and verifying custom EBML definitions.

3. MediaInfo

While widely used for high-level codec inspection, MediaInfo includes a powerful lower-level trace engine capable of detailed EBML tree parsing.

  • How it works: MediaInfo can dump full block-level and element-level hierarchies when executed with debug trace options.

  • Validation capability: Highlights unexpected element IDs, missing mandatory elements (such as EBMLHeader or Segment), and data size discrepancies.

  • Usage:

    mediainfo --Details=1 input.mkv

4. libebml and libmatroska

Maintained by the Matroska organization, libebml is the official C++ reference library for parsing and writing EBML data.

  • How it works: Developers can integrate the library into their own C/C++ applications to read an arbitrary MKV file stream.
  • Validation capability: It enforces strict type checks, maximum/minimum element size bounds, and correct nesting of EBML Master Elements. It reports parsing errors when encountering unmapped IDs or invalid data types (e.g., invalid float sizes or non-UTF-8 strings).

5. FFprobe / FFmpeg

FFprobe provides a quick way to detect container-level and bitstream-level corruption.

  • How it works: Using trace-level logging, FFprobe exposes the underlying demuxing steps as it reads EBML tags.

  • Validation capability: It detects missing headers, truncated elements, invalid track configurations, and malformed simple blocks.

  • Usage:

    ffprobe -v trace -i input.mkv

Summary

For quick manual inspection, mkvinfo -v -v and mediainfo --Details=1 are the most straightforward options. For automated testing and strict schema-level compliance checks in code, programmatic libraries like Python's ebmlite or the reference libebml C++ implementation provide the deepest validation against the official EBML specifications.
