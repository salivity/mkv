How Matroska Stores Segment Identifiers in MKV

The Matroska (MKV) container uses the Segment Info element to define master metadata and manage global file identification. Within this structure, unique binary identifiers—specifically the SegmentUID, PrevUID, NextUID, and SegmentFamily—serve as global fingerprints that distinguish individual files and facilitate seamless multi-file linking across playback streams. This article explains the technical structure of these identifier elements, how they are formatted within the Extensible Binary Meta Language (EBML), and how media players utilize them for file integrity and chained playback.

The Segment Info Element Context

In the Matroska file format, all content is encapsulated within a top-level Segment element. Inside this segment lies the Info element (EBML ID: 0x1549A966), which houses general information about the segment, such as timestamps, title, duration, and global identifiers.

Because Matroska is built on EBML—a binary equivalent of XML—each identifier inside the Info element is stored as a distinct, tag-based binary data field containing raw bytes.

Key Global Identifier Elements

Matroska uses several specific child elements within Info to uniquely track and chain files:

1. SegmentUID

  • EBML ID: 0x73A4
  • Format: 128-bit (16-byte) binary number (UUID/GUID).
  • Function: The SegmentUID is the primary global identifier for a single MKV segment. It is typically generated randomly via standard UUID algorithms during file creation or multiplexing. Every single MKV file (or segment within a concatenated file) possesses a unique SegmentUID, ensuring that no two files share the exact same identifier globally.

2. SegmentFamily

  • EBML ID: 0x4444
  • Format: 128-bit (16-byte) binary number.
  • Function: Used to group logically related segments that belong to the same collection or project, but are not necessarily ordered linearly (e.g., separate camera angles, multi-part series, or alternate editions). Multiple segments can share the same SegmentFamily ID.

3. PrevUID and NextUID

  • PrevUID (EBML ID: 0x3CB923): Contains the 128-bit SegmentUID of the preceding segment.
  • NextUID (EBML ID: 0x3EB923): Contains the 128-bit SegmentUID of the following segment.
  • Function: These elements enable hard linking between separate MKV files. When an MKV stream is split into multiple physical files (for instance, CD1 and CD2), PrevUID and NextUID create a cryptographic reference chain that allows compatible players to identify and play sequential files back-to-back without manual user intervention.

4. Supporting Filename Elements

Alongside binary identifiers, Matroska allows optional string elements to reference linked files by human-readable names:

  • SegmentFilename (0x7384): The original file name of the segment.
  • PrevFilename (0x3C83AB): The file name of the previous segment.
  • NextFilename (0x3E83BB): The file name of the next segment.

These string fields act as fallback hints for software if the referenced SegmentUID cannot be resolved automatically in the local file system.

How Players Use Matroska Identifiers

  1. Ordered Chapters and External Segment Linking: When an MKV file uses ordered chapters, it can reference chapters located in entirely separate MKV files. The main file uses the ChapterSegmentUID element within its chapter structure to match the target file’s SegmentUID, loading the external audio or video stream seamlessly into the current timeline.
  2. Loop Prevention and Validation: Media players scan the SegmentUID, PrevUID, and NextUID to verify that linked segments are loaded in the correct order and to prevent infinite playback loops if segments are misconfigured.
  3. Database Indexing: Media servers and cataloging software use the static 128-bit SegmentUID as a persistent primary key to track playback state, subtitles, and external metadata, even if the file itself is renamed on disk.
