How MKV Manages Segment Linking Across Files

Matroska (MKV) container files manage segment linking across multiple independent video files by using unique mathematical identifiers and metadata headers rather than physically concatenating media streams. Through a combination of 128-bit Segment Unique Identifiers (UIDs), sequence pointers, and ordered chapter systems, an MKV-compliant media player can dynamically load, synchronize, and play disparate files consecutively or conditionally as a single, uninterrupted stream.

The Foundation: Segment UIDs

Every Matroska segment contains a SegmentUID element within its Info header. This is a randomly generated 128-bit number (UUID) that acts as a globally unique fingerprint for that specific segment. When independent files need to reference one another, they rely on these UIDs rather than local file names or paths, making the linking resilient to file renaming.

Hard Segment Linking

Hard linking establishes a direct, linear sequence between two or more independent MKV files. This method uses two specific elements in the segment header:

  • PrevUID: Stores the SegmentUID of the preceding file in the sequence.
  • NextUID: Stores the SegmentUID of the subsequent file in the sequence.

When a media player reaches the end of a file with a NextUID defined, it scans the directory or playlist for a file matching that UID and immediately transitions playback without user intervention. Hard linking is typically used to split large continuous recordings into smaller files while preserving timeline continuity.

Soft Linking via Ordered Chapters

Soft linking is a more advanced and flexible method that uses MKV's chapter structure rather than sequential header flags. It enables non-linear assembly, reordering, and the reuse of shared segments across multiple files (commonly used to reference standard opening or ending sequences in multi-episode series).

  1. Ordered Chapter Flag: The main MKV file contains a chapter edition marked as "ordered," signaling to the player that chapters define the actual playback timeline rather than just navigation markers.
  2. ChapterSegmentUID: Individual chapters specify the SegmentUID of an external MKV file.
  3. ChapterSegmentEditionUID (Optional): Points to a specific edition within the linked external file if that file has multiple cuts.
  4. ChapterTimeStart and ChapterTimeEnd: Define the precise timecode range to extract from the external segment.

During playback, the media player follows the master file's chapter timeline, seamlessly jumping to external segments at defined timestamps and returning to the base file when that chapter ends.

Synchronization and Codec Constraints

For segment linking to work seamlessly without playback artifacts or crashes, the linked segments must maintain compatibility:

  • Codec and Track Matching: Linked files generally need matching video/audio codecs, dimensions, color spaces, and channel layouts to prevent the rendering pipeline from resetting or failing during transitions.
  • Timestamp Alignment: The player recalculates presentation timestamps (PTS) dynamically, masking internal timecode resets from the user interface and ensuring continuous audio/video synchronization across segment boundaries.
