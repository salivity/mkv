How MKV Handles Anamorphic Pixel Aspect Ratio

The Matroska (MKV) container handles anamorphic video by storing dedicated display metadata within its video track headers, allowing renderers to dynamically stretch or compress non-square pixels into the correct display aspect ratio (DAR) during playback. Rather than altering the underlying encoded video frames, MKV provides clear geometric instructions that decouple the stored pixel dimensions from the final rendered output, ensuring accurate widescreen presentation without requiring video re-encoding.

MKV Header Elements for Aspect Ratio

The Matroska specification manages anamorphic rendering through specific elements located inside the TrackEntry -> Video structure of the file:

  • PixelWidth and PixelHeight: These fields define the actual encoded matrix dimensions (e.g., 720x480 for NTSC DVD content).
  • DisplayWidth and DisplayHeight: These fields define the intended visual dimensions when the video is presented on a screen (e.g., 853x480 for a 16:9 aspect ratio).
  • DisplayUnit: An optional element indicating the measurement unit of DisplayWidth and DisplayHeight (defaulting to pixels, but can also represent centimeters, inches, or display aspect ratios).

Container-Level vs. Stream-Level Precedence

Anamorphic video streams often contain their own aspect ratio flags embedded directly inside the elementary video bitstream—such as the Video Usability Information (VUI) in H.264/AVC and H.265/HEVC or the sequence header in MPEG-2.

When an MKV file contains both container-level tags (DisplayWidth/DisplayHeight) and stream-level flags:

  1. Demuxer Interpretation: Modern media players and splitters prioritize the MKV container's track header values over the underlying bitstream parameters.
  2. Override Capability: This priority structure allows users to fix incorrect bitstream aspect ratio tags without re-encoding the entire video, simply by modifying the MKV header elements using a metadata editor like MKVToolNix.

The Rendering Pipeline

During playback, the rendering engine processes anamorphic MKV files in three distinct stages:

  1. Demuxing: The container demuxer parses the MKV headers, extracts PixelWidth, PixelHeight, DisplayWidth, and DisplayHeight, and passes these values to the video renderer.
  2. Decoding: The video decoder outputs uncompressed video frames at their native storage resolution (e.g., 720x576) with non-square pixels.
  3. Scaling and Display: The video renderer (such as Direct3D, OpenGL, or Metal) calculates the Pixel Aspect Ratio (PAR) using the formula: \[\text{PAR} = \frac{\text{DisplayWidth} \times \text{PixelHeight}}{\text{PixelWidth} \times \text{DisplayHeight}}\] Using this ratio, the GPU scaler applies bilinear, bicubic, or custom interpolation algorithms to map the non-square pixels onto the screen's square-pixel grid at the targeted Display Aspect Ratio.
