MKV Encapsulation of H.265 Custom SEI Messages

The Matroska (MKV) multimedia container fully supports the encapsulation of raw H.265 (HEVC) bitstreams containing custom Supplemental Enhancement Information (SEI) messages. Because MKV acts as a versatile wrapper that preserves the underlying Network Abstraction Layer (NAL) units of an HEVC elementary stream, custom or unregistered SEI messages are retained without data loss or corruption during the multiplexing process.

Understanding H.265 Custom SEI Messages

In the H.265/HEVC standard, SEI messages contain metadata that assists with decoding, display, or application-specific functions without altering the raw decoded video frames. Custom metadata typically relies on "User Data Unregistered" SEI payloads (SEI payload type 5), packaged within PREFIX_SEI_NUT (NAL unit type 39) or SUFFIX_SEI_NUT (NAL unit type 40) structures. These NAL units are embedded directly into the elementary video stream alongside parameter sets (VPS, SPS, PPS) and slice data.

How Matroska Encapsulates HEVC

Matroska encapsulates H.265 video using the codec identifier V_MPEGH/ISO/HEVC. By default, the container expects the bitstream formatted as length-prefixed NAL units (similar to the MP4/ISOBMFF container format defined in ISO/IEC 14496-15), though raw Annex B byte-stream formats can also be parsed and converted during muxing.

During encapsulation:

  • Access Unit Integrity: The muxer groups all NAL units corresponding to a single video frame—including slice data, parameter sets, and prefix/suffix SEI messages—into Matroska Block or SimpleBlock structures.
  • Payload Preservation: The container does not modify the internal payload of non-VCL (Video Coding Layer) NAL units. As long as custom SEI messages conform to standard H.265 NAL unit syntax, the muxer treats them as standard stream components and carries them across container boundaries.

Muxing and Demuxing Workflows

Standard multiplexing tools like FFmpeg and MKVToolNix (mkvmerge) seamlessly accept raw H.265 bitstreams with custom SEIs. When converting raw Annex B .h265 or .hevc files into an .mkv container, the tools parse the start codes, wrap the NAL units in Matroska blocks, and retain the custom metadata.

Upon extraction or playback:

  1. Demuxing: The demuxer reads the Matroska blocks and outputs the intact NAL unit stream.
  2. Parsing: Downstream applications or decoders that support reading custom SEI payloads can extract the specific metadata using the unique Universal Unique Identifier (UUID) designated in the user-data payload.
  3. Compatibility: Standard decoders that do not recognize custom SEI messages simply ignore them as per the H.265 specification, preventing playback errors while keeping the custom data available for specialized software.
