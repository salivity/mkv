Inspect MKV EBML Tree Hierarchies via CLI

The Extensible Binary Meta Language (EBML) serves as the foundational binary format for Matroska (MKV) multimedia containers. This guide explores the dedicated command-line tools used to inspect, parse, and analyze the raw EBML tree hierarchy inside any MKV file, detailing installation, essential command syntax, and practical examples for deep container inspection.

The Primary Tool: mkvinfo

The definitive command-line utility for inspecting Matroska EBML trees is mkvinfo, which is distributed as part of the open-source MKVToolNix package. It directly parses the binary MKV structure and prints every element, container, cluster, and track parameter in a human-readable hierarchical tree.

Installation

  • Debian/Ubuntu: sudo apt install mkvtoolnix
  • macOS (Homebrew): brew install mkvtoolnix
  • Arch Linux: sudo pacman -S mkvtoolnix-cli
  • Windows (Chocolatey): choco install mkvtoolnix

Basic EBML Inspection

Running mkvinfo on an MKV file provides a standard view of the segment header, track specifications, and metadata:

mkvinfo input.mkv

Full EBML Tree Parsing (Verbose Mode)

To view the complete EBML tree hierarchy, including all child elements, positions, and binary sizes, increase the verbosity level by passing the -v or --verbose flag multiple times:

mkvinfo -v -v input.mkv

Using -v -v forces mkvinfo to show all structural levels, down to individual cluster entries, frame references, timestamps, and EBML element IDs.

Showing Element Byte Offsets and Hex Dumps

To inspect the exact byte offsets and hexadecimal representations of EBML elements:

mkvinfo -s -v -v input.mkv
  • -s (or --summary): Displays a concise tree structure with element sizes.
  • -v -v: Expands clusters and sub-elements with element IDs and file positions (offsets).

Alternative Tools for EBML Inspection

While mkvinfo is the standard, other command-line utilities can inspect or validate EBML tree structures:

1. mkvalidator

Part of the Matroska specification tools, mkvalidator checks MKV files for technical compliance and can print the element tree:

mkvalidator --details input.mkv

2. MediaInfo CLI

MediaInfo provides raw container details when configured with the full debug level:

mediainfo --Details=1 input.mkv

This output reveals the underlying EBML tags, element sizes, and hierarchy starting from the root header.

Key EBML Elements in an MKV File

When inspecting an MKV EBML tree, you will typically observe the following root structure:

  • EBML Header (0x1A45DFA3): Contains EBML versioning, read version, and DocType (matroska).
  • Segment (0x18538067): The root container containing all payload data.
    • Info: General timeline, segment UID, duration, and muxing application.
    • Tracks: Codec IDs, video resolutions, audio sample rates, and language metadata.
    • Clusters: Block groups containing actual encoded audio/video/subtitle packets.
    • Cues: Index points for fast seeking.
    • Tags & Chapters: Nested metadata trees for chapters and tagging.
