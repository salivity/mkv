Matroska MKV Versions 1, 2, 3, and 4 Differences

The Matroska multimedia container format (.mkv) has evolved through four official specification versions since its inception in 2002. Each version builds upon the Extensible Binary Meta Language (EBML) architecture to improve storage efficiency, add support for modern video standards, and expand playback capabilities. This guide provides a clear breakdown of the technical differences, additions, and deprecations across Matroska versions 1, 2, 3, and 4.

Understanding EBML Versioning

Matroska files declare their specification level in the EBML header using two parameters:

  • DocTypeVersion: The version of the specifications used to create the file.
  • DocTypeReadVersion: The minimum version a parser/player must support to safely read and demux the file.

Because Matroska is designed with forward and backward compatibility, a modern player supporting v4 can typically parse older files seamlessly.

Matroska Version 1 (v1)

Released in 2003, Version 1 established the core open-standard foundation for the Matroska container format.

  • Core Structure: Defined the fundamental hierarchy containing the EBML Header, Segment, Track information, Clusters, Cues (seeking indexes), and basic Tags.
  • BlockGroup Element: Media payloads were encapsulated exclusively within BlockGroup elements, which contained the raw data frame alongside detailed metadata such as duration, reference blocks (for forward/backward prediction), and block virtual references.
  • Basic Codec Support: Supported core audio, video, and text subtitle tracks.

Matroska Version 2 (v2)

Version 2 expanded the interactivity and structure of media files, primarily targeting DVD-like capabilities and advanced navigation.

  • Enhanced Chaptering: Introduced advanced chapter structures, including Edition entries, hidden chapters, and ordered chapters (allowing seamless branching and modular playback).
  • Menu Systems: Added Matroska Menu elements to support interactive, DVD-style menu navigation.
  • Attachment Enhancements: Formalized support for embedding external files, such as custom fonts and cover art, directly into the container.

Matroska Version 3 (v3)

Version 3 focused heavily on optimization, reducing file overhead, and streamlining stream parsing for real-time playback.

  • SimpleBlock Element: Introduced the SimpleBlock structure as a lightweight alternative to BlockGroup. It embedded keyframe information, discardable flags, and lacing directly into the block header, drastically reducing container overhead for standard video streams.
  • Deprecations: Deprecated complex and rarely implemented features from v1 and v2, including BlockVirtual and legacy audio compression schemes within EBML headers.

Matroska Version 4 (v4)

Version 4 modernized the specification to support high-definition, stereoscopic 3D, and high-dynamic-range (HDR) video, serving as the basis for modern IETF standardization (RFC 8794).

  • Stereoscopic 3D Support: Introduced the StereoMode element to define 3D layouts (e.g., side-by-side, top-bottom, row interleaved).
  • Advanced Colorimetry and HDR: Added detailed color metadata elements, including MatrixCoefficients, BitsPerChannel, ChromaSubsampling, TransferCharacteristics, and mastering display metadata required for HDR formats like HDR10 and Dolby Vision.
  • Pixel and Field Adjustments: Added elements for FieldOrder (interlaced video handling), AlphaMode (transparency support), and display unit precision.
  • WebM Alignment: Synchronized elements with Google's WebM format, which is a restricted subset of Matroska v4.
