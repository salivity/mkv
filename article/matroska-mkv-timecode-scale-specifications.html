Matroska MKV Timecode Scale Specifications

This article provides an overview of how the Matroska multimedia container specification defines and utilizes timecode scale elements inside MKV files. It breaks down the role of the segment-level TimestampScale (historically known as TimecodeScale), explains the mathematical formula used to calculate absolute playback time, and outlines the legacy track-level scaling parameters.

The Role of TimestampScale in the Info Element

In the Matroska specification, timestamps are not stored as raw, absolute nanosecond values in every single data block. Storing large 64-bit nanosecond integers throughout a file would create unnecessary container overhead. Instead, Matroska uses a base scaling factor defined inside the Info (Segment Information) EBML element.

The primary element governing timing is TimestampScale (EBML ID: 0x2AD7B1):

  • Data Type: Unsigned integer.
  • Default Value: 1,000,000 (representing 1,000,000 nanoseconds, or 1 millisecond).
  • Function: It establishes the base multiplier (in nanoseconds) applied to all relative timestamps found in the file's clusters and blocks.

With the default value of 1,000,000, a relative timestamp integer of 1 inside a cluster or block corresponds exactly to 1 millisecond of playback time.

Calculating Absolute Timestamps

Matroska structures media data into Cluster elements, which contain individual SimpleBlock or BlockGroup elements. Timestamps at these levels are expressed as integer offsets:

  1. Cluster Timestamp: Each Cluster contains an integer timestamp representing the base time of that specific cluster relative to the start of the Segment.
  2. Block Timestamp: Each Block within a Cluster contains a signed 16-bit integer representing a relative offset from the parent Cluster’s timestamp.

To compute the absolute presentation time (in nanoseconds) of any given frame, demuxers apply the following formula:

\[\text{Time (in nanoseconds)} = (\text{Cluster Timestamp} + \text{Block Timestamp}) \times \text{TimestampScale}\]

Track-Level Scaling (TrackTimestampScale)

The Matroska specification also historically provided a track-level modifier known as TrackTimestampScale (EBML ID: 0x23314F, previously TrackTimecodeScale):

  • Location: Located within individual TrackEntry elements.
  • Data Type: Floating-point number.
  • Default Value: 1.0.
  • Function: It acts as a secondary multiplier applied to the resulting timestamp of that specific track, calculated as:

\[\text{Final Track Time} = \text{Time (in nanoseconds)} \times \text{TrackTimestampScale}\]

In modern revisions of the Matroska specification (version 4 and later), the use of TrackTimestampScale is deprecated. Demuxers and muxers are encouraged to maintain a single global TimestampScale across all tracks to avoid synchronization drift and playback incompatibility.

Precision vs. File Size Optimization

The Matroska timecode scale system provides flexibility for different media types:

  • Standard Video/Audio: The default 1 ms resolution (TimestampScale = 1,000,000) is sufficient for standard frame rates (e.g., 24 fps, 30 fps, 60 fps) and keeps block headers compact.
  • High-Precision Media: For high-frame-rate content or specialized scientific recordings requiring sub-millisecond precision, encoders can set TimestampScale to a smaller value (such as 1 for pure nanosecond precision), at the cost of requiring larger integer values in cluster timestamps.
