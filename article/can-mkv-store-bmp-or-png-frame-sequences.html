Can MKV Store BMP or PNG Frame Sequences?

The Matroska (MKV) container format is capable of storing both uncompressed BMP files and lossless PNG frame sequences as a functional video stream. Because MKV was engineered to be an open, highly extensible multimedia container, it does not restrict video tracks to traditional inter-frame compressed formats like H.264 or HEVC. This article explains how MKV handles image sequences as video streams, how they are technically encapsulated, and the practical considerations regarding playback and performance.

How MKV Handles Image Sequences

The Matroska specification is codec-agnostic. Instead of dictating specific compression algorithms, it stores metadata, timing packets, and raw payload data. When an image sequence such as a series of BMP or PNG files is wrapped into an MKV container, each image is treated as an individual video frame with a corresponding presentation timestamp (PTS).

Storing PNG as a Video Stream

PNG frames can be natively stored in MKV using the designated Codec ID V_PNG or standard FourCC mapping. In this setup:

  • Each keyframe contains the full, losslessly compressed PNG data.
  • Color depth, alpha channels (transparency), and RGB color spaces are fully preserved.
  • The container sets the frame rate by defining the time duration each PNG frame is displayed.

Tools like FFmpeg can mux PNG sequences directly into MKV without re-encoding by utilizing stream copy commands or the PNG video encoder:

ffmpeg -framerate 24 -i input_%04d.png -c:v copy output.mkv

Storing BMP and Raw Uncompressed Video

BMP files generally represent raw, uncompressed DIB (Device-Independent Bitmap) data. While BMP files contain header structures that can be stored directly via FourCC wrappers, MKV more commonly stores this data as uncompressed raw video (V_UNCOMPRESSED or rawvideo).

  • Direct Bitmaps: MKV can wrap BMP payloads using Video for Windows (VFW) compatibility layers.
  • Raw Video Frames: MKV can store the raw RGB or YUV planar/packed pixel arrays extracted from BMP files, along with resolution and color depth metadata.

Advantages and Practical Considerations

Using MKV to store frame sequences provides several benefits over loose directory-based image folders:

  • Single-File Portability: Thousands of separate files are consolidated into a single container without data loss.
  • Audio and Subtitle Synchronization: Audio tracks and timecodes can be muxed directly alongside the sequence.
  • Preserved Quality: Mastering-grade visuals retain exact pixel values, making this useful for archival and video production intermediate steps.

Limitations

  • File Size: Storing uncompressed BMPs or large PNG sequences results in massive file sizes that require high disk read speeds.
  • Decoding Overhead: PNG compression is computationally intensive for real-time decoding, which may cause frame drops during playback at high resolutions and frame rates.
  • Player Compatibility: While professional players and software like VLC or mpv support these streams natively, hardware decoders and consumer media players often lack support for non-standard video streams inside MKV files.
