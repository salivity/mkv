How Media Servers Select Languages Using MKV Track Names

Media servers like Plex, Jellyfin, and Emby automatically select audio and subtitle streams by parsing embedded Matroska (MKV) metadata against user-defined profile preferences. While standardized ISO language codes provide the baseline language identification, media servers read track names and header flags to distinguish between multiple tracks of the same language, identifying specialized versions like Director's Commentary, Forced subtitles, or specific audio formats.

The Role of MKV Metadata and Track Names

The MKV container format uses the Extensible Binary Meta Language (EBML), allowing rich metadata to be embedded directly into media files. For every stream (video, audio, or subtitle), the container stores two critical pieces of linguistic and descriptive data:

  1. Language Tags (Language / LanguageIETF): Standardized ISO 639-2 or BCP 47 codes (e.g., eng, spa, jpn) that identify the primary spoken or written language.
  2. Track Name / Title (Name): A customizable text string (e.g., "Full Dialogue", "Forced", "Director's Commentary", "Descriptive Audio") that offers context beyond the basic language code.

How the Automatic Selection Algorithm Works

When a media server scans a library or initiates playback, it executes a hierarchical matching algorithm:

  1. User Profile Evaluation: The server checks the active user's global settings, which define the preferred audio language, preferred subtitle language, and subtitle display mode (e.g., "Always on", "Manually selected", or "Shown with foreign audio").
  2. ISO Language Matching: The server first filters the available tracks by matching the embedded ISO language tag to the user's preferred language.
  3. Track Name Parsing and Keyword Heuristics: When multiple tracks share the same ISO language tag, the server parses the track name strings using internal heuristic rules and regular expressions:
    • Forced Subtitles: If a user selects foreign audio with native subtitles, the server searches for terms like Forced or Foreign Dialogue Only in the subtitle track name to display only translated non-native segments.
    • Accessibility Streams: Keywords like SDH (Subtitles for the Deaf and Hard of Hearing) or CC (Closed Captions) in subtitle titles, or Commentary and Audio Description in audio titles, allow the server to deprioritize or prioritize tracks based on accessibility configurations.
    • Default vs. Alternative Mixes: Audio track names containing descriptive flags (e.g., "Original Audio", "Stereo", "TrueHD Atmos") help the server pick the best track suited to the playback client's hardware capabilities.
  4. Flag Prioritization: In addition to track names, servers cross-reference container-level boolean flags—such as FlagDefault, FlagForced, and FlagHearingImpaired—with the track name metadata to resolve conflicts.

Best Practices for Reliable Language Automation

To ensure automated language selection functions accurately across all media servers:

  • Assign Accurate ISO Codes: Never leave the language tag as "Undefined" (und), as track names alone are rarely used as a fallback for the primary language filter.
  • Use Standardized Naming Conventions: Keep track names clean and descriptive, using universally recognized keywords like Forced, SDH, or Commentary.
  • Set Proper Flags: Use MKV multiplexing tools to set the Forced and Default flags alongside descriptive track titles so media servers can instantly recognize the track's purpose without relying solely on text parsing.
