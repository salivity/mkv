How MKV Represents Interlaced Video Field Order

The Matroska (MKV) container handles interlaced video by embedding structural metadata directly within its video track headers. Through specific elements such as FlagInterlaced and FieldOrder, the container signals to decoders and renderers whether the video stream contains fields rather than full progressive frames, as well as the exact temporal and spatial order in which those fields must be displayed. This container-level metadata allows media players to apply appropriate deinterlacing or field-matching algorithms without needing to parse the underlying video bitstream.

The Matroska Video Track Header Structure

In the Matroska specification, stream configuration is defined inside the TrackEntry element. For video streams, a nested Video master element holds rendering properties like resolution, aspect ratio, color spaces, and interlacing parameters.

MKV handles interlacing metadata using two primary elements:

  • FlagInterlaced (Element ID 0x9A): Declares whether the video is interlaced or progressive.
  • FieldOrder (Element ID 0x9D): Defines the exact field cadence and temporal relationship between fields.

The FlagInterlaced Element

The FlagInterlaced element is an unsigned integer flag that acts as the initial switch for the playback engine:

  • 0 (Undetermined): The container does not declare whether the content is interlaced or progressive.
  • 1 (Interlaced): The stream contains interlaced fields.
  • 2 (Progressive): The stream contains full, non-interlaced frames.

When FlagInterlaced is set to 1, the demuxer looks for the FieldOrder element to determine rendering behavior.

The FieldOrder Element Values

The FieldOrder element provides granular information regarding which field was captured first in time and which field occupies the top spatial line of the frame. Matroska defines standardized integer values for this element:

  • 0 - Progressive: The frames are progressive (used when interlacing flags are explicitly unset or overridden).
  • 1 - Top Field First (TFF): The top field (even scan lines) is displayed first in time, and stored first in the frame.
  • 2 - Undetermined: The video is known to be interlaced, but the field order is not specified in the container metadata.
  • 6 - Bottom Field First (BFF): The bottom field (odd scan lines) is displayed first in time, and stored first in the frame.
  • 9 - Bottom Field First (Swapped): The bottom field is displayed first in time, but the top field is stored first in the bitstream.
  • 14 - Top Field First (Swapped): The top field is displayed first in time, but the bottom field is stored first in the bitstream.

Values 1 (TFF) and 6 (BFF) represent the vast majority of consumer and broadcast interlaced media, such as standard broadcast television (often TFF) and DV video (often BFF).

Interaction Between Container Flags and Codec Bitstreams

Many video compression standards (like MPEG-2, H.264, and VC-1) include their own field order signaling inside sequence headers or Picture Timing SEI messages. Matroska's container-level flags provide an independent layer of abstraction.

When an MKV file is processed:

  1. The demuxer reads FlagInterlaced and FieldOrder from the MKV track header.
  2. The demuxer passes these parameters downstream to the video renderer and deinterlacer.
  3. If container-level flags conflict with codec bitstream metadata, renderers typically prioritize the container flags or use them as a fallback when bitstream headers omit interlacing information.

This ensures proper field parity, preventing common playback artifacts such as comb distortion, judder, or strobing caused by inverted field order.
