How MKV Stores Custom Color Space Transfer Functions

The Matroska (MKV) multimedia container stores custom color space and transfer function data through structured Extensible Binary Meta Language (EBML) elements located within its video track headers, supplemented by bitstream-level metadata and container attachments. By combining standardized ITU-T H.273 enumerations in the Colour master element, precise mastering display chromaticity coordinates, and raw bitstream signaling like Supplemental Enhancement Information (SEI) NAL units, MKV enables rendering engines and professional grading suites to accurately reconstruct custom electro-optical transfer functions (EOTFs) and cinematic color volumes.

The EBML Colour Element Hierarchy

Matroska defines color grading parameters inside the TrackEntry element using the Colour master element (EBML ID: 0x55B0). This section provides container-level signaling for display pipelines without requiring full decoding of the video payload.

The key child elements governing color interpretation include:

  • TransferCharacteristics (0x55BA): Identifies the opto-electronic or electro-optical transfer function. It uses integer values mapped to ITU-T H.273 / ISO/IEC 23001-8 standards, such as BT.709 (Value 1), SMPTE ST 2084 / PQ (Value 16), and ARIB STD-B67 / HLG (Value 18).
  • ColourPrimaries (0x55BB): Defines the chromaticity coordinates of the source color primaries (e.g., BT.2020, DCI-P3, or BT.709).
  • MatrixCoefficients (0x55B1): Specifies the matrix coefficients used to derive luma and chroma signals from primary color inputs.
  • Range (0x55B9): Explicitly flags the clipping boundaries of the signal (broadcast legal range, full range, or unspecified).

Handling Custom Mastering Color Volumes

When cinematic grading relies on a custom color volume rather than standard broadcast targets, MKV utilizes the MasteringMetadata element (0x55D0). This sub-element defines the physical color capabilities of the display used during the color grading process according to SMPTE ST 2086 specifications.

The container explicitly stores floating-point coordinates for:

  1. Primary Chromaticities: PrimaryRChromaticityX/Y, PrimaryGChromaticityX/Y, and PrimaryBChromaticityX/Y define the exact triangular gamut of the mastering monitor.
  2. White Point Chromaticities: WhitePointChromaticityX/Y define the calibrated target white (such as D65 or DCI white).
  3. Luminance Range: LuminanceMax and LuminanceMin specify the peak brightness and black level capabilities in candelas per square meter (\(\text{cd/m}^2\) or nits).

Bitstream-Level Custom Transfer Curves and Dynamic Metadata

MKV acts as a transparent carrier for codecs (such as HEVC, AV1, or ProRes) that carry custom or dynamic transfer curves directly inside the elementary video bitstream:

  • SEI NAL Units: In codecs like HEVC (H.265), custom tone-mapping curves, parametric transfer functions, and dynamic HDR metadata (such as HDR10+ SMPTE ST 2094-40 or Dolby Vision RPU data) are embedded within Video Usability Information (VUI) and Supplemental Enhancement Information (SEI) packets. MKV preserves these bitstream elements intact.
  • BlockAdditions: MKV supports auxiliary block data structures (BlockAdditions) to associate dynamic metadata layers directly with individual frame blocks for advanced multi-layer video workflows.

Embedding Custom LUTs and Calibration Data via Attachments

For proprietary production formats, logarithmic curves (such as ARRI LogC or REDLogFilm), or custom 3D Look-Up Tables (LUTs) that fall outside standardized ITU-T enumerations, MKV utilizes its native attachment framework.

The AttachedFile element stores .cube, .clut, or ICC profiles alongside the video track with designated MIME types (e.g., application/x-lut or application/vnd.iccprofile). Video players and digital audio workstations with advanced color management engines can extract these attachments and apply the specific non-linear transformation curves during real-time playback.
