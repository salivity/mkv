Can MKV Store Multiple Video Tracks with Different FPS?

The Matroska (MKV) multimedia container fully supports storing multiple video streams with different frame rates simultaneously within a single file. This capability stems from the flexible architecture of the Matroska format, which treats each media stream as an independent track with its own distinct timing, resolution, and codec parameters. This guide explains how MKV handles multiple video tracks, how frame rate independence works, and what to consider regarding playback and compatibility.

Independent Track Architecture

Matroska is an open-standard container format designed to hold an unlimited number of video, audio, picture, and subtitle tracks. When an MKV file is created, each video stream is encapsulated in its own separate TrackEntry element.

Because each track header is entirely independent, properties such as the following can vary across tracks:

  • Frame Rate: One video track can run at 24 fps (film standard), while a second track runs at 60 fps (high frame rate).
  • Resolution and Aspect Ratio: Different streams can have different resolutions (e.g., 4K and 720p).
  • Compression Codec: Different tracks can use entirely different codecs (e.g., H.264/AVC, H.265/HEVC, AV1, or VP9).

How Matroska Manages Frame Rates

MKV files do not enforce a single global frame rate clock across the entire file. Instead, the format uses a timestamp-based system to display frames accurately:

  1. Nanosecond Timecodes: Every individual frame (block) inside an MKV track carries a relative timestamp based on the container's internal timecode scale (typically measured in nanoseconds or milliseconds).
  2. Variable Frame Rate (VFR) Support: Because timing is handled per frame via timestamps rather than a fixed container rate, MKV natively supports both Constant Frame Rate (CFR) and Variable Frame Rate (VFR) streams across different tracks.
  3. No Synchronization Conflicts: Because the demuxer reads the timing for each track independently, a 23.976 fps primary video and a 29.97 fps secondary video will each present their frames at the correct time intervals without interfering with one another.

Practical Use Cases

Storing multiple video streams with differing frame rates in one MKV file is commonly used for:

  • Multi-Angle Video: Offering different camera perspectives of a live event or sports broadcast, where some angles might be recorded at higher capture rates.
  • Director's Commentary / Picture-in-Picture: Including a secondary video track (e.g., the director talking in the corner) encoded at a lower frame rate (such as 15 or 24 fps) to save file size, while the main feature plays at 60 fps.
  • Mixed-Format Releases: Packaging archival footage (e.g., 25 fps PAL or 29.97 fps NTSC) alongside remastered modern footage (e.g., 24 fps or 48 fps HFR) in a single archival container.

Playback and Compatibility Considerations

While the MKV container itself easily accommodates multiple video tracks with varying frame rates, playback behavior depends on the software or hardware decoder:

  • Track Switching: Most standard media players (such as VLC, MPV, and MPC-HC) allow users to toggle between available video streams seamlessly. The player adapts its rendering rate to match whichever stream is currently selected.
  • Simultaneous Playback: If you intend to play both video tracks at the same time (e.g., dual-screen or Picture-in-Picture), the player must support multi-stream decoding.
  • Hardware Limitations: Some hardware media players and Smart TVs only decode the default primary video track and may not recognize or switch to secondary video tracks within an MKV file.
