How MKV Handles Audio with Different Sample Rates

The Matroska (MKV) multimedia container format natively supports multiple embedded audio streams featuring different sampling frequencies by treating each audio stream as an entirely independent track. Utilizing the Extensible Binary Meta Language (EBML) structure, MKV stores discrete metadata—including individual sample rates—for every stream within its own track header. This architecture allows the container to maintain precise audio-video synchronization across disparate audio tracks (such as a 48 kHz surround mix alongside a 44.1 kHz stereo commentary) without requiring uniform encoding parameters.

Independent Track Metadata

In the MKV format, every stream (video, audio, or subtitles) is defined within a TrackEntry element. For audio streams, this entry contains a specific Audio sub-element that defines parameters unique to that stream:

  • SamplingFrequency: Specifies the base sampling rate of the audio data (e.g., 44100 Hz, 48000 Hz, 96000 Hz).
  • OutputSamplingFrequency: Used when the output frequency differs from the encoded frequency, common in technologies like Spectral Band Replication (SBR) in AAC/HE-AAC.
  • Channels and BitDepth: Defines channel layout and sample resolution independently for each track.

Because this metadata is defined per track rather than globally, the container imposes no requirement for audio streams to share the same sampling rate, codec, or channel configuration.

Timestamp-Based Interleaving

MKV synchronizes audio and video using absolute timestamps rather than counting audio samples. Media data is divided into Cluster elements containing SimpleBlock or BlockGroup structures:

  1. Master Timebase: The container operates on a global timebase (defined by TimestampScale, typically set to 1,000,000 nanoseconds, or 1 millisecond).
  2. Packet Timestamps: Each audio packet contains a timestamp relative to the cluster's start time.
  3. Decoupled Timing: Because the container relies on container-level timecodes to determine when a block should be presented, differences in sampling rates (which dictate how many samples represent a given duration) do not disrupt overall playback synchronization.

Demuxing and Decoder Pipeline

When a media player reads an MKV file containing tracks with different sampling rates:

  1. Track Parsing: The demuxer reads the TrackEntry for the active audio stream to configure the appropriate audio decoder.
  2. Stream Demultiplexing: The demuxer extracts only the packets associated with the active track number, ignoring inactive audio tracks.
  3. Dynamic Switching: If a user switches audio tracks during playback to one with a different sampling rate (e.g., moving from 48 kHz to 96 kHz), the demuxer signals the audio pipeline to reconfigure or reinitialize the decoder and the system's audio output device with the new stream parameters.
