How MKV Stores Mastering Display Color Volume Data

The Matroska (MKV) multimedia container format stores High Dynamic Range (HDR) mastering display color volume data natively as structured metadata elements inside the video track header. By integrating the SMPTE ST 2086 standard directly into its container specifications, Matroska allows media splitters, decoders, and playback hardware to extract mastering display color primaries, white point coordinates, and luminance boundaries without having to parse the underlying elementary video bitstream.

The Matroska Colour Element Hierarchy

In an MKV file, track configurations are organized hierarchically under the Segment master element. Video-specific parameters reside within the TrackEntry element, which contains a Video master element.

Within the Video element, Matroska provides a dedicated Colour master element (EBML ID 0x55B0). This element serves as the parent container for all colorimetry settings, including color space, transfer characteristics, matrix coefficients, and HDR metadata.

Mastering Display Metadata (SMPTE ST 2086)

To define the color volume of the display used to master the video content, Matroska includes a specific sub-element inside Colour called MasteringMetadata (EBML ID 0x55D0). This element contains floating-point values representing the chromaticity coordinates defined by the CIE 1931 color space and the luminance bounds in candelas per square meter (\(\text{cd/m}^2\) or nits):

  • Color Primaries: Defines the coordinates for the red, green, and blue primaries used by the mastering monitor:
    • PrimaryRChromaticityX (0x55D1) and PrimaryRChromaticityY (0x55D2)
    • PrimaryGChromaticityX (0x55D3) and PrimaryGChromaticityY (0x55D4)
    • PrimaryBChromaticityX (0x55D5) and PrimaryBChromaticityY (0x55D6)
  • White Point Coordinates: Defines the chromaticity of the reference white point (typically D65 for standard HDR10 content):
    • WhitePointChromaticityX (0x55D7) and WhitePointChromaticityY (0x55D8)
  • Luminance Range: Defines the physical output capabilities of the mastering display:
    • LuminanceMax (0x55D9): The maximum display luminance (e.g., 1000 or 4000 nits).
    • LuminanceMin (0x55DA): The minimum display luminance (e.g., 0.005 or 0.0001 nits).

Content Light Level Metadata

In addition to the physical mastering monitor parameters, MKV stores the dynamic light levels of the actual video content directly within the Colour element as companion metadata:

  • MaxCLL (0x55BC): Maximum Content Light Level, representing the highest single-pixel brightness value across the entire video.
  • MaxFALL (0x55BD): Maximum Frame-Average Light Level, representing the highest average frame brightness across the entire video.

Container-Level vs. Bitstream-Level Storage

HDR video codecs such as HEVC (H.265) and AV1 typically carry mastering display color volume data inside the encoded video stream using Supplemental Enhancement Information (SEI) messages or sequence-level metadata.

MKV replicates this data at the container level to optimize playback workflows:

  1. Fast Extraction: Demuxers and source filters can read the container headers instantly upon loading the file, passing the HDR characteristics directly to the display pipeline or renderer before decoding begins.
  2. Hardware Handshaking: The player can configure HDMI/DisplayPort output and trigger display HDR switching without waiting for the video decoder to encounter the first in-band SEI NAL unit.
  3. Tone Mapping Assistance: If playback occurs on a Standard Dynamic Range (SDR) or lower-luminance display, tone-mapping algorithms can prepare look-up tables (LUTs) in advance based on the container's declared luminance boundaries and color coordinates.
