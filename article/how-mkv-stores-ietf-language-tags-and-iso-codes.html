How MKV Stores IETF Language Tags and ISO Codes

The Matroska (MKV) container format manages track languages by pairing legacy ISO 639-2 codes with modern IETF BCP 47 language tags inside its track metadata structure. By utilizing two distinct, coexisting Extensible Binary Meta Language (EBML) elements within each track entry, MKV preserves full backward compatibility with older media players while enabling modern players to read precise regional, script, and dialect information.

The EBML Language Elements

Inside the MKV hierarchy, every audio, video, and subtitle stream is defined within a TrackEntry master element. Within this entry, Matroska defines two separate elements to handle language identification:

  • Language (EBML ID: 0x22B59C): The legacy element used since the inception of the Matroska format. It accepts standard 3-letter bibliographic ISO 639-2 codes (such as eng for English, fre for French, or jpn for Japanese).
  • LanguageBCP47 (EBML ID: 0x22B59D): The modern element introduced to support full IETF BCP 47 language tags. This allows strings containing language, script, region, and variant subtags (such as pt-BR for Brazilian Portuguese, zh-Hant for Traditional Chinese, or es-419 for Latin American Spanish).

Dual-Storage Implementation

To ensure seamless playback across all generations of hardware and software demuxers, MKV multiplexers (such as MKVToolNix) write both tags simultaneously to the same TrackEntry.

When a track is muxed with an IETF tag:

  1. The multiplexer populates LanguageBCP47 with the complete, specific IETF BCP 47 string.
  2. The multiplexer automatically maps the primary language subtag to its corresponding 3-letter ISO 639-2 code and writes it to the legacy Language element.
  3. If an IETF tag cannot be accurately mapped to a distinct ISO 639-2 code, the legacy element is typically set to und (undetermined) or the closest matching macro-language.

Demuxer and Player Parsing Hierarchy

Media players and demuxers read these elements using a fallback priority defined in the official Matroska specifications:

  • Modern Parsers: Software that supports BCP 47 prioritizes the LanguageBCP47 element. If found, it ignores the legacy Language element, presenting the user with precise regional audio and subtitle track names.
  • Legacy Parsers: Older hardware players, smart TVs, or deprecated software that do not recognize EBML ID 0x22B59D simply skip the unknown element and read the standard Language element instead.
  • Default Fallback: If neither element is present in a track header, the container specification mandates that the track language defaults to eng (English), or und (undetermined) depending on the container version specifications applied during playback.
