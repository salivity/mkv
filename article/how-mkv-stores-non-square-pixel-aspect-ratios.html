How MKV Stores Non-Square Pixel Aspect Ratios

The Matroska (MKV) container handles non-square pixel formats—commonly known as anamorphic video—by defining separate metadata fields for coded pixel dimensions and target display dimensions within its video track headers. Instead of relying solely on the underlying video codec's internal bitstream parameters, MKV uses dedicated elements like PixelWidth, PixelHeight, DisplayWidth, and DisplayHeight to instruct media players exactly how to scale and stretch the video frame for correct presentation.

Core Header Elements for Aspect Ratio

MKV manages aspect ratios within the TrackEntry -> Video element of the Matroska specification. The key elements include:

  • PixelWidth & PixelHeight: Define the raw, encoded resolution of the video stream in actual pixels (e.g., 720x480 for NTSC DVD video).
  • DisplayWidth & DisplayHeight: Define the dimensions at which the video should be rendered on screen (e.g., 853x480 for a 16:9 aspect ratio).
  • DisplayUnit: Specifies the measurement unit used for DisplayWidth and DisplayHeight. The default value is 0 (pixels), but it can also represent centimeters (1), inches (2), or a direct aspect ratio (3).

When a video contains non-square pixels, the Sample Aspect Ratio (SAR) or Pixel Aspect Ratio (PAR) is derived by comparing the coded pixel grid with the specified display dimensions.

Cropping and Display Calculations

Matroska also supports frame cropping prior to scaling via dedicated cropping elements:

  • PixelCropTop
  • PixelCropBottom
  • PixelCropLeft
  • PixelCropRight

When cropping values are present, modern media players subtract the cropped pixels from PixelWidth and PixelHeight before applying the scaling factor determined by DisplayWidth and DisplayHeight. This ensures that black bars can be removed without distorting the final Display Aspect Ratio (DAR).

Container vs. Codec Bitstream Precedence

Video codecs such as H.264 (AVC), H.265 (HEVC), and MPEG-2 can also store aspect ratio information directly inside their Sequence Parameter Sets (SPS) or Video Usability Information (VUI).

In an MKV container:

  1. Container-level priority: Most media splitters and players give precedence to the MKV track headers (DisplayWidth/DisplayHeight) over the internal bitstream metadata.
  2. Bitstream fallback: If the MKV header omits explicit DisplayWidth or DisplayHeight values, playback software falls back to the codec's internal SAR/PAR signaling to calculate the proper render size.

Practical Example: Anamorphic NTSC

A standard widescreen DVD source is encoded at a non-square resolution of 720x480 pixels with a 16:9 Display Aspect Ratio. In an MKV container, this is represented as:

  • PixelWidth: 720
  • PixelHeight: 480
  • DisplayWidth: 853 (or 854)
  • DisplayHeight: 480
  • DisplayUnit: 0 (pixels)

The playback software reads the 720x480 raw data from the decoder and stretches the horizontal axis to 853 pixels during the rendering stage, ensuring the geometry appears undistorted on modern displays.
