MKV Chapter Edition UIDs for Branching Media

Matroska (MKV) containers manage non-linear and branching narrative media through an advanced, hierarchical chapter structure governed by Extensible Binary Meta Language (EBML). By using unique identification elements—specifically the EditionUID within an EditionEntry—the MKV container allows content creators to package multiple narrative paths, such as alternate endings, director's cuts, or interactive storylines, within a single file or across linked files without duplicating media streams.

The Chapter Hierarchy and EditionEntry

The MKV chapter system is structured hierarchically under the root Chapters element. Inside, content is organized into one or more EditionEntry master elements. Each EditionEntry represents an independent, complete version or timeline of the media.

Within every EditionEntry, the key metadata elements include:

  • EditionUID: A unique 64-bit unsigned integer that identifies that specific narrative path or edition.
  • EditionFlagOrdered: A 1-bit boolean flag. When set to 1, it signals to the media player that the edition is an "Ordered Chapter" set, meaning the player must construct a virtual timeline strictly following the defined sequence of chapter segments rather than playing the file linearly from start to finish.
  • EditionFlagDefault: Specifies which EditionUID the player should load automatically if the user makes no selection.
  • EditionFlagHidden: Flags whether the edition should be exposed in standard player menus (useful for internal branching logic).

Defining Narrative Paths with Chapter Atoms

Each EditionEntry contains a sequence of ChapterAtom elements that construct the timeline for that specific EditionUID.

  1. Virtual Splicing: Each ChapterAtom specifies a ChapterTimeStart and ChapterTimeEnd. In an ordered edition, the player plays only the designated time ranges in sequence, seamlessly jumping over unreferenced sections of the video file.
  2. Timeline Assembly: For branching media contained within a single file, two different editions (e.g., EditionUID: 1001 for the Theatrical Cut and EditionUID: 1002 for the Alternate Ending Cut) will share the initial identical ChapterAtom segments. At the branch point, EditionUID: 1001 directs the player to timestamp block A, while EditionUID: 1002 directs playback to timestamp block B.

Multi-File Branching via Segment Linking

For complex branching media where branch assets are stored in separate MKV files to optimize distribution, the container uses EBML segment linking:

  • ChapterSegmentUID: Stored inside a ChapterAtom, this 128-bit binary UID references an external Matroska file's SegmentUID.
  • ChapterSegmentEditionUID: Points to a specific EditionUID inside the targeted external segment.

When the playback engine reaches a ChapterAtom configured with an external ChapterSegmentUID, it pauses the current stream, opens the referenced MKV segment, reads the specified ChapterSegmentEditionUID, and renders the external audio/video seamlessly before returning to the parent timeline.

Player Parsing and Execution

When a compatible player opens an MKV file containing branching media:

  1. It parses the Chapters master tag and enumerates all EditionEntry elements.
  2. It reads each EditionUID and any associated localized strings in ChapterDisplay (e.g., "Narrative Path A", "Director's Cut").
  3. Once an edition is selected, the playback engine builds an internal seek table corresponding solely to the ChapterAtom sequence listed under that specific EditionUID.
  4. During playback, the player utilizes the chapter timecodes to execute gapless seeks across internal tracks or external segment links, delivering a continuous viewing experience tailored to the chosen storyline.
