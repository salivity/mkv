Can MKV Store ProRes and DNxHD for Editing?

The Matroska (MKV) container can technically store intermediate codecs like Apple ProRes and Avid DNxHD, but it is rarely utilized for post-production editing. While MKV's flexible, open-standard architecture allows it to wrap almost any video stream, professional non-linear editing systems (NLEs) are built around QuickTime (MOV) and Material Exchange Format (MXF) containers. Consequently, using MKV for ProRes or DNxHD often causes software compatibility and workflow issues during the editing process.

Technical Feasibility vs. Workflow Reality

From a purely technical standpoint, the MKV specification supports wrapping both ProRes and DNxHD/DNxHR streams. Open-source encoding tools like FFmpeg can easily multiplex these intermediate codecs into an .mkv file.

However, post-production workflows depend heavily on software integration. Intermediate codecs are designed to preserve maximum image quality and provide smooth timeline scrubbing during active editing. Wrapping these codecs in an MKV file creates a mismatch between standard video codecs and typical editor expectations.

NLE Compatibility Issues

Most professional editing software lacks native, robust support for MKV containers carrying editing codecs:

  • DaVinci Resolve: Historically lacks native decoding support for MKV files, requiring users to transcode or remux files before importing.
  • Adobe Premiere Pro: Provides limited native MKV support, often leading to playback stutter, missing audio tracks, or import errors with non-standard codec combinations.
  • Apple Final Cut Pro: Does not support the MKV container natively, requiring all footage to be wrapped in .mov or supported broadcast formats.
  • Avid Media Composer: Strictly requires DNxHD/DNxHR and ProRes to be housed in either .mov or .mxf containers via Avid Media Access (AMA).

Industry Standard Containers for Intermediate Codecs

To ensure seamless timeline playback, color grading, and audio synchronization, post-production facilities standardize on two primary containers:

  1. QuickTime (.mov): The primary and native container for Apple ProRes, also widely used for DNxHD. It offers universal support across macOS and Windows editing platforms.
  2. Material Exchange Format (.mxf): The professional broadcast standard, specifically the OP1a or Avid-native OP-Atom variants, ideal for DNxHD, DNxHR, and broadcast-ready ProRes delivery.

Solution: Remuxing Instead of Transcoding

If you receive ProRes or DNxHD footage wrapped inside an MKV container, you do not need to perform a lossy or time-consuming transcode. Because the underlying video stream is already an editing codec, you can simply "remux" (stream copy) the video from the MKV container into an MOV or MXF container without any loss in image quality.

Using FFmpeg, a fast remux command looks like this:

ffmpeg -i input.mkv -c copy output.mov

This process instantly updates the container to a post-production-friendly format while keeping the original ProRes or DNxHD stream intact.
