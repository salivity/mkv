How MKV Stores Dolby Vision Dynamic Metadata

This article explains how the Matroska (MKV) container encapsulates and delivers Dolby Vision dynamic metadata for frame-by-frame tone mapping. It covers the role of the Reference Processing Unit (RPU), how metadata is embedded within elementary video streams as Network Abstraction Layer (NAL) units, and how MKV container-level signaling allows media players and decoders to extract and apply dynamic HDR instructions seamlessly.

The Role of the Reference Processing Unit (RPU)

Unlike static HDR formats like HDR10—which apply a single set of brightness parameters across an entire video—Dolby Vision utilizes dynamic tone mapping to adjust brightness, contrast, and color balance scene-by-scene or frame-by-frame. The instructional data that drives this process is packaged into a data structure called the Reference Processing Unit (RPU).

The RPU contains all Dolby Vision dynamic metadata, including:

  • Content-dependent metadata (trim passes, minimum/maximum/mid-point luminance targets).
  • Color-remapping coefficients (polynomial and look-up table parameters for dual-layer enhancements).
  • Display mastering properties.

Bitstream-Level Storage via NAL Units

The MKV container does not store Dolby Vision dynamic metadata in a separate proprietary metadata track. Instead, MKV preserves the metadata embedded directly inside the elementary video bitstream (typically HEVC/H.265 or AVC/H.264).

  1. NAL Unit Encapsulation: In an HEVC stream, the Dolby Vision RPU is wrapped inside an ITU-T / ISO standard Network Abstraction Layer (NAL) unit. Specifically, Dolby Vision designates specific NAL unit types (such as Unspecified NAL unit type 62 or Prefix SEI messages) to carry the binary RPU payload.
  2. Access Unit Ordering: The RPU NAL unit is placed immediately before the slice data NAL units for the corresponding video frame within each Access Unit (AU).
  3. Block Preservation: When MKV muxers (such as MKVToolNix) package the video, each frame's Access Unit—including its slice data, parameter sets, and RPU NAL units—is placed inside standard Matroska SimpleBlock or BlockGroup structures without stripping the Dolby Vision NAL units.

Container-Level Signaling

To ensure hardware and software decoders recognize that the video stream contains Dolby Vision data, the MKV specification utilizes specific track-level elements:

  • CodecID: The video stream is typically identified with standard identifiers such as V_MPEGH/ISO/HEVC.
  • Dolby Vision Configuration Record (dvcC / dvvC): Placed within the Matroska CodecPrivate data, this descriptor explicitly signals the Dolby Vision profile (e.g., Profile 5, Profile 7, Profile 8.1), compatibility level, and whether the stream uses standard HDR10 or HLG as a fallback base layer.
  • Colour Header Elements: Standard Matroska elements—such as ColourPrimaries, TransferCharacteristics, and MatrixCoefficients—provide the baseline signaling (e.g., BT.2020 and SMPTE ST 2084/PQ) required if a non-Dolby Vision decoder falls back to standard HDR10.

Handling Single-Layer vs. Dual-Layer Profiles

Dolby Vision profiles vary based on delivery formats:

  • Single-Layer Streams (Profiles 5 and 8.1): The single HEVC stream contains both the base image and the RPU NAL units. In Profile 8.1, the video uses standard HDR10 encoding, allowing players that lack Dolby Vision support to ignore the RPU NAL units and output standard HDR10.
  • Dual-Layer Streams (Profile 7): Originally found on Ultra HD Blu-ray discs as two separate video tracks (a Base Layer and an Enhancement Layer), MKV tools can interleave both layers into a single track inside the MKV container. The Base Layer, Enhancement Layer (FEL or MEL), and RPU NAL units are merged sequentially into single Access Units inside the MKV SimpleBlock elements, preserving synchronization between the layers and the dynamic metadata.

How Demuxers and Decoders Process the Metadata

When a compatible player opens the MKV file:

  1. The demuxer reads the CodecPrivate block to verify Dolby Vision compatibility.
  2. The demuxer passes the raw HEVC Access Units to the video decoder.
  3. The decoder separates the video frame slices from the RPU NAL unit.
  4. The decoded base image and the raw RPU metadata are passed to the Dolby Vision display management engine, which performs dynamic tone mapping mapped precisely to the target display's peak brightness and color volume.
