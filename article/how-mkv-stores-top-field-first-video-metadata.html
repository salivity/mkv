How MKV Stores Top-Field-First Video Metadata

This article explains how the Matroska (MKV) multimedia container defines and stores field order metadata for interlaced video streams, specifically for top-field-first (TFF) content. It covers the underlying Extensible Binary Meta Language (EBML) structure, the dedicated video track elements used to signal interlacing, and how media players interpret this container-level information to ensure correct frame rendering.

The Matroska Track Structure

Matroska uses an EBML architecture organized into hierarchical elements. All track configuration data resides within the Tracks master element, which contains individual TrackEntry elements for every audio, video, or subtitle stream in the file.

For a video track, properties such as resolution, frame rate, and scanning format are contained inside the child Video master element (EBML ID: 0xE0).

Segment (0x18538067)
└── Tracks (0x1654AE6B)
    └── TrackEntry (0xAE)
        └── Video (0xE0)
            ├── FlagInterlaced (0x9A)
            └── FieldOrder (0x9D)

EBML Elements for Top-Field-First Signaling

To define a video as interlaced with a top-field-first orientation, the MKV specification utilizes two specific EBML elements within the Video track settings:

  1. FlagInterlaced (EBML ID 0x9A) This element informs the demuxer whether the video stream is progressive or interlaced.
    • Value 1: Indicates an interlaced stream.
    • Value 2: Indicates a progressive stream.
    • Value 0: Unspecified.
  2. FieldOrder (EBML ID 0x9D) When FlagInterlaced is set to 1, the FieldOrder element dictates the temporal and spatial order of the interlaced fields.
    • Value 1 (Top Field First): Specifies that the top field (the even-numbered scan lines) represents the earliest temporal moment and should be displayed first, with the top field stored first in the bitstream.

Other values for FieldOrder include 0 (Progressive/Unspecified), 2 (Undetermined interlacing), 6 (Bottom Field First), 9 (Bottom field displayed first, top field stored first), and 14 (Top field displayed first, bottom field stored first). For standard top-field-first video, the value is set explicitly to 1.

Container-Level vs. Codec Bitstream Metadata

Interlaced video formats—such as MPEG-2, H.264/AVC, and H.265/HEVC—often contain field order parameters embedded directly inside their elementary bitstream headers (for example, within Picture Timing SEI messages or Sequence Parameter Sets in H.264).

However, setting the FieldOrder to 1 at the MKV container level allows demuxers, hardware decoders, and playback software to determine the field parity immediately without parsing the raw compressed video packets. If a conflict occurs between the container metadata and the bitstream metadata, most compliant media frameworks prioritize the container-level FieldOrder flag to guide deinterlacing filters and video renderers.
