Can MKV Store Uncompressed RGB Video Data?

The Matroska (MKV) multimedia container fully supports uncompressed RGB video data, making it an excellent open-standard format for scientific recording. This article explains how MKV handles uncompressed video streams, its support for high bit depths and arbitrary frame rates, the technical mechanisms involved, and its practical advantages for scientific research.

MKV Support for Uncompressed RGB

The Matroska container specification is codec-agnostic, meaning it does not enforce video compression. It natively supports raw, uncompressed video frames via the standard V_UNCOMPRESSED codec identifier, as well as legacy FourCC definitions (such as rawvideo, RGB, RGBA, and BGR) encapsulated through Video for Windows (VFW) compatibility mode.

When uncompressed RGB frames are stored inside MKV, every pixel payload from the camera sensor is preserved byte-for-byte without quantization, spatial compression, or color subsampling.

Key Features for Scientific Recording

MKV offers several structural features that are critical for scientific measurement, computer vision, and instrumentation:

  • High Bit-Depth Support: Beyond standard 8-bit per channel RGB (RGB24), MKV can contain 10-bit, 12-bit, 14-bit, and 16-bit per channel RGB (such as RGB48 or planar RGB formats). This accommodates high-dynamic-range scientific cameras and spectrometers.
  • Nanosecond-Precision Timestamps: Matroska tracks timing using integer nanosecond timecodes for each frame. This enables precise temporal synchronization across multiple cameras, sensors, and external trigger inputs.
  • Variable Frame Rates (VFR): Scientific experiments often use triggered acquisition where exposure intervals fluctuate. MKV handles non-standard and fluctuating frame rates natively without requiring duplicate dummy frames.
  • Custom Metadata Tracks: MKV can mux arbitrary data alongside the video stream. Researchers can embed synchronous telemetry, sensor readings, GPS data, or experiment parameters into separate subtitle or binary attachment tracks.
  • No File Size Limits: Unlike standard AVI (which has a 2GB/4GB limit without OpenDML extensions) or older formats, 64-bit Matroska structures support massive continuous recordings spanning hundreds of gigabytes or terabytes.

Creating Uncompressed RGB MKV Files

Uncompressed RGB MKV files can be generated using standard scientific processing tools and libraries such as FFmpeg, OpenCV, or custom C/C++ implementations via libmatroska.

Using FFmpeg, a raw RGB frame sequence or direct camera stream can be packaged without re-encoding:

ffmpeg -f rawvideo -pixel_format rgb24 -video_size 1920x1080 -framerate 60 -i input.raw -c:v rawvideo -pix_fmt rgb24 output.mkv

For 16-bit-per-channel data:

ffmpeg -f rawvideo -pixel_format rgb48le -video_size 1920x1080 -framerate 60 -i input.raw -c:v rawvideo -pix_fmt rgb48le output.mkv

Lossless Compression Alternative: FFV1 in MKV

While raw RGB can be stored directly, uncompressed video requires exceptionally high disk write speeds (e.g., 1080p60 8-bit RGB requires approximately 373 MB/s).

If storage bandwidth becomes a bottleneck during recording, the MKV container also supports FFV1, an open-source, mathematically lossless intra-frame/inter-frame video codec widely recognized in archival and scientific communities. FFV1 supports full RGB color spaces at up to 16 bits per channel while reducing data footprint by roughly 30% to 50% without altering a single pixel value.
