What Is CueBlockNumber in MKV Cue Points?

The CueBlockNumber element inside a Matroska (MKV) cue point identifies the specific sequential block within a cluster that corresponds to a given timestamp. By providing the exact block index of a target frame, typically a keyframe, this element helps media players and demuxers optimize seeking operations and access specific video or audio samples without parsing the entire cluster from the beginning.

In the Matroska container format, seeking is managed through an index structure known as Cues. The Cues element contains multiple CuePoint entries, each marking a specific point in playback time. Within each cue point, CueTrackPositions defines where the media data for a particular track resides.

Inside CueTrackPositions, several elements work together to pinpoint data:

  • CueTrack: Specifies the track number.
  • CueClusterPosition: Indicates the byte offset of the cluster containing the target data.
  • CueRelativePosition: Provides the byte offset of the target block relative to the start of the cluster.
  • CueBlockNumber: Specifies the sequential number (1-based) of the block within that cluster.

When a media player seeks to a specific timestamp, it uses the cue point to find the exact byte position of the target cluster via CueClusterPosition. Once the cluster is located, the player must locate the relevant SimpleBlock or BlockGroup.

Without CueBlockNumber or CueRelativePosition, a demuxer must read and parse every block header from the start of the cluster sequentially until it encounters the target timestamp. When CueBlockNumber is present, the demuxer can simply count the blocks as it parses, immediately knowing when it has arrived at the indexed block.

While CueBlockNumber is an optional element in the Matroska specification, its primary function is reducing parser overhead, improving seeking performance, and ensuring precise frame retrieval during playback and editing.
