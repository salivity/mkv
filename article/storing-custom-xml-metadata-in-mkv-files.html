Storing Custom XML Metadata in MKV Files

The Matroska (MKV) multimedia container fully supports custom XML tags designed to hold extended production metadata. Because the Matroska specification is built on Extensible Binary Meta Language (EBML), it provides a flexible, standardized tagging system that allows creators, archivists, and post-production teams to embed deep structural, technical, and contextual details directly into the container without altering the underlying audio or video streams.

Matroska’s Tagging System

Matroska uses a hierarchical metadata structure defined by XML-compliant tagging specifications. Unlike simpler container formats that limit metadata to basic fields such as title, artist, or year, Matroska allows for nested tag structures that can be targeted at different levels of the file hierarchy, including the entire collection, specific chapters, tracks, or segments.

The core components of the Matroska tag specification include:

  • <Targets>: Specifies the exact element to which the metadata applies (e.g., whole file, track, or chapter) using numeric target levels.
  • <SimpleTag>: Contains the actual metadata key-value pairs via <TagName> and <TagString> elements.
  • Nested <SimpleTag>: Enables parent-child relationships, allowing for complex, structured data sets.

Embedding Extended Production Metadata

You can store extended production details by defining custom tag names within the <SimpleTag> structure or by using official Matroska tag definitions for production data. Examples of custom production metadata you can include are:

  • Shooting Details: Camera model, lens serial number, focal length, ISO, shutter angle, and white balance settings.
  • Post-Production Data: Color space, applied Look-Up Tables (LUTs), mastering display information, and software versions.
  • Administrative Metadata: Production company, copyright registration numbers, ISAN identifiers, and licensing terms.
  • Technical Identifiers: Extended timecodes, reel identifiers, and audio channel mapping schemes.

Example XML Structure

To attach custom metadata, create an XML file following Matroska's schema:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Tags SYSTEM "matroskatags.dtd">
<Tags>
  <Tag>
    <Targets>
      <TargetTypeValue>50</TargetTypeValue>
    </Targets>
    <SimpleTag>
      <TagName>PRODUCTION_STUDIO</TagName>
      <TagString>Example Post Works</TagString>
    </SimpleTag>
    <SimpleTag>
      <TagName>CAMERA_MODEL</TagName>
      <TagString>Cinema Camera 6K</TagString>
    </SimpleTag>
    <SimpleTag>
      <TagName>CUSTOM_LUT</TagName>
      <TagString>Rec709_FilmPrint_Emulation_v2</TagString>
    </SimpleTag>
  </Tag>
</Tags>

Tools for Injecting XML Tags

The standard utility for working with Matroska metadata is the open-source suite MKVToolNix.

  • mkvpropedit: Allows you to inject or update XML tags in an existing MKV file instantly without remuxing or re-encoding the media:

    mkvpropedit input.mkv --tags all:metadata.xml

  • mkvmerge: Allows you to attach the XML metadata file during the initial multiplexing process using the --global-tags or --tags flags.

While consumer media players often display only basic tags (such as title or track language), custom and extended production tags remain fully preserved inside the MKV container, making them accessible to any script, digital asset management (DAM) system, or tool capable of parsing EBML or Matroska XML data.
