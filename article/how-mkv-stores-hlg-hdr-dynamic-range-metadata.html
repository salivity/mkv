How MKV Stores HLG HDR Dynamic Range Metadata

This article explains how the Matroska (MKV) multimedia container format encapsulates and stores metadata for Hybrid Log-Gamma (HLG) High Dynamic Range (HDR) video. It covers the container-level Extensible Binary Meta Language (EBML) elements responsible for signaling color properties, the standardized parameter values required for HLG, and how these container tags interact with the underlying video bitstream.

The Matroska Colour Element Structure

Matroska organizes multimedia tracks using an EBML tree hierarchy. Dynamic range and colorimetry information are stored within the track headers under the following path:

Segment ➔ Tracks ➔ TrackEntry ➔ Video ➔ Colour

The Colour element acts as a centralized container for video signal parameters, allowing media splitters, decoders, and display pipelines to identify color reproduction requirements without needing to decode the primary video stream first.

Key Parameter Values for HLG

To signal HLG HDR content accurately, MKV uses standardized numerical identifiers that correspond directly to ITU-T H.273, ISO/IEC 23001-8, and ITU-R BT.2100 specifications. The essential sub-elements configured within the Colour block include:

  • TransferCharacteristics (EBML ID: 0x55BA): This is the definitive parameter for signaling HLG. It is set to the integer value 18, which identifies the transfer function as ARIB STD-B67 (the standardized optical-electro transfer function for Hybrid Log-Gamma).
  • MatrixCoefficients (EBML ID: 0x55B1): Typically set to 9 (ITU-R BT.2020 non-constant luminance system) to define how color difference channels are derived from RGB components.
  • Primaries (EBML ID: 0x55BB): Set to 9 (ITU-R BT.2020), defining the wide color gamut chromaticity coordinates for red, green, and blue primaries alongside the D65 white point.
  • Range (EBML ID: 0x55B9): Usually set to 1 for standard broadcast/limited range (quantization range of 64–940 in 10-bit), or 2 for full range.
  • BitsPerChannel (EBML ID: 0x55B2): Typically set to 10, reflecting the standard 10-bit precision used for HLG distribution.

Handling of Mastering and Dynamic Metadata

Unlike HDR10 or HDR10+, which rely heavily on static mastering display color volume (MDCV), content light level (CLL) metadata, or dynamic frame-by-frame metadata, HLG is a scene-referred system designed to be natively compatible with both SDR and HDR displays without mandatory metadata.

However, if mastering display parameters or nominal peak luminance descriptors are provided, Matroska can store them inside optional child elements within the Colour tree:

  • MasteringMetadata: Contains coordinates for display primaries and white point (PrimaryRChromaticityX, WhitePointChromaticityY, etc.).
  • LuminanceMax and LuminanceMin: Define the peak and black-level mastering luminance in candelas per square meter (nits).

Bitstream and Container Synchronization

In standard workflows (such as HEVC/H.265 or AV1 encoding), HLG transfer characteristics are already embedded directly within the codec bitstream's Video Usability Information (VUI) or Supplemental Enhancement Information (SEI) messages.

MKV replicates these properties at the container level to streamline playback initialization. When a playback system loads the file, the demuxer reads the MKV Colour headers immediately to configure the display pipeline, hardware overlay, or operating system HDR mode before frame decoding begins. If a discrepancy exists, compliant renderers typically prioritize the container-level signaling or synchronize it directly with the verified bitstream VUI parameters.
