How MKV Stores 360 Video Projection Metadata

Matroska (MKV) containers store 360-degree video projection metadata directly inside the video track headers using standardized elements defined in the Matroska and WebM specifications. This metadata informs media players that a flat, two-dimensional video stream represents a spherical panoramic scene and instructs the rendering engine on how to map the pixels onto a 3D sphere for interactive viewing.

The Projection Master Element

In the Matroska EBML (Extensible Binary Meta Language) structure, projection data is embedded within the track-level information. Specifically, it resides inside the TrackEntry element under the Video settings block:

Segment ➔ Tracks ➔ TrackEntry ➔ Video ➔ Projection

The Projection master element (EBML ID: 0x7670) contains all parameters required to interpret the geometric layout of the video frames.

Key Sub-Elements for Equirectangular Video

When encoding standard 360-degree spherical video, several specific child elements are written into the Projection block:

  • ProjectionType (0x7671): An integer specifying the projection method. For equirectangular video, this value is set to 1 (Equirectangular). A value of 0 denotes standard rectangular video, 2 denotes cubemap, and 3 denotes custom mesh projections.
  • ProjectionPoseYaw (0x7674): A float value representing the initial yaw rotation in degrees (ranging from -180.0 to 180.0). This defines the horizontal center of the viewing perspective.
  • ProjectionPosePitch (0x7675): A float value representing the initial pitch rotation in degrees (ranging from -90.0 to 90.0), defining the vertical tilt of the camera.
  • ProjectionPoseRoll (0x7676): A float value representing the initial roll rotation in degrees (ranging from -180.0 to 180.0), compensating for camera horizon tilt.
  • ProjectionData (0x7672): An optional binary element used to store private projection data or boundary configurations, typically utilized when dealing with cropped equirectangular frames or specific field-of-view limits.

Playback and Rendering Pipeline

  1. Header Parsing: When an MKV file is opened, the demuxer inspects the Video track descriptors before decoding video frames.
  2. Mode Detection: Detecting a ProjectionType value of 1 alerts the player to switch from a flat 2D viewport to a 3D spherical rendering canvas.
  3. Texture Mapping: The video decoder outputs the standard 2:1 aspect ratio equirectangular frame. The rendering engine applies this frame as an inverse-mapped texture onto an internal 3D sphere using standard latitude-longitude (UV) coordinates.
  4. Orientation Correction: The rendering engine applies the ProjectionPoseYaw, ProjectionPosePitch, and ProjectionPoseRoll offsets to align the default camera view to the intended focal point of the scene.
