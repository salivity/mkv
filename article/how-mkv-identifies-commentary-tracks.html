How MKV Identifies Commentary Tracks

The Matroska (MKV) container format identifies tracks intended for commentary or director notes through a combination of dedicated structural flags, track naming metadata, and standardized tagging systems. Built on Extensible Binary Meta Language (EBML), MKV allows multiplexers to explicitly flag the role and nature of any audio or subtitle stream so that media players can recognize and categorize commentary tracks automatically.

The FlagCommentary Element

In modern Matroska specifications, the primary method for identifying commentary is the FlagCommentary element (EBML ID 0x55EE).

  • Located within the TrackEntry master element alongside standard track properties.
  • Set as a boolean value: 1 indicates the track contains commentary, while 0 (default) indicates standard content.
  • Applicable to both audio tracks (e.g., director or cast audio commentary) and subtitle tracks (e.g., trivia subtitles or production notes).

When FlagCommentary is active, compliant media players know not to select the stream as the default primary audio or subtitle track, preventing commentary from playing unintentionally during normal playback.

The Track Name Element (Name)

Before FlagCommentary was standardized, and still widely used for backward compatibility, the Name element (0x536E) provided the primary way to designate commentary.

  • Contains a human-readable UTF-8 string, such as "Director's Commentary by Jane Doe" or "Cast Commentary."
  • Displayed directly in the media player's audio/subtitle selection menu.
  • Many software players and media servers use string-matching heuristics on the Name tag to automatically categorize tracks as commentary if modern flags are absent.

Matroska Tagging System

MKV also features a nested tagging infrastructure (Tags element) to store richer commentary metadata:

  • Targetting TrackUID: Tags can be mapped directly to a specific track's unique identifier (TrackUID).
  • COMMENTARY Tag: Advanced tags can define key-value pairs specifying the nature of the commentary, the commentators involved, and recording details.
  • TITLE or DESCRIPTION: Used to provide extended descriptions of what a particular commentary track covers throughout the film or episode.

Media Player Behavior

Modern media players (such as VLC, MPC-HC, and mpv) evaluate these elements hierarchically:

  1. They check for the FlagCommentary header to categorize the track type and adjust default playback rules.
  2. They read the Name and Language (LanguageIETF / 0x22B59D) tags to display the track properly in audio selection menus.
  3. They use tag metadata to provide full details in track information panels.
