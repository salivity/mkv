Can MKV Store Raw Video Without Overhead?

This article explores whether the Matroska (MKV) container can encapsulate raw elementary video streams without adding container overhead. While MKV is flexible enough to store virtually any raw, uncompressed, or compressed elementary video stream, it is technically impossible to encapsulate data inside an MKV file with zero container overhead due to the structural requirements of the format.

The Matroska format is built upon EBML (Extensible Binary Meta Language), a binary equivalent of XML. To store an elementary video stream—such as raw H.264, HEVC, AV1, or uncompressed YUV video—the data must be packaged into the EBML hierarchical structure. This process requires dividing the continuous stream into discrete packets, which are then wrapped inside specific MKV data elements.

Every MKV file requires a set of mandatory structural metadata elements. These include:

  • EBML Header: Identifies the file type, EBML version, and read compatibility.
  • Segment Header: Declares the master container for all multimedia data.
  • Track Information: Specifies track numbers, codec IDs, video resolution, color space, and frame rates.
  • Clusters and Blocks: Raw frame data is stored inside SimpleBlock or BlockGroup elements within Cluster structures. Each block introduces bytes for track identification, relative timestamps, and flags (such as keyframe markers).
  • Indexes and Cues (Optional but common): Metadata that enables seeking and navigation throughout the file.

Because each video frame must be encapsulated inside an individual Block with its own timestamp and overhead flags, the MKV container inherently adds extra bytes to the original elementary stream. An elementary stream by itself contains only the codec-level bitstream (such as NAL units in H.264), whereas an MKV file wraps that stream with synchronization and container metadata.

Although zero overhead is structurally impossible in MKV, the overhead generated by the Matroska container is generally negligible. For standard video files, the EBML tags, cluster headers, and block framing typically account for less than 1% of the total file size.
