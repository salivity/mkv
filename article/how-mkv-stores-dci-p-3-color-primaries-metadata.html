How MKV Stores DCI-P3 Color Primaries Metadata

This article explains how the Matroska (MKV) container format defines and stores custom color primaries metadata for video mastered in the DCI-P3 color space. It covers the hierarchical structure of the Matroska Colour element, the use of standard primary enumeration values, and the integration of explicit chromaticity coordinates inside the MasteringMetadata block to ensure accurate wide color gamut reproduction.

The Matroska Color Metadata Hierarchy

Matroska defines color properties at the container level within its standard EBML (Extensible Binary Meta Language) tree structure. Color information is placed inside the track header rather than relying solely on the underlying video bitstream. The hierarchy follows this path:

Segment
└── Tracks
    └── TrackEntry
        └── Video
            └── Colour

The Colour element contains sub-elements that define the transfer characteristics, matrix coefficients, color range, and color primaries of the video track.

Predefined DCI-P3 Primaries Enumeration

For standard implementations of the DCI-P3 color space, the MKV container provides the Primaries element (EBML ID 0x55BB). This element takes an unsigned integer corresponding to ITU-T H.273 / ISO/IEC 23091-2 values:

  • Value 11 (SMPTE RP 431-2): Standard DCI-P3 with the theater DCI white point (\(x = 0.314, y = 0.351\)).
  • Value 12 (SMPTE EG 432-1): Display P3 (DCI-P3 primaries with a standard D65 white point: \(x = 0.3127, y = 0.3290\)).

Setting these values informs the demuxer and player of the base color space without requiring raw video bitstream decoding.

Storing Custom Coordinates with MasteringMetadata

When a video uses a custom DCI-P3 calibration profile or requires precise mastering display parameters (common in HDR and wide color gamut workflows), MKV uses the MasteringMetadata container (EBML ID 0x55D0) inside the Colour element.

Custom color primaries and white points are stored as floating-point CIE 1931 \((x, y)\) chromaticity coordinates using the following specific elements:

  • PrimaryRChromaticityX / PrimaryRChromaticityY: Defines the red primary coordinate (standard DCI-P3 uses \(x = 0.680, y = 0.320\)).
  • PrimaryGChromaticityX / PrimaryGChromaticityY: Defines the green primary coordinate (standard DCI-P3 uses \(x = 0.265, y = 0.690\)).
  • PrimaryBChromaticityX / PrimaryBChromaticityY: Defines the blue primary coordinate (standard DCI-P3 uses \(x = 0.150, y = 0.060\)).
  • WhitePointChromaticityX / WhitePointChromaticityY: Defines the custom mastering display white point.

These elements accept exact floating-point values, allowing mastering facilities to signal non-standard or calibrated variations of P3 primaries directly at the container level.

Container and Bitstream Synchronization

In standard encoding pipelines (such as HEVC or AV1), color metadata is also embedded directly inside the video elementary stream via Video Usability Information (VUI) and Mastering Display Colour Volume Supplemental Enhancement Information (SEI) messages.

MKV preserves this data inside the codec bitstream while simultaneously exposing the coordinates in the container headers. This redundancy allows media players, renderers, and display pipelines to configure display color management, tone mapping, and gamut conversion immediately upon demuxing.
