Batch Transcoding MKV Files with CLI Tools

Automating the transcoding of large directories of MKV files requires combining command-line tools like FFmpeg or HandBrakeCLI with shell scripting or task runners. This article explores how automated pipelines traverse nested directories, execute parallel encoding tasks, leverage hardware acceleration, handle multi-track MKV streams, and implement robust error handling to process high-volume video libraries efficiently.

Core Command-Line Utilities

Modern video transcoding pipelines primarily rely on two command-line utilities:

  • FFmpeg: The industry-standard framework providing granular control over demuxing, decoding, filtering, encoding, and muxing. It supports virtually every video and audio codec and handles complex multi-stream mapping.
  • HandBrakeCLI: A high-level CLI wrapper optimized for standard consumer distribution presets, offering simplified parameter tuning for common formats like MP4 and MKV using x264, x265, and AV1 encoders.

Directory Traversal and Scripting Strategies

To process files across complex folder hierarchies, pipelines employ recursive file discovery methods.

1. Sequential Processing via Shell Scripts

A basic pipeline uses a standard shell loop to find and process files sequentially. In a Linux/macOS environment using Bash:

#!/usr/bin/env bash
INPUT_DIR="/path/to/source"
OUTPUT_DIR="/path/to/output"

find "$INPUT_DIR" -type f -name "*.mkv" | while read -r input_file; do
    # Replicate directory structure
    rel_path="${input_file#$INPUT_DIR/}"
    target_path="$OUTPUT_DIR/${rel_path%.mkv}.mp4"
    mkdir -p "$(dirname "$target_path")"

    # Execute transcoding
    ffmpeg -nostdin -y -i "$input_file" \
        -c:v libx264 -crf 22 -preset medium \
        -c:a aac -b:a 192k \
        "$target_path"
done

2. Parallel Processing with GNU Parallel

When working with multi-core CPUs or distributed workers, sequential processing underutilizes system resources. GNU Parallel allows concurrent execution of multiple FFmpeg instances:

find /path/to/source -type f -name "*.mkv" | \
parallel --jobs 4 --bar ffmpeg -nostdin -y -i {} \
    -c:v libx265 -crf 24 -preset fast \
    -c:a copy \
    /path/to/output/{/.}.mp4

This command automatically schedules four concurrent tasks, dynamically assigning jobs as worker threads complete.

Stream Mapping and Container Handling

MKV (Matroska) files frequently contain multiple audio tracks (commentary, foreign languages) and subtitle streams (PGS, SRT, ASS). A production pipeline must account for stream management:

  • Preserving All Streams: Using -map 0 forces FFmpeg to include all video, audio, and subtitle streams from the input file rather than default single-stream selection.
  • Audio/Subtitle Passthrough: Use -c:a copy or -c:s copy to avoid re-encoding non-video streams, reducing processing time and preserving quality.
  • Subtitle Compatibility: If converting from MKV to MP4, bitmap subtitles (e.g., PGS) must either be burned in (-filter_complex "subtitles=...") or stripped, as MP4 native containers do not support them.
ffmpeg -i input.mkv \
    -map 0:v:0 -map 0:a -map 0:s? \
    -c:v libx264 -crf 20 \
    -c:a aac -b:a 256k \
    -c:s copy \
    output.mkv

Hardware Acceleration

For large directories containing thousands of high-bitrate files, CPU-based software encoding (libx264/libx265) can be bottlenecked by compute limits. Pipelines integrate dedicated hardware encoders to achieve faster-than-realtime throughput:

  • NVIDIA NVENC: -c:v hevc_nvenc -preset p4 -cq 26
  • Intel QuickSync (QSV): -c:v hevc_qsv -global_quality 24
  • Apple VideoToolbox: -c:v hevc_videotoolbox -q:v 60

Hardware encoders offload rendering tasks to dedicated silicon, enabling higher concurrent job counts per server node.

Error Handling, Verification, and Safety

Robust batch pipelines implement safeguards to prevent data corruption and incomplete jobs:

  1. Atomic File Writes: Output video to a temporary extension (e.g., .tmp.mp4) and rename it to the final destination name only after the process exits with code 0.
  2. Integrity Validation: Run a secondary verification step using ffmpeg -v error -i target_path.mp4 -f null - to verify frame integrity before deleting or archiving source MKV files.
  3. Process Logging: Redirect standard error (2> encoding.log) per file to retain diagnostics for failed encodes without polluting standard terminal outputs.
