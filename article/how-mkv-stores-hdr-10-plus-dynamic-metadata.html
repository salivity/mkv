How MKV Stores HDR10 Plus Dynamic Metadata

MKV (Matroska) stores HDR10+ dynamic parameters directly within the elementary video bitstream rather than in the container’s high-level track headers. While static HDR10 metadata can be stored in the Matroska container's native Colour elements, the frame-by-frame dynamic metadata required for HDR10+ (SMPTE ST 2094-40) is embedded inside the video codec layer as ITU-T T.35 Supplemental Enhancement Information (SEI) messages for HEVC or Metadata Open Bitstream Units (OBUs) for AV1.

Static vs. Dynamic Metadata in Matroska

To understand how HDR10+ works in MKV, it is essential to distinguish between static and dynamic metadata:

  • Static Metadata (HDR10): Fixed values—such as Mastering Display Color Volume (MDCV) and Content Light Level (CLL/MaxFALL/MaxCLL)—apply to the entire video. The Matroska specification natively supports these in the Track/Video/Colour container elements (MasteringMetadata, MaxCLL, MaxFALL).
  • Dynamic Metadata (HDR10+): Scene-by-scene or frame-by-frame luminance adjustments defined by SMPTE ST 2094-40. Because these values change continuously, storing them in static container-level headers is insufficient.

Bitstream-Level Integration (ITU-T T.35)

Because the Matroska format does not define per-frame container tags for dynamic metadata, HDR10+ relies on the underlying video compression standard:

  1. HEVC (H.265) Streams: HDR10+ metadata is packed into "User Data Registered by ITU-T Recommendation T.35" SEI NAL (Network Abstraction Layer) units.
    • The SEI message contains a specific country code (0xB5 for the United States) and terminal provider code assigned to SMPTE ST 2094-40 (Application Identifier 4).
    • These SEI messages precede the video slice data for the corresponding frames, ensuring synchronized rendering.
  2. AV1 Streams: In AV1 video tracks, HDR10+ parameters are encapsulated within METADATA_TYPE_HDR_PLUS Metadata OBUs, which also carry the ITU-T T.35 payload defining the ST 2094-40 dynamic curves.

The Role of the MKV Container

The MKV container acts as a transparent carrier:

  • Block Encapsulation: The video packets containing the SEI NAL units or OBUs are packaged into standard Matroska SimpleBlock or Block structures without modification.
  • Demuxing and Decoding: When an MKV demuxer reads the file, it passes the raw video packets—including the embedded HDR10+ SEI data—directly to the video decoder.
  • Display Mapping: The video decoder or tone-mapping processor parses the T.35 metadata from the decoded frames and dynamically adjusts brightness and contrast according to the target display's capabilities.
