How MKV Stores HDR Maximum Luminance Values

High Dynamic Range (HDR) video relies on mastering display metadata to ensure playback devices accurately tone-map luminance levels to match their specific display capabilities. The Matroska (MKV) container format preserves this critical color grading information by embedding standardized static metadata fields directly into its track headers using Extensible Binary Meta Language (EBML). This article explains the technical structure MKV uses to define, store, and expose maximum luminance parameters—such as peak display luminance and Content Light Level metadata—independently of the underlying video bitstream.

The MKV EBML Header Structure

Matroska uses an extensible, binary hierarchical system (EBML) to organize media properties. When an HDR video stream is multiplexed into an MKV container, HDR color grading parameters are defined within the container's Track properties.

The hierarchy follows this path:

  1. Segment (The root EBML element)
  2. Tracks
  3. TrackEntry (Specific to the video stream)
  4. Video
  5. Colour

The Colour element (EBML ID 0x55B0) contains all video colorimetry information, including color space, matrix coefficients, transfer characteristics, and display luminance specifications.

Mastering Display Luminance Elements

Within the Colour element, the MasteringMetadata master element (EBML ID 0x55D0) defines the physical characteristics of the monitor used during the mastering process, adhering to the SMPTE ST 2086 standard.

The maximum luminance of the mastering display is explicitly stored in the following tag:

  • LuminanceMax (EBML ID 0x55D9): Represents the maximum luminance of the mastering display. The value is stored as a floating-point number representing candelas per square meter (\(\text{cd/m}^2\)), commonly referred to as nits (e.g., 1000.0 or 4000.0).
  • LuminanceMin (EBML ID 0x55DA): Represents the minimum black level luminance of the mastering display, also expressed as a floating-point value in \(\text{cd/m}^2\) (e.g., 0.0001 or 0.005).

Alongside luminance values, the MasteringMetadata element stores the chromaticity coordinates (\(x, y\)) for the red, green, and blue primary colors, as well as the white point.

Content Light Level Metadata (MaxCLL and MaxFALL)

In addition to mastering display capabilities, HDR color grading requires constraints based on the actual pixel values within the content, as defined by CTA-861-3. MKV stores these values directly under the Colour element:

  • MaxCLL (EBML ID 0x55E9): Maximum Content Light Level. Stored as an unsigned integer representing the maximum pixel brightness (\(\text{cd/m}^2\)) found in any single frame of the entire video.
  • MaxFALL (EBML ID 0x55EA): Maximum Frame-Average Light Level. Stored as an unsigned integer representing the highest average brightness value (\(\text{cd/m}^2\)) of any single frame across the entire video.

Container-Level vs. Bitstream-Level Metadata

In modern codecs like HEVC (H.265) or AV1, mastering luminance data is typically embedded within the video stream's Supplemental Enhancement Information (SEI) NAL units or sequence headers.

MKV replicates these values at the container level to provide major advantages for playback pipelines:

  • Instant Extraction: Media splitters, renderers, and operating systems can query display and content peak brightness instantly during file inspection without initializing video decoders or parsing raw bitstream packets.
  • Direct Passthrough: Hardware video processors and external displays can immediately prepare tone-mapping curves and HDMI dynamic range signaling (InfoFrames) prior to decoding the first video frame.
