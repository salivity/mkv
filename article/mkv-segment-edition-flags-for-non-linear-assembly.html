MKV Segment Edition Flags for Non-Linear Assembly

The Matroska (MKV) container format utilizes an extensible Extensible Binary Meta Language (EBML) structure to manage non-linear video assembly and seamless branching through its chaptering system. By embedding specific flags and metadata inside the EditionEntry and ChapterAtom elements, MKV allows media players to reconstruct dynamic timelines, splice alternate scenes, or reference external media segments without physically duplicating stream data.

The EditionEntry Master Element

At the core of Matroska's non-linear system is the Chapters master element, which contains one or more EditionEntry blocks. Each EditionEntry represents an independent timeline or presentation of the media. Within each EditionEntry, specific binary flags dictate how media splitters and demuxers interpret the chapters:

  • EditionFlagOrdered (EBML ID: 0x45DD): This is the primary flag governing non-linear assembly. When set to 1 (true), it instructs the demuxer that the chapters within this edition are not merely navigational bookmarks, but explicit playback instructions. The player must play the chapters strictly in sequence based on their defined start and end timestamps, skipping any media not covered by the ordered chapter entries.
  • EditionFlagDefault (EBML ID: 0x45DB): A boolean flag indicating whether the player should load that particular edition automatically upon opening the file. Only one edition per file should have this set to 1.
  • EditionFlagHidden (EBML ID: 0x45BD): When set to 1, this flag instructs the user interface to hide the edition from the chapter/edition selection menu. It is frequently used for internal assembly fragments or base files in multi-part segment linking.

ChapterAtom Hierarchy and Time Boundaries

Inside an ordered edition (EditionFlagOrdered = 1), each sub-segment is defined by a ChapterAtom. Rather than letting the stream play continuously, the demuxer relies on the following elements within the ChapterAtom to cut and assemble the final output:

  • ChapterTimeStart and ChapterTimeEnd: Define the exact range (in nanoseconds) within the target segment's media tracks to be decoded and rendered.
  • ChapterFlagHidden: Allows individual cuts within the non-linear timeline to remain invisible as navigational jumps to the user, ensuring seamless transitions between stitched cuts.

Cross-File Non-Linear Assembly (Segment Linking)

MKV expands non-linear assembly beyond a single file via Segment Linking. An EditionEntry can assemble a timeline using scenes distributed across separate MKV files through two critical identifiers:

  1. SegmentUID: A globally unique 128-bit identifier located in the Info element of each MKV file.
  2. ChapterSegmentUID (EBML ID: 0x6E67): Placed inside a ChapterAtom within an ordered edition. If this element is present, the demuxer pauses playback of the current file, searches the local environment for an MKV file possessing a matching SegmentUID, and decodes the time range specified by ChapterTimeStart and ChapterTimeEnd from that external file.

Once the end timestamp of an external chapter is reached, the demuxer transitions to the next ChapterAtom in the ordered list, whether it resides locally or in another linked file.

Demuxer Execution

When an MKV demuxer parses a file containing these edition flags:

  1. It reads the Chapters block and identifies the active EditionEntry (prioritizing EditionFlagDefault).
  2. If EditionFlagOrdered is 1, it creates a virtual presentation timeline.
  3. It queues sequential media slices matching each ChapterTimeStart and ChapterTimeEnd, resolving any ChapterSegmentUID references to external files.
  4. The demuxer then feeds only the assembled slices to the video, audio, and subtitle decoders, delivering a seamless, non-linear presentation without altering the underlying bitstreams.
