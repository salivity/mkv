SimpleBlock vs BlockGroup in MKV Explained

This article explores the core differences between the SimpleBlock and BlockGroup elements within the Matroska (MKV) container format. While both elements serve the primary function of storing raw media payloads—such as video, audio, or subtitle frames—they differ significantly in EBML overhead, feature support, frame-level metadata handling, and typical use cases.

Understanding Blocks in Matroska

Inside an MKV file, media frames are packaged within Cluster elements. Within these clusters, actual encoded data is stored in block structures. Matroska defines two main elements for this purpose: BlockGroup and SimpleBlock.

What is a BlockGroup?

BlockGroup is the original Matroska container structure introduced in version 1 of the specification. It is a parent (master) EBML element that wraps a single Block along with associated metadata elements.

Key characteristics of BlockGroup include:

  • Explicit Block Duration: It can contain a BlockDuration element, explicitly defining how long a specific frame or subtitle should be displayed.
  • Reference Frames: It supports ReferenceBlock elements to explicitly state which previous or future frames are needed to decode the current frame (useful for forward/backward temporal prediction).
  • Additional Data: It can contain BlockAdditions to store extra data streams, such as additional codec layers or spatial data.
  • Higher Overhead: Because it is a nested structure with multiple sub-elements, it requires more bytes of EBML syntax per frame.

What is a SimpleBlock?

SimpleBlock was introduced in Matroska version 2 to optimize streaming and reduce file overhead for standard audio and video streams. Instead of using a master element with nested sub-elements, a SimpleBlock packs the payload and essential flags into a single binary structure.

Key characteristics of SimpleBlock include:

  • Low Overhead: It removes the need for multiple child elements, significantly reducing container bloat in high-framerate media.
  • Integrated Flags: Keyframe status, discardable status (for frames that can be dropped without breaking temporal references), and lacing information are stored directly in a compact 1-byte header flag.
  • No Explicit Duration: It does not support an individual BlockDuration element; playback duration relies on the track's default duration or the timestamp difference between consecutive blocks.

Key Differences

Feature SimpleBlock BlockGroup
Structure Single binary EBML element Master EBML element containing child elements
Overhead Minimal (optimized for performance) Higher (more metadata tags per block)
Keyframe Flagging Dedicated 1-bit flag in the header Inferred from absence of ReferenceBlock or explicit tags
Discardable Flag Built-in bit flag (useful for B-frames) Requires explicit structure / reference tracking
BlockDuration Not supported Supported (critical for variable-duration elements)
BlockAdditions Not supported Supported (allows multi-layer or additional data)

When Each Element is Used

  • SimpleBlock is the modern standard for standard audio and video tracks. Most MKV muxers default to SimpleBlock for video and audio frames because it minimizes container overhead and simplifies parsing.
  • BlockGroup remains essential for subtitle tracks (where text cues vary in duration and require the BlockDuration tag) and advanced video configurations requiring explicit frame references or additional layered payloads.
