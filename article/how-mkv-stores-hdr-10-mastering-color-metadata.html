How MKV Stores HDR10 Mastering Color Metadata

The Matroska (MKV) container stores custom mastering color metadata for HDR10 video displays by utilizing dedicated metadata elements nested within the video track headers. This container-level integration allows media players and display devices to read essential High Dynamic Range (HDR) parameters—such as color primaries, white point coordinates, luminance boundaries, and content light levels—directly from the file envelope without needing to parse the underlying video bitstream first.

The MKV Track Header Hierarchy

In the Matroska specification (EBML format), HDR metadata resides in the Colour element, which is a sub-element of the Video settings block inside a specific TrackEntry. The hierarchical path within the file is:

Segment ➔ Tracks ➔ TrackEntry ➔ Video ➔ Colour

Inside the Colour element, MKV separates HDR10 data into standardized structural parameters, mastering display color volume (SMPTE ST 2086), and content light level information (CTA-861.3).

Mastering Display Metadata (SMPTE ST 2086)

To ensure an HDR10 display maps luminance and color volume accurately, MKV defines floating-point elements representing the mastering monitor used during post-production:

  • Color Primaries: The chromaticity coordinates for the display's red, green, and blue color primaries are stored in the elements:
    • PrimaryRChromaticityX / PrimaryRChromaticityY
    • PrimaryGChromaticityX / PrimaryGChromaticityY
    • PrimaryBChromaticityX / PrimaryBChromaticityY
  • White Point: The normalized coordinates of the reference white point (typically D65 for HDR10) are stored in WhitePointChromaticityX and WhitePointChromaticityY.
  • Luminance Limits: The minimum and maximum brightness capabilities of the mastering display are stored in candelas per square meter (\(cd/m^2\) or nits):
    • LuminanceMin (e.g., 0.005 nits)
    • LuminanceMax (e.g., 1000 or 4000 nits)

Content Light Level Metadata (CTA-861.3)

MKV stores the static content light levels required for dynamic tone mapping on consumer displays:

  • MaxCLL (Maximum Content Light Level): An integer representing the maximum brightness of the single brightest pixel in the entire video stream, measured in nits.
  • MaxFALL (Maximum Frame-Average Light Level): An integer representing the highest average brightness for any single frame in the video stream, measured in nits.

Color Space and Transfer Characteristics

For a standard HDR10 signal, the Colour element also defines the color space encoding values:

  • MatrixCoefficients: Set to 9 to indicate the ITU-R BT.2020 non-constant luminance color space.
  • TransferCharacteristics: Set to 16 to represent the SMPTE ST 2084 Perceptual Quantizer (PQ) electro-optical transfer function (EOTF).
  • Primaries: Set to 9 for ITU-R BT.2020 color primaries.
  • Range: Defines whether the video uses full range or broadcast limited range (typically 1 for broadcast/limited).

Container vs. Bitstream Metadata

In typical HDR10 streams (such as HEVC/H.265), this metadata also exists within Supplemental Enhancement Information (SEI) NAL units inside the raw video bitstream. The MKV container duplicates this metadata at the track level. Demuxers and hardware players can read the container-level Matroska elements to configure HDMI transmission pipelines and display modes before decoding begins, or to override incorrect metadata inside the bitstream without re-encoding the video track.
