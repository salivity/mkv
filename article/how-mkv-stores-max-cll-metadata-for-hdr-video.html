How MKV Stores MaxCLL Metadata for HDR Video

This article provides an overview of how the Matroska (MKV) container format stores static High Dynamic Range (HDR) metadata, focusing specifically on the Maximum Content Light Level (MaxCLL). It explains the underlying EBML structure used to store these values, how container-level metadata interacts with the underlying video bitstream, and why accurate signaling is critical for display tone mapping.

The EBML Hierarchy and the Colour Element

Matroska uses Extensible Binary Meta Language (EBML) to organize media streams hierarchically. Video track properties are nested within individual track entries. HDR static metadata, including MaxCLL, is housed within the Colour element found in the video settings block.

The hierarchy inside an MKV file appears as follows:

  • Segment
    • Tracks
      • TrackEntry (Video)
        • Video
          • Colour (0x55B0)
            • MaxCLL (0x55BD)
            • MaxFALL (0x55BE)
            • MasteringMetadata (0x55D0)

Within the Colour element, the MaxCLL (EBML ID 0x55BD) tag stores an unsigned integer representing the maximum brightness of any single pixel in the entire video stream, measured in candelas per square meter (\(\text{cd/m}^2\) or nits). It is usually accompanied by MaxFALL (Maximum Frame-Average Light Level, EBML ID 0x55BE), which defines the highest average brightness value of any single frame.

Container-Level vs. Bitstream Metadata

In modern HDR video codecs such as HEVC (H.265) and AV1, HDR10 metadata is typically embedded directly inside the elementary video bitstream:

  • HEVC: Encapsulated inside Supplemental Enhancement Information (SEI) messages (specifically, the content_light_level_info SEI message).
  • AV1: Stored inside Open Bitstream Units (OBUs) designated for metadata.

The MKV container duplicates this metadata at the container header level. Storing MaxCLL in the MKV track headers offers two distinct advantages:

  1. Fast Parsing: Demuxers and media players can read HDR parameters instantly during file initialization without needing to initialize the video decoder or parse individual video stream packets.
  2. Metadata Overriding: Media authoring tools can correct or inject missing HDR parameters into the MKV container headers without re-encoding the underlying video elementary stream.

Interaction During Playback and Tone Mapping

During playback, the media pipeline follows these steps to process the MaxCLL parameter:

  1. Demuxing: The MKV splitter (such as FFmpeg/libavformat or LAV Splitter) reads the Colour element in the EBML header.
  2. Metadata Priority: Well-behaved players generally prioritize container-level parameters or cross-reference them with bitstream SEI messages to resolve discrepancies.
  3. Display Communication: The media player passes the MaxCLL and mastering display luminance values to the operating system, video renderer, or directly to an external display via HDMI static metadata InfoFrames (CTA-861-G standard).
  4. Tone Mapping: The receiving display or the software renderer uses the MaxCLL value to calculate the tone-mapping curve, scaling the highlights of the content to fit the physical peak brightness capabilities of the screen without clipping.
