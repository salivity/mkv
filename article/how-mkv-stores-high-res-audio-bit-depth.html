How MKV Stores High-Res Audio Bit Depth

The Matroska (MKV) multimedia container format utilizes a structured, hierarchical metadata system based on Extensible Binary Meta Language (EBML) to store audio stream parameters. This article explains how the MKV container defines and stores audio sample bit depth for high-resolution audio formats, outlining the specific EBML container elements used for lossless audio streams and explaining how bit depth resolution is handled across different high-resolution codec architectures.

The EBML BitDepth Element

At the container level, Matroska organizes stream definitions inside the Tracks master element. Each audio track contains an Audio settings master element that defines stream-specific properties such as sample rate, channel count, and bit depth.

The specific element used to store the audio sample resolution is:

  • Element Name: BitDepth
  • Element ID: [62][64]
  • Type: Unsigned Integer (uinteger)

For high-resolution uncompressed or lossless codecs—such as Linear PCM, FLAC, and WavPack—this element explicitly defines the exact number of bits per audio sample (typically 24 or 32 for high-resolution audio). Demuxers read this value to configure the audio output buffer size before sending the raw decoded samples to the operating system's audio engine.

Handling Uncompressed and Open Lossless Codecs

For codecs where the container dictates the packaging of raw audio data:

  • Linear PCM (A_PCM/INT/LIT, A_PCM/INT/BIG, A_PCM/FLOAT/IEEE): The BitDepth element is mandatory. Because raw PCM contains no internal header data per frame, the demuxer relies entirely on the BitDepth element alongside SamplingFrequency and Channels to parse the byte boundaries of individual samples.
  • FLAC (A_FLAC): While FLAC stores its native bit depth inside the STREAMINFO metadata block within the CodecPrivate element, the MKV BitDepth element is also populated to allow player interfaces to display stream technical details without reading the codec initialization data.

Bitstream-Decoded High-Resolution Formats

For proprietary, packetized high-resolution audio codecs such as Dolby TrueHD (A_TRUEHD), DTS-HD Master Audio (A_DTS), or Dolby Atmos over TrueHD, bit depth management functions differently:

  1. Internal Frame Headers: Advanced surround and object-based codecs encode bit depth, sample rates, and channel layouts directly within the elementary bitstream frames (such as the TrueHD major sync header or the DTS-HD extension substream header).
  2. CodecPrivate Data: Initialization parameters are stored in the MKV CodecPrivate binary element. This allows decoders to initialize the decoding pipeline according to the codec manufacturer's specification.
  3. Container-Level Metadata: In an MKV file containing TrueHD or DTS-HD MA, the BitDepth element is frequently set to 24 to reflect the maximum decoded bit resolution. However, the external MKV BitDepth value is primarily informational for the player; the audio decoder hardware or software derives the true bit depth dynamically from the elementary stream packets during decompression.
