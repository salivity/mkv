Can MKV Store Non-Standard Audio Bit Depths?

The Matroska (MKV) multimedia container fully supports audio streams with non-standard bit depths, including 20-bit audio. Thanks to its flexible, open-standard architecture, MKV does not restrict audio tracks to conventional 16-bit or 24-bit formats. This article details how the MKV specification accommodates arbitrary bit depths, how different audio codecs interact with the container, and what to expect during playback.

Matroska Specification and Bit Depth Handling

The Matroska container format uses Extensible Binary Meta Language (EBML), a binary equivalent to XML. Within the Matroska track specifications, the Audio element includes an explicit BitDepth parameter defined as an unsigned integer.

Because BitDepth accepts any valid integer value, container-level metadata can explicitly declare a track as 20-bit (or any other bit depth, such as 12-bit or 18-bit). When multiplexing an audio stream into an MKV container, tools like MKVToolNix can write the exact source bit depth directly into the track headers without forcing truncation or zero-padding at the container level.

Codec Compatibility

MKV acts as an envelope for compressed or uncompressed audio bitstreams. Storing a 20-bit stream depends largely on whether the underlying audio codec supports non-standard bit depths:

  • Raw PCM: Uncompressed PCM can be mapped to 20-bit within MKV. However, depending on the multiplexer, 20-bit PCM samples may be stored packed or padded within standard 24-bit or 32-bit byte boundaries while retaining the header metadata indicating a 20-bit depth.
  • Lossless Codecs (FLAC, WavPack): Lossless formats like FLAC natively support arbitrary bit depths from 4 to 32 bits per sample. A 20-bit FLAC stream (often sourced from 20-bit master tapes or decoded HDCDs) can be muxed into MKV without any data alteration. WavPack also natively handles 20-bit audio seamlessly.
  • Specialized Cinema and Lossy Codecs: Formats such as DTS-HD Master Audio or Dolby TrueHD can contain audio derived from 20-bit masters. When these bitstreams are encapsulated in MKV, the container preserves the original bitstream untouched.

Playback and Hardware Considerations

While MKV can store 20-bit audio without issue, playback depends on the media player, operating system audio engine, and Digital-to-Analog Converter (DAC):

  1. Demuxing and Decoding: Modern software demuxers (like FFmpeg, LAV Filters, and Libmatroska) read the 20-bit flag accurately and decode the payload without discarding bit precision.
  2. Audio Output: Most modern sound architectures (Windows WASAPI, macOS CoreAudio, Linux ALSA) process modern high-resolution audio inside 24-bit or 32-bit processing pipelines. When playing a 20-bit file, decoders typically align the 20-bit data within a 24-bit container (zero-padding the least significant bits) for output to standard DACs, ensuring the original dynamic range is preserved without loss or distortion.
