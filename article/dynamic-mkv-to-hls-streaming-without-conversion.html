Dynamic MKV to HLS Streaming Without Conversion

Yes, an MKV (Matroska) file can be dynamically segmented for HTTP Live Streaming (HLS) without performing a full conversion or video re-encoding. By utilizing a technique called dynamic transmuxing (or dynamic repackaging), a streaming server can read the original streams inside the MKV container, re-encapsulate them into HLS-compatible segments on-the-fly, and generate the necessary .m3u8 playlists in real time. This process saves substantial CPU overhead and storage space.

How Dynamic Transmuxing Works

Video conversion (transcoding) decodes and re-encodes raw audio and video frames, which is resource-intensive. Transmuxing, by contrast, only alters the container format. It extracts the raw compressed elementary streams (such as video and audio packets) from the MKV container and wraps them into MPEG-TS (.ts) or Fragmented MP4 (.m4s/fMP4) segments.

Because this process only involves reading, packetizing, and streaming data, dynamic transmuxing operates with negligible CPU usage and near-zero latency.

Codec Compatibility Requirements

Dynamic segmentation without re-encoding requires that the codecs inside the MKV container are natively supported by the target HLS clients (such as Safari, iOS, Android, or desktop browsers using HLS.js).

  • Video: H.264 (AVC), H.265 (HEVC), or AV1.
  • Audio: AAC, AC-3, E-AC-3, or MP3.

If an MKV file contains incompatible codecs (such as VP9 video or DTS/TrueHD audio), dynamic transmuxing alone will fail on most clients, and the audio or video will need to be transcoded.

Technical Implementation

Dynamic HLS segmentation can be implemented using several approaches:

  1. Dedicated Media Servers: Media servers like Nimble Streamer, Wowza Streaming Engine, or the NGINX-VOD-Module can read static MKV files directly from storage and generate dynamic HLS streams and playlists via HTTP endpoints automatically.
  2. FFmpeg On-Demand: A backend service can spawn an ffmpeg process when a user requests a stream. By using the -codec copy flag, FFmpeg quickly reads the MKV file and outputs an HLS manifest and segmented files directly to a temporary directory or standard output.
  3. Custom Byte-Range Proxies: Using low-level media parsing libraries (in languages like Go, Rust, or C++), a server can parse the MKV index (seek head and cues) to locate keyframe offsets, serving exact byte ranges packaged dynamically as fragmented MP4 segments upon HTTP range requests.

Key Considerations

  • Keyframe (GOP) Structure: Dynamic segmentation splits files at video keyframes (I-frames). If the MKV file has long or irregular keyframe intervals, segment durations may vary, which can slightly affect seek precision or segment caching.
  • Subtitles: Subtitles in MKV files are frequently stored as ASS/SSA or PGS formats. These are not supported directly in HLS and must be extracted and dynamically converted to WebVTT format for browser playback.
