How MKV Handles HDR Transfer Characteristics

The Matroska (MKV) multimedia container manages High Dynamic Range (HDR) transfer characteristics by utilizing standardized EBML (Extensible Binary Meta Language) elements embedded directly within the video track headers. By mapping Electro-Optical Transfer Functions (EOTF) to internationally recognized standard values, such as SMPTE ST 2084 (PQ) and ARIB STD-B67 (HLG), MKV ensures media players, renderers, and display hardware accurately interpret the luminance curve and color space of HDR video streams.

The MKV Colour Element Hierarchy

In an MKV file, metadata describing video color reproduction is placed inside the TrackEntry element, nested under the Video settings within a designated Colour element (EBML ID: 0x55B0). This block groups all colorimetry parameters, separating container-level signaling from the raw codec bitstream.

Within the Colour element, the specific transfer function is defined by the TransferCharacteristics element (EBML ID: 0x55BA). This is an unsigned integer field that aligns directly with the ITU-T H.273 (ISO/IEC 23091-2) coding standards.

Common Transfer Characteristic Values for HDR

MKV uses standardized numerical values to declare the transfer characteristics used by the source:

  • Value 16 (SMPTE ST 2084 / PQ): Used for static and dynamic HDR formats, including HDR10, HDR10+, and Dolby Vision. It represents the Perceptual Quantizer curve capable of displaying brightness levels up to 10,000 nits.
  • Value 18 (ARIB STD-B67 / HLG): Used for Hybrid Log-Gamma, common in broadcast HDR. It allows a single signal to serve both SDR and HDR displays without separate metadata tracks.
  • Value 1 (ITU-R BT.709): The standard transfer function for SDR content, used when HDR transfer characteristics are absent or explicitly flagged as standard range.
  • Value 9 (BT.2020 10-bit) & Value 10 (BT.2020 12-bit): Used for wide color gamut representations with standard gamma curves.

Integration with Mastering Metadata

Transfer characteristics work in tandem with other nested elements inside the Colour block to provide complete HDR signaling:

  • MatrixCoefficients (0x55B1): Identifies the color matrix, typically set to 9 (ITU-R BT.2020 non-constant luminance) for HDR content.
  • Primaries (0x55BB): Identifies the chromaticity coordinates, typically set to 9 (ITU-R BT.2020) for HDR formats.
  • MasteringMetadata (0x55D0): Contains sub-elements such as PrimaryRChromaticity, LuminanceMax, and LuminanceMin to define the target display volume used during grading.
  • MaxCLL (0x55BC) and MaxFALL (0x55BD): Specify the Maximum Content Light Level and Maximum Frame-Average Light Level in candelas per square meter (nits).

Container-Level vs. Bitstream Signaling

While modern video codecs like HEVC (H.265) and AV1 embed transfer characteristics directly within the bitstream via Supplemental Enhancement Information (SEI) messages or sequence headers, MKV duplicate-flags this information at the container level.

This dual-layer approach allows demuxers and hardware splitters to read the transfer characteristics instantly during container initialization. As a result, displays can configure their HDR pipelines and tone-mapping engines before the decoder processes the first frame of video data, preventing visual artifacts and handshake delays.
