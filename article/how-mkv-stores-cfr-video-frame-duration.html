How MKV Stores CFR Video Frame Duration

The Matroska (MKV) container format manages frame durations for constant frame rate (CFR) video by combining header metadata with individual block timestamps. Although Matroska is natively designed around a timecode-based (variable frame rate) architecture, it signals and maintains CFR playback using the DefaultDuration track header element in conjunction with the segment's TimestampScale and sequential SimpleBlock timestamps.

The DefaultDuration Element

In a Matroska container, frame rate is not explicitly declared as a traditional ratio (such as 30000/1001). Instead, the container defines the expected duration of each frame using the DefaultDuration element located within the TrackEntry for that specific video track.

  • The DefaultDuration value is stored as an integer representing the duration of a single frame in nanoseconds.
  • For a standard 24 fps video, the DefaultDuration is set to 41666666 nanoseconds (\(1,000,000,000 / 24\)).
  • For a 29.97 fps (NTSC) video, it is set to approximately 33366666 nanoseconds.

Media players and decoders read DefaultDuration to determine the native display frame rate and to calculate the default length of time each video frame should be displayed on screen.

TimestampScale and Block Timestamps

Matroska organizes media payloads into units called Cluster elements, which contain either SimpleBlock or BlockGroup elements holding the compressed frame data.

Timing within clusters relies on two factors:

  1. TimestampScale: Located in the MKV Info segment, this global value defines the base time unit for timestamps in nanoseconds (defaulting to 1,000,000 ns, or 1 millisecond).
  2. Block Timestamps: Each SimpleBlock carries a relative timestamp indicating when that frame should be rendered relative to the cluster's base timestamp.

Calculating Frame Duration for CFR

For a video to remain constant in frame rate inside an MKV container:

  • Each consecutive SimpleBlock is written with a timestamp that increases by a fixed interval equal to the frame duration (adjusted to the TimestampScale).
  • Players calculate the effective frame duration either by calculating the delta between consecutive block timestamps (\(Timestamp_{n+1} - Timestamp_n\)) or by defaulting to the DefaultDuration set in the track header.
  • While BlockGroup elements support an explicit BlockDuration element for individual frames, CFR streams generally omit this per-frame tag to reduce container overhead, relying entirely on the linear timestamp increments and the track's DefaultDuration.
