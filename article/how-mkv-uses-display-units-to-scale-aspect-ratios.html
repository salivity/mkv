How MKV Uses Display Units to Scale Aspect Ratios

The Matroska (MKV) container stores display unit metadata inside its structural track headers to ensure video players correctly scale non-square pixels to their intended aspect ratio during playback. By decoupling the encoded storage resolution from the final presentation dimensions, MKV allows anamorphic video content to be displayed accurately without requiring the underlying video stream to be re-encoded.

The Role of EBML in MKV Metadata

MKV is built upon EBML (Extensible Binary Meta Language), a binary equivalent of XML. Inside an MKV file, video track parameters are defined under the TrackEntry element, which contains a dedicated Video settings master element. To manage aspect ratio and scaling, the container relies on a specific combination of EBML elements:

  • PixelWidth and PixelHeight: These mandatory elements define the actual coded dimensions of the video stream in raw pixels (Storage Aspect Ratio, or SAR).
  • DisplayWidth and DisplayHeight: These elements define the target dimensions used to calculate the presentation geometry (Display Aspect Ratio, or DAR).
  • DisplayUnit: This element determines how the player should interpret the values provided in DisplayWidth and DisplayHeight.

Interpreting the DisplayUnit Element

The DisplayUnit tag accepts specific integer values that instruct the video renderer on the mathematical scaling method to apply:

  • Value 0 (Pixels - Default): The DisplayWidth and DisplayHeight values are treated as a target pixel resolution. For example, a 720×480 DVD rip (3:2 storage ratio) intended for widescreen display will have a DisplayWidth of 854 and a DisplayHeight of 480. The player calculates the Pixel Aspect Ratio (PAR) as \((854 / 480) \div (720 / 480) \approx 1.186\) and stretches the horizontal axis accordingly.
  • Value 1 (Centimeters): The display dimensions are interpreted as physical measurements in centimeters, allowing displays calibrated to metric sizing to render the exact physical proportions.
  • Value 2 (Inches): The display dimensions are interpreted as physical measurements in imperial inches.
  • Value 3 (Display Aspect Ratio): The display values are treated directly as an abstract ratio rather than concrete pixel targets (e.g., DisplayWidth = 16, DisplayHeight = 9). The player fits the raw frame into a 16:9 rendering viewport.

Container Precedence vs. Bitstream Metadata

Video codecs like H.264 (AVC) and H.265 (HEVC) can store aspect ratio metadata internally within their Sequence Parameter Sets (SPS) via Video Usability Information (VUI) flags. MKV's display unit metadata functions at the demuxer layer.

When a media player opens an MKV file, the demuxer reads the TrackEntry parameters before decoding begins. Compliant media players prioritize the container-level DisplayWidth, DisplayHeight, and DisplayUnit values over any internal bitstream VUI flags, allowing users or remuxing utilities to correct incorrect aspect ratios instantly at the container level without modifying the compressed video bitstream.
