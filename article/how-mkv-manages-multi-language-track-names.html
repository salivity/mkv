How MKV Manages Multi-Language Track Names

The Matroska (MKV) multimedia container format manages multi-language display names for embedded tracks through a structured metadata architecture based on Extensible Binary Meta Language (EBML). Instead of relying solely on hardcoded, single-string track titles, MKV utilizes a combination of native TrackEntry parameters, modern BCP 47 language tags, and the specialized Matroska Tagging system. This structure enables media players to read, localize, and present distinct display names for audio, video, and subtitle tracks based on the end user's system language preferences.

The Track Header vs. The Tagging System

In basic MKV implementations, each track contains a single Name element within its TrackEntry master element. This string defines the default label (e.g., "Director's Commentary"). However, the native TrackEntry element is limited because it can only hold a single Name string per track.

To provide localized, multi-language display names for that same track, MKV relies on its integrated Tagging System (Tags master element).

How Matroska Tags Enable Localized Track Names

The Matroska Tagging specification provides a hierarchical way to attach multilingual metadata to specific components of the file using Track Unique Identifiers (TrackUID).

  1. Targeting the Track: Under the Tags element, a Tag contains a Targets sub-element. The TargetTypeValue is set to 30 (which designates a track-level target), and TargetTrackUID is matched to the specific track's UID.
  2. Assigning Localized Strings: Inside the SimpleTag element, the TagName is defined (typically as TITLE).
  3. Specifying the Display Language: Each SimpleTag includes language identifiers—historically TagLanguage (ISO 639-2) and modernly TagLanguageIETF (BCP 47).
  4. Multiple Translations: Authors can include multiple SimpleTag entries for the same TagName under the same track target, each carrying a different TagLanguageIETF and translated TagString.

For example, a commentary track can have a TagString of "Director's Commentary" with an en (English) language tag, and a corresponding SimpleTag with "Commentaire du réalisateur" tagged as fr (French).

Language Tag Modernization (BCP 47)

Older MKV specifications relied exclusively on three-letter ISO 639-2 codes (Language and TagLanguage). Modern MKV specifications (v4 and later) introduced LanguageIETF and TagLanguageIETF.

These elements use the IETF BCP 47 standard, which supports:

  • Primary language subheaders (e.g., es for Spanish)
  • Regional variants and dialects (e.g., pt-BR for Brazilian Portuguese vs. pt-PT for European Portuguese)
  • Script variations (e.g., zh-Hans for Simplified Chinese vs. zh-Hant for Traditional Chinese)

This precision ensures that multi-language display names accurately correspond to specific regional dialects.

Player Resolution and Fallback Behavior

When an MKV file is opened, a compatible media player determines which track name to display using a standardized fallback hierarchy:

  1. Exact Locale Match: The player queries the Tags structure for a TITLE tag whose TagLanguageIETF matches the user's interface language.
  2. Primary Language Match: If an exact regional match (e.g., fr-CA) is missing, the player looks for the base language (fr).
  3. Default Track Header: If no matching tag exists, the player falls back to the static Name string stored inside the TrackEntry.
  4. Generic Fallback: If the Name element is empty, the player generates a generic label using the track type, codec, and the track's primary content language (e.g., "Audio 1 - Spanish [AC-3]").
