Extract Blu-ray Multi-Track Audio to MKV

Automated Blu-ray ripping applications extract multi-track audio into MKV containers by decrypting the disc, reading the playlist architecture to map out all available streams, demultiplexing the raw audio packets from the transport stream, and remultiplexing those tracks alongside video and subtitles into a single Matroska file. This process preserves the original bit-for-bit quality of advanced formats like Dolby TrueHD, DTS-HD Master Audio, and multi-channel LPCM without requiring lossy transcoding.

1. Decryption and Disc Authentication

Before any media data can be accessed, the ripping software must bypass the digital rights management (DRM) layers present on commercial Blu-rays.

  • AACS and BD+ Handling: The software utilizes volume keys, processing keys, or key databases to decrypt the Advanced Access Content System (AACS) and reverse the BD+ virtual machine transformations.
  • LibreDrive / Direct Hardware Access: Modern ripping tools bypass hardware-level drive restrictions to read the raw encrypted blocks directly, preventing the optical drive firmware from altering or blocking access to specific sectors.

2. Parsing the BDMV Playlist Architecture

Blu-ray discs store content inside a structured folder hierarchy called BDMV. Rather than storing movies as single contiguous files, Blu-ray splits data into multiple .m2ts (MPEG-2 Transport Stream) files controlled by playlist files (.mpls).

  • The software parses the .mpls playlist files to identify the main feature runtime and avoid "playlist obfuscation" (false playlists used as copy protection).
  • It maps the sequence of .m2ts clips required to construct the full audio-video timeline seamlessly.
  • The tool identifies all elementary streams within the transport stream, including the primary audio (director's mix, native language), secondary tracks (commentaries, alternative languages), and descriptive audio.

3. Demultiplexing Multi-Track Audio Streams

The transport streams combine video, audio, and subtitle packets into a single interleaved data feed. Automated applications separate (demux) these packets on the fly.

  • PID Filtering: Every stream inside an .m2ts file has a unique Packet Identifier (PID). The demuxer filters and extracts specific PIDs corresponding to each audio track.
  • Handling Nested Audio Formats: Many Blu-ray audio formats are structured in layers. For example:
    • Dolby TrueHD: Contains an embedded Dolby Digital (AC-3) core for backwards compatibility.
    • DTS-HD Master Audio: Contains a lossy DTS Digital Surround core alongside high-resolution extension packets.
  • Ripping software allows users to either extract the full lossless stream (extension + core), split the audio into separate tracks (extracting the lossless track and standard lossy core independently), or extract only the lossy core to save file space.

4. Direct Remuxing into the Matroska (MKV) Container

Unlike traditional video conversion software, automated lossless rippers do not decode the audio into uncompressed PCM and re-encode it. Instead, they perform direct stream copying (remuxing).

  • Header Generation: The application creates a Matroska container structure, writing the essential track headers for each audio stream.
  • Timestamp Synchronization: The software synchronizes the Presentation Time Stamps (PTS) from the original transport stream to ensure multi-track audio aligns perfectly with the video frame rate, eliminating audio delay issues.
  • Packet Encapsulation: The raw audio packets (lossless TrueHD, DTS-HD MA, or multi-channel LPCM) are encapsulated directly into Matroska audio blocks.

5. Metadata and Language Tagging

During the final multiplexing phase, the application reads the language and configuration attributes defined in the disc's playlist metadata and applies them to the MKV file:

  • Language Tags: Tracks are assigned ISO 639-2 language codes (e.g., eng, spa, jpn).
  • Channel Layouts: Specific channel configurations (e.g., 7.1, 5.1, Stereo) and spatial flags (such as Dolby Atmos or DTS:X metadata) are embedded directly into the track headers.
  • Track Flags: Default and forced track flags are assigned, determining which audio stream media players prioritize upon playback.
