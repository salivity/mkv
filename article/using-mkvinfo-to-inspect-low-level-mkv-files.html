Using mkvinfo to Inspect Low-Level MKV Files

The mkvinfo command-line utility, part of the open-source MKVToolNix suite, is a dedicated tool for analyzing and troubleshooting the internal structure of Matroska (MKV) and WebM media files. By parsing the underlying Extensible Binary Meta Language (EBML) architecture, it allows developers, video engineers, and power users to inspect the precise structural hierarchy of an MKV container without decoding the actual audio or video streams.

Understanding the MKV Hierarchy

Matroska files are organized using EBML, which operates similarly to binary XML. Data is stored in nested elements containing an ID, a data size descriptor, and the payload. mkvinfo reads these elements sequentially and outputs a structured tree view of the container.

The primary structural components exposed by mkvinfo include:

  • EBML Header: Contains fundamental metadata about the container format version, EBML read version, and doctype (e.g., matroska or webm).
  • Segment Header & Info: Defines global properties for the file, including the Segment UID, multiplexing application, writing application, duration, and timestamp scale.
  • Tracks: Lists individual stream definitions (video, audio, subtitles), detailing codec IDs, track numbers, default durations (frame rates), resolution, channel counts, and codec-specific private data.
  • Clusters and SimpleBlocks: Houses the actual media frames. mkvinfo reveals cluster timestamps, block payloads, keyframe flags, and track references, which is vital for inspecting timecode alignment.
  • SeekHead and Cues: Contains indexing elements. The SeekHead points to major segment positions, while Cues map timestamps to specific file offsets for fast seeking.
  • Chapters and Tags: Displays rich metadata, segment editions, and custom descriptive tags.

Key Use Cases for Low-Level Inspection

  1. Diagnosing Playback and Seeking Errors: Corrupted Cue points or missing SeekHeads often lead to slow or broken seeking in media players. mkvinfo quickly verifies whether index tables are complete and properly mapped.
  2. Analyzing A/V Synchronization Issues: By viewing cluster-level timestamps and individual Block durations, users can pinpoint timestamp drift, non-monotonic timecodes, or missing frames.
  3. Validating Codec Configurations: Inspecting the CodecPrivate element helps verify whether stream initialization headers (such as AVC/HEVC parameter sets or Vorbis/Opus headers) are intact.
  4. Header and Structural Corruption Analysis: If a file fails to open, running mkvinfo reveals the exact byte offset where parsing terminates, indicating where container damage has occurred.

Command-Line Usage and Verbosity

By default, mkvinfo provides a summary of tracks and top-level segment info. Increasing the verbosity level exposes deeper container layers:

  • Basic Summary:

    mkvinfo input.mkv

  • Detailed Hierarchy (Tracks, Clusters, and Timecodes):

    mkvinfo -v input.mkv

  • Maximum Detail (Every Block, Frame Size, and Hex Dumps):

    mkvinfo -v -v -X input.mkv

    (Using -X includes hexadecimal dumps of element payloads, useful for low-level byte analysis.)

Through these capabilities, mkvinfo serves as a critical diagnostic tool, providing clear visibility into how media streams and metadata are multiplexed within the Matroska container format.
