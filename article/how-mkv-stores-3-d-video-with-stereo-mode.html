How MKV Stores 3D Video with StereoMode

The Matroska (MKV) container format supports stereoscopic 3D content by defining the physical layout of the left- and right-eye perspectives within the video stream using the StereoMode element. Rather than relying on proprietary 3D codecs, MKV uses this standardized metadata tag inside its video track headers to tell media players and 3D displays how to split, unpack, and render combined video frames into an immersive three-dimensional experience.

The Role of the StereoMode Element

In Matroska's Extensible Binary Meta Language (EBML) structure, the StereoMode element is stored within the Track definition hierarchy:

Segment ➔ Tracks ➔ TrackEntry ➔ Video ➔ StereoMode (Element ID 0x53B8)

The element is stored as an unsigned integer. When omitted, the player assumes a default value of 0 (monoscopic/standard 2D video). When present, the assigned integer instructs the decoder how the video frames are packed and which eye's view comes first.

Common StereoMode Values and Layouts

Stereoscopic 3D video usually packs two separate images into a single video frame. The StereoMode element defines the spatial arrangement of these images:

  • 0: Mono – Standard 2D video.
  • 1: Side by Side (Left Eye First) – The frame is split vertically; the left half contains the left-eye image and the right half contains the right-eye image.
  • 2: Top - Bottom (Right Eye First) – The frame is split horizontally; the upper half displays the right eye and the lower half displays the left eye.
  • 3: Top - Bottom (Left Eye First) – The frame is split horizontally; the upper half displays the left eye and the lower half displays the right eye.
  • 7: Side by Side (Right Eye First) – The frame is split vertically; the right-eye view is placed on the left side of the frame.
  • 11: Anaglyph (Cyan/Red) – Both views are overlaid into a single image using color filters.
  • 13 & 14: Field Sequential / Block Interleaved – Both views are interlaced within the same block, either left-eye first (13) or right-eye first (14).

How Decoders Process Stereoscopic MKV Files

  1. Header Parsing: When an MKV file is opened, the media player parses the TrackEntry for video tracks and reads the StereoMode tag value.
  2. Standard Frame Decoding: The underlying video stream (such as H.264, H.265/HEVC, or VP9) is decoded as a standard, single video stream without needing specialized 3D decoder hardware.
  3. Post-Processing and Rendering: The renderer uses the StereoMode value to crop and separate the single frame into distinct left and right channels. It then outputs the images according to the connected display technology—such as alternating frames for active shutter glasses, line-by-line interlacing for passive polarized screens, or separate viewports for virtual reality headsets.

Advantages of Container-Level 3D Flagging

Storing stereoscopic arrangement at the container level offers broad compatibility. Video compression algorithms do not require modification to handle 3D data, enabling creators to encode 3D content using standard video encoders while ensuring that compatible media players automatically switch to the correct 3D display mode without requiring manual user configuration.
