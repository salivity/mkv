MKV Support for Right-to-Left Subtitles

MKV (Matroska) container files fully support embedded subtitle tracks in right-to-left (RTL) scripts, such as Arabic, Hebrew, Persian, and Urdu. Because Matroska is an open, flexible container format designed to handle virtually any combination of video, audio, and subtitle streams, it places no restrictions on the reading direction or character encoding of embedded text. Whether subtitles are text-based or image-based, they can be multiplexed directly into an MKV file and rendered accurately when using compatible media playback software.

How MKV Handles Right-to-Left Subtitles

MKV files do not render text on their own; instead, they encapsulate subtitle data streams alongside video and audio tracks. RTL language support operates primarily through two subtitle categories:

1. Text-Based Subtitles (SRT, ASS/SSA)

  • UTF-8 Encoding: Modern MKV files store text subtitles using UTF-8 character encoding. UTF-8 natively supports all Unicode character sets, including Arabic, Hebrew, and other RTL alphabets.
  • Bidirectional (BiDi) Text: Standard formats like SubRip (.srt) and Advanced SubStation Alpha (.ass) rely on standard Unicode Bidirectional algorithms. When formatted correctly, embedded text files preserve the proper word order and script direction.
  • Styling and Shaping: Formats like ASS/SSA allow specific font styling, alignments, and positioning, ensuring that RTL text displays naturally without broken ligatures or reversed characters.

2. Image-Based Subtitles (PGS, VobSub)

  • Formats like PGS (used on Blu-ray) and VobSub (used on DVD) store subtitles as pre-rendered bitmapped images rather than raw text.
  • Because the text is already rasterized into an image before being embedded into the MKV container, script direction is completely preserved regardless of the playback device's font libraries.

The Role of Media Players and Rendering Engines

While MKV successfully stores RTL subtitle tracks, the final visual output depends on the media player's text-rendering engine.

  • Text Shaping Engines: Languages such as Arabic and Persian require contextual shaping (where letter forms change based on their position in a word). Players using modern rendering libraries (like HarfBuzz and Libass) correctly connect letters and order text from right to left.
  • Player Compatibility: Software like VLC Media Player, MPV, and MPC-HC natively handle RTL subtitles embedded in MKV files. If text appears reversed or disconnected, the issue stems from the media player's subtitle settings or missing fonts rather than the MKV container itself.

Embedding RTL Subtitles into MKV

RTL subtitle tracks can be embedded into an MKV container using multiplexing tools such as MKVToolNix (mkvmerge). During the muxing process, creators can specify the correct ISO 639-2 language code (such as ara for Arabic or heb for Hebrew) and designate the track's default or forced flags, ensuring that compatible players automatically apply appropriate RTL rendering rules upon playback.
