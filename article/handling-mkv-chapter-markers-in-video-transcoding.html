Handling MKV Chapter Markers in Video Transcoding

Video transcoding pipelines process embedded Matroska (MKV) chapter markers by extracting the metadata during demuxing, preserving timecode accuracy through video transformations, and serializing the data into the target container format. Because different containers handle metadata differently, pipelines must translate MKV's hierarchical chapter format into standard formats like MP4 QuickTime chapter tracks, Nero chapters, WebVTT sidecar files, or streaming manifests.

1. Demuxing and Chapter Extraction

The pipeline begins with the demuxer (such as FFmpeg's libavformat or GPAC) reading the MKV file. MKV stores chapters within its Extensible Binary Meta Language (EBML) tree using the Chapters element, which contains nested EditionEntry and ChapterAtom structures.

During demuxing, the pipeline extracts:

  • TimeStart and TimeEnd: Millisecond-accurate or nanosecond-accurate presentation timestamps (PTS).
  • ChapterDisplay: Strings representing chapter titles, language tags, and country codes.
  • Hierarchical structures: Parent-child chapter relationships, if present.

The demuxer normalizes these EBML elements into a generic internal chapter representation (such as an array of AVChapter structs in FFmpeg), decoupling the metadata from the MKV container.

2. Timestamp Synchronization and Drift Management

If the transcoding pipeline alters the video's presentation timeline—through trimming, frame rate conversions, or dynamic ad insertion—chapter markers must be adjusted:

  • Trimming and Slicing: If the video start point is offset, the pipeline subtracts the offset duration from each chapter's start and end timestamps. Chapters outside the active duration are discarded.
  • Timebase Rescaling: MKV chapters typically use a nanosecond timebase (\(1/1,000,000,000\)), while MP4 containers typically use the video stream's timebase (e.g., \(1/90000\)). The pipeline rescales chapter timestamps to match the target container's clock rate.
  • Keyframe Alignment: Many transcoders force an Instantaneous Decoder Refresh (IDR) keyframe at exact chapter boundary timestamps to allow seamless navigation without visual artifacts during playback jumps.

3. Target Format Serialization

Handling chapter metadata depends entirely on the destination container:

MP4 and MOV (MPEG-4 Part 14)

Pipelines convert the internal chapters into one of two MP4 implementations:

  • QuickTime Chapter Track: The pipeline generates a dedicated hidden timed-text track (text or tx3g). The track contains sample durations equal to each chapter's length, with text payloads for the chapter names. It links this track to the primary video track via a track reference box (tref with a chap reference type).
  • Nero Metadata Atom (chpl): A single atom inside the moov/udta box that stores a table of chapter start times and string names.

HLS and MPEG-DASH (Segmented Streaming)

Segmented formats do not support embedded MKV chapters natively within media segments (MPEG-2 TS or fragmented MP4). The pipeline handles this by:

  • Generating a separate WebVTT file that lists cue points with timestamps and titles.
  • Embedding the WebVTT file into the master playlist manifest (e.g., #EXT-X-MEDIA:TYPE=SUBTITLES or metadata tracks in HLS).
  • Injecting ID3 timed metadata tags at segment boundaries corresponding to chapter points.

Plain Text and Sidecar Files

When converting to formats that lack metadata support (such as bare elementary streams or certain legacy formats), pipelines export chapters into external files such as standard Simple Chapter format (CHAPTER01=...), XML, or WebVTT.

4. Edge Cases and Lossy Conversions

Transcoding pipelines employ fallback strategies when handling complex MKV features:

  • Nested/Hierarchical Chapters: MKV supports nested sub-chapters, whereas MP4 and WebVTT support only flat lists. Pipelines flatten hierarchical chapters or discard secondary depth levels.
  • Multiple Editions: MKV allows ordered chapters and alternative story cuts (editions). Most standard transcoders select the default edition entry and discard alternative tracks unless explicitly configured to map them.
