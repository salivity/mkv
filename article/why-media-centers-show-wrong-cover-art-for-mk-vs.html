Why Media Centers Show Wrong Cover Art for MKVs

Media centers frequently display the wrong poster, thumbnail, or backdrop for Matroska (MKV) video files that contain multiple embedded images. This issue occurs because media players and server software—such as Plex, Kodi, Jellyfin, and VLC—use different methods to prioritize, parse, and identify embedded image attachments. When an MKV container contains several images without standardized naming conventions or priority flags, the media center may simply display the first image it reads rather than the intended primary poster.

How MKV Image Attachments Work

The Matroska container format allows various files to be embedded directly alongside video, audio, and subtitle streams. These attachments often include:

  • Front cover art (cover.jpg or cover.png)
  • Back cover art (cover_back.jpg)
  • Fanart, backdrops, or landscape thumbnails
  • Production stills, cast photos, or disc art

Each attachment inside an MKV file contains metadata fields, including a filename, a MIME type (such as image/jpeg), and an internal track/attachment index number.

Common Causes for Incorrect Cover Art Display

1. Attachment Index Priority (First-In Priority)

Many media scrapers and players do not evaluate attachment metadata deeply. Instead, they scan the container sequentially and display the very first image stream they encounter. If a background wallpaper or disc image was added to the MKV before the primary cover, the media player will default to showing that image.

2. Non-Standard Attachment Naming

According to Matroska metadata specifications, primary cover images should ideally be named cover.jpg or cover.png, while smaller thumbnails are designated as small_cover.jpg. If embedded images use arbitrary names (e.g., folder.jpg, image1.jpeg, poster_final.png), the media center's parser may fail to recognize which image is the official cover.

3. Conflicting Local and Online Metadata Agents

Media servers often use a combination of online scrapers (such as TheMovieDB or TheTVDB) and local metadata agents. If local media asset prioritization is enabled, the server will override accurate online metadata with whatever attachment is extracted from the local MKV file, even if that attachment is an incorrect or low-resolution image.

4. Multiple Images with Identical MIME Types

When an MKV contains multiple attachments sharing the same MIME type (e.g., three separate image/jpeg files) without distinctive Matroska description tags, the parser has no programmatic way to determine image hierarchy, leading to inconsistent thumbnail generation across different devices.

How to Resolve the Issue

  • Edit Attachments with MKVToolNix: Open the file in MKVToolNix Header Editor or Multiplexer. Remove unnecessary image attachments, reorder them, or rename the primary poster to cover.jpg.
  • Standardize File Naming: Ensure the primary front poster uses the exact filename cover.jpg or cover.png.
  • Adjust Scraper Priority: In media server settings (such as Plex or Jellyfin), lower the priority of "Local Media Assets" so that the server prioritizes fetched online metadata over embedded container attachments.
  • Clear Image Caches: After modifying the MKV attachments, refresh the media center's metadata cache to remove the previously cached incorrect thumbnail.
