How MKV Segment UIDs Create Virtual Discs

The Matroska (MKV) container format utilizes unique 128-bit Segment Unique Identifiers (Segment UIDs) combined with ordered chapters to construct complex virtual disc environments from separate physical media files. By referencing external Segment UIDs within its chapter metadata, a single master MKV file can instruct media splitters to seamlessly branch, reorder, and assemble audio, video, and subtitle streams dynamically on playback without requiring redundant data storage or physical file concatenation.

Understanding the Segment UID

Every MKV file contains a Segment Information element at its root level. Within this block resides the SegmentUID, a randomly generated, 128-bit (16-byte) value designed to uniquely identify that specific file among any collection of files.

Because the SegmentUID is independent of the file name, file paths, or file size, media demuxers identify files based on their intrinsic metadata. When authoring complex media architectures, these UIDs serve as absolute pointers across a local library.

The Role of Ordered Chapters and Segment Linking

To build a virtual disc environment—such as an interactive structure with shared opening sequences, alternate angles, or multiple cut editions—the Matroska specification employs two distinct methods of segment linking:

1. Hard Linking (PrevUID and NextUID)

In basic segment linking, an MKV container includes PrevUID and NextUID fields within its Segment Information header. When a media player finishes rendering the current segment, it reads the NextUID, finds the matching file in the same directory or playback scope, and seamlessly transitions playback to the next segment. This functions linearly, similar to continuous tracks on a CD or DVD.

2. Soft Linking via Ordered Chapters

The core mechanism for emulating complex DVD or Blu-ray virtual structures is Ordered Chapters. Standard MKV chapters simply mark timestamps within a single file. Ordered chapters, however, define a complete virtual timeline where each entry specifies:

  • A start and end timestamp on the virtual timeline.
  • A target ChapterSegmentUID matching an external MKV's SegmentUID.
  • Source start and end timestamps indicating which slice of the referenced file to play.

When ordered chapters are enabled, the player ignores the physical linear timeline of the file and strictly follows the structured chapter list.

How the Splitter Processes the Virtual Environment

When a user opens a master MKV file, compatible demuxers and splitters process the Segment UIDs through a distinct execution pipeline:

  1. Header Parsing: The splitter reads the master file's chapter table and flags the presence of the ChapterFlagOrdered attribute along with external ChapterSegmentUID values.
  2. Directory Indexing: The splitter scans the current directory and indexed folders, reading only the header blocks of adjacent .mkv files to build a lookup table mapping each SegmentUID to a physical file path.
  3. Timeline Construction: The player synthesizes a virtual duration by summing the durations of each ordered chapter block, regardless of which physical file hosts the content.
  4. Stream Pre-buffering and Codec Synchronization: For seamless switching, splitters ensure that the video and audio codecs, resolutions, and track layouts between linked files match. The demuxer initializes decoders capable of switching input streams at defined keyframes without dropping frames.
  5. Dynamic Branching: As the playback position approaches the end of a chapter, the demuxer opens the linked file corresponding to the upcoming ChapterSegmentUID, seeks to the specified in-point, and transitions the packet delivery pipeline to the video and audio decoders.

Practical Virtual Disc Applications

This architecture enables several advanced media environments without physical disc media:

  • Shared Sequences (De-duplication): Episodic television series can store recurring intros and credits in individual, standalone MKV files. Each episode contains only unique story content and an ordered chapter map linking to the shared sequences, saving substantial storage space.
  • Multi-Cut Master Files (Seamless Branching): A single distribution can include both Theatrical and Director's Cuts. The master file references exclusive scenes and shared scenes from separate component files, playing alternate timelines based on user edition selection.
  • Complex Menu and Extra Replication: By linking short segment clips, commentary audio tracks, and supplementary featurettes via chapter indices, authoring tools can mimic the non-linear interactive features of physical optical discs within standard file systems.
