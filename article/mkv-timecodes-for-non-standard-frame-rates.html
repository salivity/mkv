MKV Timecodes for Non-Standard Frame Rates

The Matroska (MKV) container handles non-standard, fractional, and variable frame rates by relying on an absolute timestamp architecture rather than a fixed frame rate counter. Instead of assuming a rigid frame interval, MKV assigns discrete presentation timestamps to individual data blocks using nanosecond-level time scaling. This design ensures that fractional rates like 23.976 fps or arbitrary non-standard frame rates playback precisely without timing drift or audio-video desynchronization.

The Timestamp-Based Model

Unlike legacy containers that rely on fixed frame rates and frame counters, Matroska decouples the frame delivery from a global timing constant. Video frames are stored in dynamic data structures called Clusters, which contain individual SimpleBlocks or BlockGroups.

Every frame is presented based on a calculated timecode relative to the cluster's base time, allowing any frame to occur at any arbitrary point on the timeline.

Timecode Precision and TimestampScale

Matroska achieves precision through the TimestampScale (formerly TimecodeScale) element located in the container's Segment Information header:

  • Default Base Unit: The default TimestampScale is set to 1,000,000, which means timecodes are measured in millisecond increments (\(1,000,000\text{ nanoseconds} = 1\text{ millisecond}\)).
  • Nanosecond Precision: For complex fractional frame rates where rounding to the nearest millisecond might introduce jitter, the TimestampScale can be adjusted down to 1 (pure nanosecond precision) or customized to a common denominator matching the video source.

Storing Fractional Frame Rates

Fractional frame rates—such as 23.976 fps (\(24000/1001\)) or 29.97 fps (\(30000/1001\))—do not divide into whole milliseconds. MKV addresses this through two primary mechanisms:

  1. Individual Block Offsets: Each Block inside a Cluster contains a signed 16-bit integer representing its timestamp relative to the cluster's reference timestamp. The playback engine calculates the exact presentation time for each frame: \[\text{Frame Time} = (\text{Cluster Timestamp} + \text{Block Timestamp}) \times \text{TimestampScale}\]
  2. Dynamic Interval Rounding: When using the standard 1 ms scale, the container alternates frame durations slightly (e.g., alternating between 41 ms and 42 ms for 23.976 fps) so the cumulative timeline matches the real-world fractional rate over time without drift.

The Role of DefaultDuration

Within the Track header, MKV can store an optional element called DefaultDuration.

  • DefaultDuration expresses the expected duration of a single frame in nanoseconds (for example, approximately 41,708,333 ns for 23.976 fps).
  • This field serves as a hint to media splitters and decoders to set up the display refresh rate or buffer allocation.
  • If a file contains non-standard or variable frame rates, the playback engine prioritizes the individual block-level timestamps over the DefaultDuration field.

Native Support for Variable Frame Rates (VFR)

Because every block contains its own timestamp relative to the cluster, non-standard frame rates do not require special flags or container-level modifications. An MKV file can seamlessly switch between arbitrary intervals—such as dropping to 1 fps during static scenes and ramping up to 120 fps during high-motion scenes—simply by writing the exact presentation time to each consecutive block.
